# 持续研究收件箱

## 为什么单独存在

“向猫猫许愿”适合标记某个刚刚发生、值得优先处理的问题，但不能代表日常输入。
持续研究收件箱用于补足这部分证据：一次明确开启后，只要当前用户继续使用猫猫
输入法，普通输入域里的输入法内部事件就按不重叠批次保存在本机。新版批次还带
一条进程内连续链，因此存储批次不再被误当成用户输入的段落边界。许愿目录仍只放
用户主动标记的重点现场，持续批次写入独立的 `research-inbox`，两者不会混在
同一列表里；主动许愿会锚到当时所在的连续链位置。

这不是遥测，也不是全局键盘记录器。当前实现没有网络发送端，不能自动把数据送入
正在进行的 Codex 对话；以后进行训练或评测时，仍需用户明确授权一次本地读取。

## 收集什么

只收集猫猫输入法本身已经知道的结构化语义事件：

- 有效组合码、展示过的候选页、候选来源与是否存在后续页；
- 最终选择或提交的文字、选择方式、页内和绝对名次；
- 原码提交、取消及取消来源；
- 自动换序的触发证据与结果；
- 候选窗首帧和完整显示耗时；
- 仅在整条按键路径达到 16 ms 时记录的无正文阶段耗时：候选数据刷新、候选规划、
  TSF 编辑会话和整键总耗时。正常按键不产生这类诊断事件；
- 候选提交后紧接无修饰 Backspace 时，个人学习已撤回且按键已交给宿主的事实。
  它不等同于已观察到文档删除，回顾会明确保留这个边界。

它不安装系统级键盘钩子，不读取光标周围正文、窗口标题、文件路径、剪贴板、其他
输入法或其他应用的内容。提交后的任意宿主文档编辑也不在当前范围内。

## 永远拒绝的范围

持续研究沿用 TSF 的 fail-closed 输入范围门：

- 密码、数字密码和 PIN；
- `IS_PRIVATE`；
- 键盘被宿主禁用、空 Context；
- URL、邮箱、姓名、地址等受限 InputScope；
- 缺失、读取失败或未来未知的 InputScope。

只有明确分类为普通文本、聊天、搜索、中文文本或 native-script 的范围才会进入
批次。“完全解禁”指普通输入域不再依赖逐次许愿，不会越过以上安全边界。

## 存储和批次

授权标记位于：

```text
.local/tsf-alpha/user-data/research-inbox/continuous-capture.enabled-v1
```

标记只含 schema、开关、范围、加密方式和无网络声明，不含输入文字。持续事件先在
宿主进程中组成有界批次，满足以下任一条件时发布：

- 8 次完成的输入片段；
- 256 条事件；
- 已完成一个输入片段，且本批次跨度达到 60 秒；
- 文本服务停用或对象释放。

绝对单调时钟不会写入文件；批次只保留相对末尾的毫秒数。发布复用
`ziranma-wish-v10` 的有界事件格式，scope 为 `continuous-journal`，整个批次都
属于研究范围。V8 起为每个宿主进程生成不含正文的唯一连续流 ID，并记录批次序号、
首事件序号以及与上一批末事件的间隔；关闭后重新开启、单调时钟倒退或发布失败会新开一条流，
不会把不确定的两段强行接在一起。V7 已记录当前 DLL 的 SHA-256、核心候选数据版本
及可选补充候选数据版本，V8 继续保留这些身份；V9 新增上述慢按键分段计时，V10
新增提交后紧接退格的路由事实。公开补充层在安全组合边界刷新时，
运行时会先封存仍缓冲的旧版本批次，再把后续事件绑定到新版本，避免跨版本误标。
旧 V1–V9 批次继续兼容读取；其中 V1–V7 没有连续链时，不会用文件时间补猜连续链
或运行版本。明文在内存中形成后立即使用 Windows 当前
用户 DPAPI 保护，临时文件和最终 `.ziw` 都只含密文。文件名由密文内容摘要确定，
不覆盖既有包。

如果 InputScope 不合格、授权标记损坏、DPAPI 不可用或本地写入失败，本次路径
fail closed；缓冲会被丢弃或停止，不改变候选、上屏和宿主稳定性。

## 开启、查看和关闭

首次使用先构建包含持续记录链路的 DLL 和控制工具，再按现有安全换代流程安装：

```powershell
cargo build --release --lib --bin tsf-devctl --bin candidatectl --bin researchctl
.\update-ime.cmd
```

根目录脚本把持续授权与本地分析缩成五个动作：

```powershell
.\research-ime.cmd status
.\research-ime.cmd on
.\research-ime.cmd summary
.\research-ime.cmd review
.\research-ime.cmd off
```

不带参数等同于 `status`。`on` 是一次持久授权；正在运行的输入法宿主会在后续输入
中检查标记，通常无需重启应用。检查最多每秒一次，并且每个加密批次发布前还会
再次核验。`off` 立即撤销后续落盘授权，运行中的宿主不会再发布新批次；已有密文
保留，不会被关闭动作顺带删除。

`review` 是显式的本地只读回顾。它逐批使用当前用户 DPAPI 解密，聚合首选率、
非首选/翻页提交、候选加载深度、候选窗耗时、慢按键各阶段分布、自动换序标签、运行身份分组，以及
同一编码和文字是否出现“第一次靠选择、后来升为首选”。它会在当前终端显示真实
编码和提交文字，因此底层命令要求 `--confirm-show-private-text`；结果不写文件、
不写模型、不联网。回顾开头还会把时间上最新的已标识 DLL 单独汇总，避免大量旧批次
掩盖刚换代后的首选、候选中间态和耗时变化；这一节只显示聚合数字，不列输入原文。
同一运行身份下连续的普通候选首页还会重建“奇数键暂态 → 下一键偶数完成帧”，
只报告固定时延分桶、首选变化数和候选保留数。候选文字只在内存中做相等比较，
不会进入这个聚合结果；批次序号或事件序号不连续时不会猜测跨批次配对。
V8 及之后批次会先按连续链接回，再以失焦/宿主结束为硬边界、以本批
间隔分布为自适应软边界形成自然片段；片段仍限制最长十分钟和 128 次完成输入。
主动许愿连接到同一流中最近的前序片段。旧批次会明确显示“尚无连续链”，不会被
文件边界或文件时间伪装成自然片段。非首选、取消和原码上屏只作为待复查线索，
不能自动解释为错误；单次改码也不会形成手癖结论。

`summary` 使用同一套只读解密和聚合逻辑，但只显示运行版本、批次/事件计数、
候选与提交计数、候选窗耗时、慢按键分段耗时和自动换序标签。它不列出原码、
候选、提交文字、取消组合、个人学习身份或许愿场景，适合先判断某次卡顿是否留下
可用样本。底层仍要求显式的 `--confirm-read-private-feedback`，因为即使不回显
文字，计算聚合值也确实在当前进程内解密并读取了私人批次。

底层等价命令为：

```powershell
.\target\release\researchctl.exe enable --confirm-continuous-private-feedback
.\target\release\researchctl.exe status
.\target\release\researchctl.exe summary --confirm-read-private-feedback
.\target\release\researchctl.exe review --confirm-show-private-text
.\target\release\researchctl.exe disable
```

控制工具的状态输出只显示开关和密文批次数，不解密、不显示原文、不联网。

## 更新分层

持续记录不是所有改进都要替换 TSF DLL：

- `researchctl` 的分段、许愿连接和只读分析位于独立短生命周期程序中。运行
  `cargo build --release --bin researchctl` 后，下一次 `research-ime.cmd review` 就会
  使用新版，不需要执行 `update-ime.cmd`，也不需要关闭正在输入的 Codex、Typora
  或其他宿主。因为当前仍是一个 Rust crate，Cargo 可能同时刷新 `target/release`
  里的待安装 DLL 构建产物；只要不运行换代脚本，它就不会替换系统已注册的按内容
  寻址副本，也不会进入现有宿主；
- `wishctl`、`wishpad` 等独立查看与整理程序同样可单独重建并在下次启动时生效；
- 候选数据槽和显式别名继续在新组合开始时原子切换，不替换 DLL；
- 新按键行为、候选窗绘制、TSF 生命周期和新的采集字段仍属于宿主进程内 DLL，
  只能在方便的换代窗口安装。已经加载旧 DLL 的宿主可以自然继续运行，不能被开发
  工具强制热卸载。

因此，V8 起的连续链、V9 慢按键字段和 V10 提交后退格线索都需要相应 DLL 换代才会开始产生；它们开始积累后，许多分段、
统计和线索提取实验都可以只更新独立分析器。若将来连核心候选算法也要求不退出宿主
即可更新，需要另立项目把稳定 TSF 桥与独立引擎进程通过有界 IPC 分开，并先完成
崩溃恢复、超时回退和明文边界审计；当前实现不假装已经具备这类热重载。

## 与个人学习的边界

持续保存不等于把每次提交都当成正确答案。首次选择、退格纠正、候选删除和上下文
都只是待分析事件；当前实现不实时训练、不写私人模型，也不直接改变候选排序。
后续本地研究应把较旧批次用于学习、较新批次用于评测，并保留因果顺序、撤销和
对照，避免把换代后的反馈反过来冒充独立证据。
