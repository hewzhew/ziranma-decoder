# 持续研究收件箱

## 为什么单独存在

“向猫猫许愿”适合标记某个刚刚发生、值得优先处理的问题，但不能代表日常输入。
持续研究收件箱用于补足这部分证据：一次明确开启后，只要当前用户继续使用猫猫
输入法，普通输入域里的输入法内部事件就按不重叠批次保存在本机。新版批次还带
一条进程内连续链，因此存储批次不再被误当成用户输入的段落边界。许愿目录仍只放
用户主动标记的重点现场，持续批次写入独立的 `research-inbox`，两者不会混在
同一列表里；主动许愿会锚到当时所在的连续链位置。

这不是遥测，也不是全局键盘记录器。当前实现没有网络发送端，不能自动把数据送入
正在进行的 Codex 对话；以后进行训练或评测时，仍需用户明确授权一次本地读取。

## 收集什么

只收集猫猫输入法本身已经知道的结构化语义事件：

- 有效组合码、展示过的候选页、候选来源与是否存在后续页；
- 最终选择或提交的文字、选择方式、页内和绝对名次；
- 原码提交、取消及取消来源；
- 自动换序的触发证据与结果；
- 候选窗首帧和完整显示耗时；
- 仅在整条按键路径达到 16 ms 时记录的无正文阶段耗时：候选数据刷新、候选规划、
  TSF 编辑会话和整键总耗时。正常按键不产生这类诊断事件；
- 候选提交后紧接无修饰 Backspace 时，个人学习已撤回且按键已交给宿主的事实。
  它不等同于已观察到文档删除，回顾会明确保留这个边界。

它不安装系统级键盘钩子，不读取光标周围正文、窗口标题、文件路径、剪贴板、其他
输入法或其他应用的内容。提交后的任意宿主文档编辑也不在当前范围内。

## 永远拒绝的范围

持续研究沿用 TSF 的 fail-closed 输入范围门：

- 密码、数字密码和 PIN；
- `IS_PRIVATE`；
- 键盘被宿主禁用、空 Context；
- URL、邮箱、姓名、地址等受限 InputScope；
- 缺失、读取失败或未来未知的 InputScope。

只有明确分类为普通文本、聊天、搜索、中文文本或 native-script 的范围才会进入
批次。“完全解禁”指普通输入域不再依赖逐次许愿，不会越过以上安全边界。

## 存储和批次

授权标记位于：

```text
.local/tsf-alpha/user-data/research-inbox/continuous-capture.enabled-v1
```

标记只含 schema、开关、范围、加密方式和无网络声明，不含输入文字。持续事件先在
宿主进程中组成有界批次，满足以下任一条件时发布：

- 8 次完成的输入片段；
- 256 条事件；
- 已完成一个输入片段，且本批次跨度达到 60 秒；
- 文本服务停用或对象释放。

绝对单调时钟不会写入文件；批次只保留相对末尾的毫秒数。发布复用
`ziranma-wish-v17` 的有界事件格式，scope 为 `continuous-journal`，整个批次都
属于研究范围。V8 起为每个宿主进程生成不含正文的唯一连续流 ID，并记录批次序号、
首事件序号以及与上一批末事件的间隔；关闭后重新开启、单调时钟倒退或发布失败会新开一条流，
不会把不确定的两段强行接在一起。V7 已记录当前 DLL 的 SHA-256、核心候选数据版本
及可选补充候选数据版本，V8 继续保留这些身份；V17 再增加三态的精确短词目录版本
（旧格式未记录 / 已记录但关闭 / 已记录具体 revision），V1–V16 历史批次不会补猜
该项。V9 新增上述慢按键分段计时，分别
记录候选数据刷新、按键与候选规划、同步编辑会话和整条已处理按键路径。分析器会用
总耗时减去三个显式阶段，得到候选 UI 更新、进程内状态、反馈工作和整数毫秒取整共同
构成的“其余阶段”；它还按每次事件的唯一最大阶段汇总主耗时，并把整数毫秒并列
单列，避免把未插桩时间误归给某一阶段。V10
新增提交后紧接退格的路由事实，V11 把笼统会话标记扩为可叠加的持久精确、持久尾简、
持久发现、会话精确、会话尾简和左侧上下文证据；V12 把真正由核心/补充词典共识
改变顺序的整词单列为“公开共识整词”；V13 另外直接记录宿主实际使用的公开候选
冷排序策略；V14 再把个人证据与真正执行的个人重排原因分开；V15 只在精确
suppression 遗忘或恢复动作成功落盘后记录对应事实，保存失败不冒充成功；V16 在
合格单字个人短语提交后增加不含文字、位置或 Context 身份的文档邻接类别及 0–4
组件数。当前 TSF 写入
“保守核心优先”，而不是用零次共识来源反推规则关闭。
公开补充层在安全组合边界刷新时，
运行时会先封存仍缓冲的旧版本批次，再把后续事件绑定到新版本，避免跨版本误标。
旧 V1–V15 批次继续兼容读取；其中 V1–V7 没有连续链时，不会用文件时间补猜连续链
或运行版本。解析器会在内存对象中保留包的来源 schema 版本；重新编码仍只写当前
格式，因此该字段用于解释历史能力覆盖，不会降级新包。明文在内存中形成后立即使用 Windows 当前
用户 DPAPI 保护，临时文件和最终 `.ziw` 都只含密文。文件名由密文内容摘要确定，
不覆盖既有包。

如果 InputScope 不合格、授权标记损坏、DPAPI 不可用或本地写入失败，本次路径
fail closed；缓冲会被丢弃或停止，不改变候选、上屏和宿主稳定性。

## 开启、查看和关闭

首次使用先构建包含持续记录链路的 DLL 和控制工具，再按现有安全换代流程安装：

```powershell
cargo build --release --lib --bin tsf-devctl --bin candidatectl --bin researchctl
.\update-ime.cmd update
```

根目录脚本把持续授权与本地分析缩成五个动作：

```powershell
.\research-ime.cmd status
.\research-ime.cmd on
.\research-ime.cmd summary
.\research-ime.cmd review
.\research-ime.cmd off
```

不带参数等同于 `status`。`on` 是一次持久授权；正在运行的输入法宿主会在后续输入
中检查标记，通常无需重启应用。检查最多每秒一次，并且每个加密批次发布前还会
再次核验。`off` 立即撤销后续落盘授权，运行中的宿主不会再发布新批次；已有密文
保留，不会被关闭动作顺带删除。

`review` 是显式的本地只读回顾。它逐批使用当前用户 DPAPI 解密，聚合首选率、
非首选/翻页提交、候选加载深度、候选窗耗时、慢按键各阶段分布、自动换序标签、运行身份分组，以及
同一编码和文字是否出现“第一次靠选择、后来升为首选”。它会在当前终端显示真实
编码和提交文字，因此底层命令要求 `--confirm-show-private-text`；结果不写文件、
不写模型、不联网。这里把两条边界明确分开：猫猫可以在宝宝的本机进程里理解真实
输入内容；私人内容仍不会因此被导出、联网或提交 Git。回顾不会再为了“脱敏”而主动
丢掉诊断语义：非首选问题卡片会显示目标、经文字一致性核对的当时首选、两者名次和
来源，以及后续是否到过首选；只显示直接相关的短片段，不倾倒无关候选或整段会话。
若提交文字与记录位置不一致，或分页现场缺少首页，报告明确标为证据不完整，不反推、
不猜测阻挡项。回顾开头还会把时间上最新的已标识 DLL 单独汇总，避免大量旧批次
掩盖刚换代后的首选、候选中间态和耗时变化；这一节只显示聚合数字，不列输入原文。
同一运行身份下连续的普通候选首页还会重建“奇数键暂态 → 下一键偶数完成帧”，
只报告固定时延分桶、首选变化数和候选保留数。候选文字只在内存中做相等比较，
不会进入这个聚合结果；批次序号或事件序号不连续时不会猜测跨批次配对。
V8 及之后批次会先按连续链接回，再以失焦/宿主结束为硬边界、以本批
间隔分布为自适应软边界形成自然片段；片段仍限制最长十分钟和 128 次完成输入。
主动许愿连接到同一流中最近的前序片段。旧批次会明确显示“尚无连续链”，不会被
文件边界或文件时间伪装成自然片段。非首选、取消和原码上屏只作为待复查线索，
不能自动解释为错误；单次改码也不会形成手癖结论。

`summary` 使用同一套只读解密和聚合逻辑，但只显示运行版本、批次/事件计数、
候选与提交计数、候选窗耗时、慢按键分段耗时、其余阶段及主耗时阶段和自动换序标签。
摘要开头另有一份可移植的“结构化问题线索”矩阵，把同一批事件按候选可达性、
排序与记忆、找字与纠错、性能和证据完整度并列计数。同一现场可以落入多类：例如
一次翻页提交既是候选可达性压力，也可能带有个人排序证据；分类器不会强迫它只属于
一个根因。只有 V11/V14 明确记录了候选个性化证据或实际重排原因时，矩阵才分别说
“已有个人证据仍非首选”或“个人重排首选被绕过”；旧格式和来源缺失继续单列。
矩阵不会再只列裸计数：非首选提交以全部候选提交为分母，原码上屏和取消分别显示
总数、可与候选帧配对数及无法配对数；V11 目标候选再互斥分成“已有个人证据”、
“无个人证据”和“目标来源缺失”，三项合计回到可核对分母。逐字 Tab 辅助以全部
形码提交为分母，自动换序选择以所有已观察到的恢复终局为分母；候选窗首次出现和
候选更新的慢样本也各自带计时样本总数。V9 慢按键、V11 精确个人证据和 V14 实际
个人重排另按批次报告字段覆盖。V10 提交后退格路由、V15 显式遗忘/恢复和 V16
个人短语文档邻接也使用相同口径；邻接事件互斥分为首锚点、已验证相邻、三种明确
断链、范围不可用和键盘连续回退，分区合计回到事件总数。因此“暂无批次”“旧格式
字段不可用”“字段支持但零事件”“已有有效观测”不会再被压成同一个 0。提交后
退格仍只证明学习已撤回且按键已交回宿主，不补猜文档是否完成删除；遗忘/恢复仍只
统计成功落盘的动作。
有运行身份时，矩阵先只汇总时间上最新的精确 DLL 与候选数据身份；若读取范围还
包含旧身份或无版本批次，再单列全部历史。两组各自显示批次、事件及配对分母，且
明确禁止用样本量不同的绝对计数直接宣称改善或退化。若全部已读取批次本来就属于
最新身份，则只显示一次，不制造一份看似独立、实则完全重复的“对照”。
候选已到底后的原码上屏或取消只称为复查线索，不会自动宣布缺词；仍可加载时放弃
也单独计数，不与真正穷尽候选混合。这个矩阵不保留原码、候选或提交文字，既供
`summary` 的脱敏聚合使用，也由公开合成测试锁定证据边界。
候选窗耗时分别显示首帧与完全显示；完全显示再把首次出现和后续更新分开。每组都报告
P50/P95/最大值和 `≥16/32/64/128 ms` 的固定阈值长尾次数与比例；这些阈值只描述
分布，不把一次长尾自动归因于候选规划、绘制或宿主调度。首次从非首选提交的身份
另按 `1–2 / 3–4 / 5–6 / 7–8 / ≥9` 个双拼键分桶，只报告桶计数，不输出原码，
并在每个桶内汇总“目标候选来源 → 当时首选来源”，用于区分短输入内部排序、
补充词覆盖与长组合拥挤。它还用纯计数区分
“同一码出现多种已提交文字”“至少两种文字都曾从非首选提交”“单一已见文字曾从
非首选提交”。首次非首选身份会进一步分成“只提交过一次”和“存在后续提交”；
只有后者才比较后来是否到过首选，避免把没有复测机会的一次性身份误报成学习失败。
第一次非首选提交还会按第 2 名、第 3–6 名和第 7 名以后分桶，并分别汇总目标候选
来源、当时全局首选来源以及二者的来源配对。分页后的配对只在同一码、同一候选视图
且第一页来源确实随页携带时成立；换码、切栏或缺少首页证据时单列为来源缺失。
总配对只展示计数最高的六类，并明确给出其余身份数；同时按三个首次名次桶分别显示
来源完整数和前三类目标→首选配对，缺失来源仍保留在各桶分母中。这样 V12 上线后能
区分公开共识首选主要挡住第 2 名还是更深候选，却不会用位置反推缺失的来源，也不让
截断后的可见数字冒充完整分布。
若该首次帧为 V11 或之后格式，目标与首选的六类精确个性化原因分别聚合；V3–V10 只报告原有
兼容标记，V1–V2 没有来源字段。这样可以区分同层词序、组合候选被整词压住和显式
别名保护等结构，而不会借候选文字或旧格式猜具体个性化路径。
摘要还逐次审计 V14+ 的非首选提交：只有当同一码、同一候选视图的全局首选来源
确实可配对时，才区分“首选确由个人路径重排”与“首选未发生个人重排”；分页沿用
第一页来源，缺页或切栏不补猜。实际重排的首选被明确绕过时，六类原因按可叠加
计数，另列多原因叠加次数，并区分替代候选自身是否也经个人重排。这个信号用于发现
值得核对的个人提升，不把一次绕过自动判成错误，也不从 V11–V13 的证据位补猜
因果动作。
报告还单列首次首选后又出现非首选的身份；这些都只是选择压力，不把多义码自动判成
排序错误。它不列出原码、候选、提交文字、取消组合、
个人学习身份或许愿场景，适合先判断某次卡顿或排序压力是否留下可用样本。底层仍要求显式的 `--confirm-read-private-feedback`，因为即使不回显
文字，计算聚合值也确实在当前进程内解密并读取了私人批次。若慢按键记录为零，
摘要先列出来源 schema 分布，再分别计算 V9 慢按键分段、V10 提交后退格、V11 精确
个性化证据、V12 公开共识来源字段、V13 公开候选冷排序策略、V14 实际个人重排
原因、V15 显式遗忘/恢复动作和 V16 个人短语文档邻接的批次覆盖。V15 摘要只计数
成功落盘的动作，不输出码或文字；V16 摘要分别计数首锚点、已验证相邻、光标/锚点/
Context 明确断链、范围不可用及键盘回退，不输出文字或位置。旧格式保持“未记录”，
不从名次变化补猜。策略汇总
分别列出“保守核心优先”“实验跨词典共识”和“旧格式或未记录”，不会把格式支持、
规则启用与零次触发混成一件事。只有全部被汇总批次都支持 V9 且仍没有慢按键事件时，才可把
零条解释为“未观察到 ≥16 ms 按键”；零覆盖保持“未确认”，新旧混合则明确写“部分
确认”，不再把字段缺失和事件为零混成同一种状态。摘要还会单列当前 V17 格式是否
已在记录中出现；没有 V17 时只说明“尚未观察到”，不会据此猜测当前安装状态。旧批次
不会补写新字段，只有之后实际生成的新格式批次才能证明相应采集能力已经上线。

确有后续提交却始终未到首选的身份另有一组脱敏归因：最好名次分桶、是否曾改善、
同码是否另有已提交文字、候选来源证据完整度、主要来源，以及是否分别观察到六种
个性化机制。V11 及之后格式可以保留同一候选叠加的多个原因；旧 V3–V10 的原有布尔值兼容映射到
“会话精确”位，但不能证明当时具体路径，而 V1–V2 没有来源字段。摘要按真实字段聚合，不用缺失或旧版字段反推
持久学习、上下文或尾简机制是否生效。对于首次从非首选提交、后来到过首选的身份，
摘要还按首次到达首选发生在第 2 次、第 3–4 次或第 5 次以后分桶，并统计到达后是否
再次出现非首选；首次回落再按同一连续流、同一运行身份的新连续流、不同运行身份和
边界未知互斥分桶。只有成为首选与后来回落的两端都来自 V11 或之后格式时，回落前后的六类
个性化原因才会分别按保留、消失和新出现汇总；精确格式但缺少任一端候选来源时会
单列为证据缺失。V3–V10 或新旧混合的两端只把原有布尔值按兼容标记汇总，V1–V2
没有来源字段；二者都不会伪装成 V11 的具体原因。挡在前面的全局首选另按来源聚合。TSF 合成测试锁定了左侧上下文
真实改变候选顺序后，`LEFT_CONTEXT` 原因能穿过候选展示反馈边界；Wish V11 另有
个性化序列化往返测试，V12 则锁定公开共识来源只在它实际移动候选时出现，且旧格式
拒绝该新标签。这些都只描述时间顺序和可验证字段，不自动解释成因果效果。

同一队列还会追踪挡在目标前面的全局首选来源。第一页取得的来源只在码串和候选视图
都相同的连续分页中向后携带；换码、切换普通/Tab/纠序视图或缺少第一页证据时不会
猜测。报告把当前实现中真正占据不可跨越前缀的 `ExplicitAlias` 明确称为“显式别名”，
项目词、核心整词和普通组合仍按各自来源列出，不用文档中的泛称替代运行时代码事实。

底层等价命令为：

```powershell
.\target\release\researchctl.exe enable --confirm-continuous-private-feedback
.\target\release\researchctl.exe status
.\target\release\researchctl.exe summary --confirm-read-private-feedback
.\target\release\researchctl.exe review --confirm-show-private-text
.\target\release\researchctl.exe disable
```

控制工具的状态输出只显示开关和密文批次数，不解密、不显示原文、不联网。

## 更新分层

持续记录不是所有改进都要替换 TSF DLL：

- `researchctl` 的分段、许愿连接和只读分析位于独立短生命周期程序中。运行
  `cargo build --release --bin researchctl` 后，下一次 `research-ime.cmd review` 就会
  使用新版，不需要执行 `update-ime.cmd`，也不需要关闭正在输入的 Codex、Typora
  或其他宿主。因为当前仍是一个 Rust crate，Cargo 可能同时刷新 `target/release`
  里的待安装 DLL 构建产物；只要不运行换代脚本，它就不会替换系统已注册的按内容
  寻址副本，也不会进入现有宿主；
- `wishctl`、`wishpad` 等独立查看与整理程序同样可单独重建并在下次启动时生效；
- 候选数据槽和显式别名继续在新组合开始时原子切换，不替换 DLL；
- 新按键行为、候选窗绘制、TSF 生命周期和新的采集字段仍属于宿主进程内 DLL，
  只能在方便的换代窗口安装。已经加载旧 DLL 的宿主可以自然继续运行，不能被开发
  工具强制热卸载。

因此，V8 起的连续链、V9 慢按键字段、V10 提交后退格线索、V11 精确个性化证据、V12 公开共识来源、V13 运行时冷排序策略、V14 实际个人重排原因、V15 显式遗忘/恢复动作和 V16 个人短语文档邻接都需要相应 DLL 换代才会开始产生；它们开始积累后，许多分段、
统计和线索提取实验都可以只更新独立分析器。若将来连核心候选算法也要求不退出宿主
即可更新，需要另立项目把稳定 TSF 桥与独立引擎进程通过有界 IPC 分开，并先完成
崩溃恢复、超时回退和明文边界审计；当前实现不假装已经具备这类热重载。

## 与个人学习的边界

持续保存不等于把每次提交都当成正确答案。首次选择、退格纠正、候选删除和上下文
都只是待分析事件；当前实现不实时训练、不写私人模型，也不直接改变候选排序。
后续本地研究应把较旧批次用于学习、较新批次用于评测，并保留因果顺序、撤销和
对照，避免把换代后的反馈反过来冒充独立证据。
