# Windows TSF Alpha：自有输入法壳

## 状态

这是用户明确批准的新里程碑。当前已完成与宿主无关的 `CompositionSession`
抽取、TSF COM 生命周期探针，以及只在测试进程中工作的按键、真实组合范围、
焦点清理和公开候选上屏闭环。仓库也提供本机范围、64 位、默认关闭的显式
开发注册和反向注销事务；它不会启用、激活或设为默认输入法。真实宿主输入
已开始验证：固定公开用例在 Windows 记事本完成 `nihk` →“你好”、切回微软
拼音和禁用闭环。另有显式的当前用户启用和禁用命令；启用不设为默认，也不
请求进程或桌面范围激活。Windows 可能只在执行命令的辅助线程内短暂激活配置，
因此换代脚本会在辅助进程退出后另起进程确认它已经持久启用；若换代前没有活动
宿主，还会继续要求它保持未活动。上一
构建已在记事本中显示系统静态控件原型；下一构建改为不抢焦点的自绘 Alpha
面板并绑定完整公开候选包，仍需真实宿主复核外观、翻页和上屏。

## 目标

第一版 Alpha 只回答一个问题：现有解码器能否在真实 Windows 编辑框中完成
一轮稳定、可回退的日常输入，并让后续功能直接依据自有输入法事件评测。

首批宿主限定为：

- Windows 记事本，用于验证标准 TSF 编辑生命周期；
- Codex 输入框，用于验证主要日常场景；
- 一个仓库内的合成宿主测试，用于覆盖异常激活、焦点切换和组合取消。

Alpha 不取代微软拼音，不设置默认输入法。安装后只能由用户通过 Windows
输入法切换器主动选择；任何时候都必须能切回微软拼音。

## 分层

```text
宿主编辑框
  ↕ Windows TSF 编辑会话
极薄 TSF 适配层
  ↕ CompositionInput / CompositionEffect
CompositionSession
  ↕ 候选请求与选择
现有 Decoder / ShapeLab / 本轮选择记忆
```

`CompositionSession` 只拥有当前组合串、换序/Tab 模式和候选页位置。已提交
文字属于宿主文档；TSF 适配层提交成功后调用 `finish_commit`。候选解码、
候选窗口、Windows 注册、私人学习和磁盘存储都不进入该状态机。

没有活跃组合时，Space、Backspace、Tab、翻页键和 Esc 返回 `PassThrough`，
由 TSF 交还宿主；终端适配器只把空输入下的 Esc 解释为退出实验台。

这条边界让终端实验台和 TSF 共用同一组按键语义，又避免把终端的退出行为、
滚动输出或累计文字上限带进真实输入框。

## 实施顺序

### 0. 可复用组合核心

- 从 `typing-lab` 抽出宿主无关状态；
- 终端继续作为回归宿主；
- 所有既有逐键场景保持通过；
- 不执行任何系统注册。

### 1. TSF 生命周期探针

- 创建最小 Windows `cdylib` 边界；
- 实现 COM 类工厂、激活、停用、服务器锁和安全卸载边界；
- 用真实的系统 `ITfThreadMgr` 在测试进程内验证生命周期与失败清理；
- 当前 DLL 只导出 `DllGetClassObject` 和 `DllCanUnloadNow`；刻意不提供
  `DllRegisterServer` / `DllUnregisterServer`，因此不能被 `regsvr32` 注册；
- 文本服务已实现 `ITfKeyEventSink`，正式激活路径会申请前台按键接收，并在
  停用时成对释放；
- 文本服务也会通过 `ITfSource` 成对订阅和释放 `ITfThreadMgrEventSink`，用来
  识别文档焦点离开当前组合所在 Context；
- 未注册测试进程拿到的是应用 client id，Windows 会拒绝用它冒充前台文本
  服务。测试因此只绕过“前台订阅”这一项，直接调用同一个按键接收器；
- 测试按键仍经过真实的 Thread Manager、Document Manager、Context 与同步
  `RequestEditSession`。事务用 `ITfRange` 修改合成文档，同时只保留有界的
  “更新/取消/提交”结构遥测，不保存原文；
- DLL 同目录没有 `candidate-data` 时，默认类工厂使用进程内只初始化一次的
  开发候选源。它复用 50 词公开演示词典，先解析严格的候选包清单，再通过
  [只读候选快照](candidate-snapshots.md)校验 schema、版本、字节数、指纹和
  词条数后建立现有 `Decoder`；`candidate-data` 存在时，新类工厂只读其中
  经过预检的公开 current。两条路径都不学习、不联网；
- 可选公开补充词层来自跨 DLL 版本共享的
  `.local/tsf-alpha/user-data/public-supplement`，默认关闭。它使用独立公开
  候选三槽和严格 `supplemental.zcl`，只给核心缺少的完整整词至多一个前排
  位置；不消费补充词典的自由简拼、纠错或句子路径，也不比较跨来源权重。
  若补充层 Top-1 同时也是核心层确认的同码完整词，TSF 冷启动可在已加载前沿
  内按补充层相对顺序校准这个共有候选；补充层独有词仍不能越过核心首选。
  首次载入时状态损坏、包与 current 不一致或预检失效会只使用核心快照。此后
  每个文本服务只在空组合的下一次字母首键前检查小型补充状态和槽指针；状态未变
  不重读大词典，新包完整验证成功后才替换自己的补充快照，损坏更新保留最后有效
  版本，关闭则从新组合切回核心。活动组合不热换；
- 核心公开快照仍随类工厂固定；显式私人别名则来自所有不可变 DLL 构建共享的
  `.local/tsf-alpha/user-data/aliases`。每个文本服务只在新组合首键前检查一次
  小型槽指针，完整 DPAPI 解密和校验成功后才替换自己的内存快照；损坏更新保留
  最后已知可用版本，活动组合不热换。`aliaspad` 只让用户主动固定或移除一个
  精确 `code → text`，通过私密标准输入调用独立 `aliasctl`，一次发布时原 current
  自动进入 previous；它不从候选选择或真实输入中自动学习；
- 在线个人排序来自共享的
  `.local/tsf-alpha/user-data/personal-ranking`。数字选择或翻页后确认这类
  明确非首选会成为 `code + text` 证据；已经由个人记忆召回、且能逐字验证的
  二至四字完整词再次空格确认时，也会增加同一完整码支持。当前宿主立即使用，普通文本等允许范围
  先建立一条待确认事务。数字选择或翻页后空格确认若紧接空组合 Backspace，会
  撤回事务并恢复此前的会话偏好；下一个按键、焦点离开或停用才确认。标点确认的
  第一次 Backspace 只可能删除候选后的标点，因而不触发候选撤回。确认结果再分批
  通过 Windows 当前用户 DPAPI 写入不可变包。新宿主加载后按时间与
  进程序列合并；同码候选先比较最多四次的确认支持，支持相同才比较最近确认。
  因而第一次个人选择仍可建立偏好，已有重复支持不会被一次偶然选择推翻，新偏好
  重复达到同等支持后仍可切换。独立的 `personal-suppression` 当前用户加密动作
  日志可精确忘记或恢复一个 `code + text`；忘记同时约束长期证据与会话置顶，
  不删除正向证据也不改变公共候选顺序。显式别名和项目保护前缀始终在它之前。
  候选确由当前宿主记忆、持久个人排序、规范尾简继承或左侧上下文重排时，序号栏
  内显示一颗不占额外宽度的柔和蓝点；普通公共候选不显示。忘记后标记与重排同时
  消失，同一组合内 Backspace 恢复后同时回来。反馈 V11 在不改变这颗蓝点的前提下，
  分别记录持久精确、持久尾简、持久发现、会话精确、会话尾简和左侧上下文；同一
  候选受多条路径影响时保留全部原因；
  反馈 V12 能表示核心/补充词典共识真正改变顺序时的“公开共识整词”来源；但该
  重排在独立 UD test 上未过零损失门，当前宿主继续使用保守分层而不会产生这种
  来源。反馈 V13 另外把宿主实际采用的公开候选冷排序策略记为独立字段；当前宿主
  明确写入“保守核心优先”，格式能力、启用状态和实际触发次数不会再互相冒充，
  V1–V12 旧批次仍保持“未记录”而不补猜。反馈 V14 再为每个候选单列真正执行过
  的个人重排原因；V11 的个人证据位继续服务蓝点与多路径支持，不能冒充因果动作，
  V1–V13 的实际重排原因保持“未记录”。反馈 V15 另记成功落盘的精确 suppression
  遗忘与恢复动作，保存失败、密码框与未知输入范围均不产生成功事件；
  已验证的公开完整整词证据可继承到同词的规范尾简：至少保留首个完整音节，
  只缩短一个非空尾部，而且目标文字必须已在普通短码候选池中。短码精确证据
  优先，别名、自由分句、任意前缀和池外文字不参与；短码抑制只关闭该视图的继承。
  逐字 Tab 组成的二至四字个人词采用更慢的发现门：完整码至少确认两次、每个
  `两键码 → 单字` 均可由公开精确候选独立验证后，才允许把池外整词放到规范尾简
  的发现位。固定前缀和原普通首选保持不动，发现项只占其后一位并带个人蓝点；
  单次组词、任意前缀、自动换序请求和无法逐字验证的文字不触发。用户再明确选择
  发现项后，才建立普通的短码精确证据；短码忘记只屏蔽该视图，不伤完整码证据。
  密码、PIN、私人、受限和未知范围不落盘，损坏或超限时关闭该宿主的持久层而
  不阻断普通输入。宿主再次激活时复用已经验证的包，只解密严格新增的批次；
  删除或倒序补入时完整重建，新增异常时保留最后已知可用快照。达到 64 批后
  新宿主可自动写入覆盖集合明确的不可变 DPAPI 检查点，之后按覆盖批次数翻倍
  更新；冷启动只解密检查点和尾部批次。检查点不删除旧日志，不要求常驻线程；
- 注册前仍可只构建和检查；获得用户明确确认后，`tsf-devctl` 可以把经过检查
  的 DLL 复制到按 SHA-256 寻址的本地不可变目录，并完成本机开发注册。

当前构建命令为 `cargo build --release --lib`，产物是
`target/release/ziranma_core.dll`。它只生成未注册的 DLL；单元测试会在测试线程
中创建并释放系统 TSF Thread Manager，不写注册表、不创建输入配置文件，也不
改变 Windows 输入法列表。

注册前可运行[TSF 开发检查](tsf-dev-inspection.md)，只读核对 DLL 的 PE 架构、
COM/注册入口、证书目录、固定 CLSID 的标准 COM 注册位置、固定 zh-CN
语言配置和键盘类别。显式注册与注销命令都要求
`--confirm-machine-wide-development-alpha`；注册固定为本机 64 位且默认关闭，
需要管理员权限，不包含启用或激活。“证书目录存在”也不冒充签名验证。
候选包的 Ed25519 脱离验签是另一条数据发布边界，不验证 DLL / EXE 的
PE/Authenticode 签名。

### 2. 最小可输入闭环

- `a`～`z`、Backspace、Esc、Space、Enter、常用中文标点与数字键的路由和
  事务计划已有进程内覆盖。Space 确认首选，活跃组合上的 Enter 原样提交当前
  字母码；没有组合时 Enter 交还宿主。中文模式下 `,` / `.` / `;`、`Shift+;`、
  `Shift+1`、`Shift+6`、`Shift+9/0` 与 `Shift+/` 分别上屏 `，` / `。` / `；` /
  `：` / `！` / `……` / `（）` / `？`，活跃组合会先确认首选再追加标点。其他可打印键会先结束当前
  预编辑再交还宿主，避免半角文字进入未完成的组合；带 Shift 的数字不会误选候选；
- 已用 `ITfInsertAtSelection`、`ITfContextComposition` 和 `ITfRange` 在合成
  Context 中创建、更新、取消与提交组合；
- 测试会逐步读回合成正文，验证同一范围更新、候选替换、取消删除以及提交后
  光标落在文字末尾；
- 另一个测试从 `IClassFactory::CreateInstance` 开始，在合成 Context 中输入
  `nihk`，确认预编辑为 `nihk`、首选提交为“你好”。它覆盖正式对象创建路径，
  不使用系统注册；
- 词典不能完整解释的首选会原样提交按键串，不插入研究解码器用于报告的
  未解析标记，也不吞掉已有预编辑；
- 开发快照若校验失败，正式类工厂会拒绝创建文本服务；文本服务内部若没有
  候选源也不接管按键。合成测试分别覆盖这两道失败边界；
- `ITfCompositionSink` 已处理宿主主动终止：使用回调给出的写入权限删除未提交
  的预编辑文字、归位光标并清理内部状态；
- 文档焦点离开、前台输入法切换和文本服务停用都会为旧 Context 排入异步取消。
  取消任务绑定到发起时的确切组合对象；如果宿主先终止旧组合、用户随后开始
  新组合，迟到的旧任务不会删除新输入；
- 合成测试会直接触发同一焦点接收器并覆盖上述竞态。注册后的真实宿主是否按
  预期时序投递焦点事件和异步编辑会话，仍需继续扩大测试；
- 未激活或没有组合时，普通按键交还宿主。
- 默认进入中文模式。没有按其他键的单独一次 `Shift` 在中文与英文模式之间
  切换；若仍有预编辑，先提交当前首选，再完成切换。`Shift` 参与组合键时不
  切换模式；
- 英文模式不接管普通按键或宿主快捷键。中文模式下的 `Shift + 字母` 与
  Caps Lock 字母也交还宿主；若切换发生在预编辑中，先结束当前首选，避免
  英文字母落入未完成的拼音组合；
- 模式目前属于每个宿主中的文本服务实例，不修改 Windows 默认输入法，也
  尚未接入系统输入模式指示器。
- 注册后的 Windows 记事本已完成一次固定公开 `nihk` →“你好”首选提交；
  随后切回微软拼音并通过显式命令禁用，未修改默认输入法。

### 3. 候选窗口与现有功能

- 普通逐键更新只解码当前可见的 Top-6；请求下一页时才补到 Top-12，此后按
  六项一页逐步扩展，最多 Top-50。同一组合缓存当前最深的确定性前缀，返回
  前页和确认候选不会重复缩小或重新解码；日常首屏不承担下一页候选的固定
  延迟。快照对任意长度先合并完整、零纠错、
  不简写的词典项，再补连续句子候选并按文字去重，避免准确完整码被大量自由
  简写路径挤出 Top-50。`ju` / `qu` / `xu` / `yu` 中无歧义的 `u` 写法也可
  沿用自然码规范 `v` 词条，因此 `ju` 能显示“句”，`uuyu` 能优先显示“属于”；
- 实现标准 `ITfCandidateListUIElement`，普通宿主与 UIless TSF 宿主读取同一
  候选、页位置和当前选择；
- 普通宿主使用最多六项的不抢焦点弹窗，通过 `ITfContextView::GetTextExt`
  跟随真实组合范围，而不是读取屏幕或猜光标；
- `GetTextExt` 的 clipped 标志只作为宿主布局提示，不再直接隐藏弹窗；部分宿主
  会在刚更新组合时暂时报告 clipped，但仍返回可用的定位矩形；
- `-` / `+` 与 PageUp / PageDown 逐页切换，最多按需展开至十页；数字键按
  当前页选择；
- 普通候选组合中，`Ctrl+Delete` 进入短暂的“忘记 · 数字选择”模式，而不是
  猜测当前高亮项。数字键精确选择当前页候选，翻页仍可用，Esc 或 Backspace
  取消；其余普通输入在该模式中被拦住，不会上屏。固定词与没有个人证据的公共
  候选只显示状态，不写忘记动作。成功后长期排序和本轮置顶立即重新计算，并在
  同一组合内提供一次 Backspace 恢复；焦点离开、停用或继续输入会结束撤销窗口。
  Tab 找字、换序、许愿、英文模式和宿主修饰键组合不会被这条快捷键误接管；
- 数字键明确选择的普通候选会进入当前文本服务实例的有界内存记忆；再次输入
  完全相同的码串时，该候选稳定移到首位。公开完整整词还可按上一节的相同约束
  影响规范尾简，但不向任意前缀传播，也不补入池外候选。空格确认首项、Enter 原码提交、换序
  候选和 Tab 找字都不产生记忆。最多保留 128 组，文本服务停用即清空，不序列化、
  不写文件，也不改变公开候选包；
- 相邻两个由公开候选源验证的“两键完整码 + 单字”明确选择会组成一个精确个人
  短语。它在第二个字提交后立即进入当前宿主候选；紧接空组合 Backspace 会撤销，
  否则跨过下一按键、焦点离开或停用边界后，一次就进入现有当前用户 DPAPI 个人
  排序。第一页空格首选、标点、简拼、纠错、Tab、换序、原码和宿主快捷键会拒绝
  或断开组合。首版尚未用文档范围锚点识别同一 Context 内的鼠标光标移动；
- 已确认的明确选择还进入一个进程内短左侧上下文表，键为“上一段已提交候选文字、

- 提交、取消、宿主终止组合、焦点离开和文本服务停用都会结束 UI 元素并隐藏
  弹窗；
- 自绘 Alpha 面板每页最多显示 6 个候选。首项使用轻微提亮、上下留白的圆角底
  和左侧柔和天蓝色短条标记，避免选中态变成一块沉重按钮；首选汉字采用近白
  半粗体，普通汉字降为柔和浅灰。序号使用更小的中灰元数据字体，并通过固定
  基线补偿与候选文字对齐，只有首选序号沿用天蓝。分页再退一级，并以低对比
  分隔线进入固定尾部区域。这个“候选文字优先、选择状态其次、操作元数据最后”
  的层级避免六个等亮标签同时争抢注意力；普通文字与背景至少保持 4.5:1 对比度。
  短候选在可用空间内按自然宽度横排；长候选共享一个最多 640 逻辑像素、且不超过
  工作区宽度 80% 的预算，首选保留完整自然宽度，普通项才压缩并使用单个 Unicode
  省略号。只有屏幕窄到
  无法容纳各项最小宽度时才确定性回落为竖排。外框内边距由 8 收紧为 5 逻辑像素，
  弹窗按宿主 DPI 缩放并限制在当前显示器工作区。“换序”模式标记使用独立强调色，
  与右侧页码分开显示。首次显示即清晰可读，逐键更新不做透明度动画，最终隐藏也
  立即完成；显式开启反馈时，每次完成绘制会记录首个完整帧与完全可见耗时，立即
  显示模式下两者相同且都不含候选文字。内容更新先在兼容内存
  DC 完成，再一次贴到屏幕；位置或尺寸
  不变时不重复 `SetWindowPos`，尺寸不变时也不重设圆角区域，减少快速组合更新中

- Shift+Tab 暂时保留为开发期的显式对照入口，不再作为计划中的日用纠错交互。

  相邻按键颠倒；交换后的候选不能再使用第二次纠错，并且只能由完整双拼或
  首音节完整、尾部简写的片段组成。恢复搜索限于 16 键，普通候选仍保持
  零错误优先，不会因容错视图而偷偷换首选；
- 当前生产候选仍使用独立词频排序。公开探针 `ybqiui` 会把“有 + 其实”排在
  “尤其 + 是”之前，`buuidiyige` 也会把高频单字“地”排在“第”之前；两者都
  是完整码、零纠错路径，不能靠纠错罚分区分。固定 UD 训练集里“尤其 → 是”
  出现 10 次而“有 → 其实”为 0，也存在“不是 → 第一 → 个”的连续证据。
  后续上下文层应在一个冻结的较深公开候选池上用预计算稀疏 word bigram 重排，
  并同时测首屏延迟、内存和 Top-K 回归；本轮不把两个完整句子硬编码成排序规则；
- 双拼奇数键暂态不再完全交给自由混合简拼：候选首先尝试“此前音节全部完整、
  只允许最后一个音节保留声母”的窄通道，并最多提升三项；普通简拼继续留在
  后续候选，补齐韵母后的偶数帧保持原排序。该策略立即更新 TSF 候选语义，
  不通过延迟绘制掩盖候选变化；
- 普通 `Tab` 已接入公开单字音形辅助：当前组合先拆成至多四个音码槽；完整
  两键槽查询精确公开单字池，末尾还可有一个只含声母的一键槽，查询所有以该键
  开头的完整两键单字读音。因此单字声母、`jdj` 一类“完整槽 + 尾声母”和原有
  偶数长度路径都能找字，中间一键简拼仍不被猜测。进入后冻结当前槽的池，
  交互键使用自然码声母位置
  `h/u/p/n/v`（横、竖、撇、捺、折），内部映射为公开数据的规范
  `h/s/p/n/z` 笔画码后稳定过滤；其他小写字母保留为未来真实部件表的有序
  部件首字母前缀，过滤协议取笔画与部件证据并集。旧的 `s/z` 输入暂作兼容，
  Backspace 撤回一枚形码、空前缀时返回上一字或普通候选，Esc 直接返回。
  候选窗显示当前字位、当前两键码或“声母”槽，以及中文笔画/部件前缀。
  单字找字选择仍通过同一 TSF 提交路径且不单独写个人排序。普通空形码前沿仍为
  50 项；非空形码先在每槽至多 4,096 个公开精确单字身份中筛选，再应用 50 项
  可见上限，避免把最需要形码的深层字提前裁掉。最近四个不可变音码池按 LRU 复用。
  约 1.2 MiB 的固定公开笔画表只在宿主第一次输入真实形码时解析，空形码 Tab
  不承担这次工作，也不增加每个新宿主的固定启动工作；损坏时形码筛选失败关闭，
  不接管普通 Tab。精确 `xuy + Tab` 仍优先进入许愿；开发期 `Shift+Tab` 只用于
  对照自动纠错，不与找字共享产品语义；
- 二至四个音码槽可以在每槽均有公开精确单字池时逐段找字；只有最后一槽允许
  是声母池。候选窗以“找第 1 字 · qt · 形码 —”“雀 → 第 2 字 · h·声母 ·
  笔画 横”一类动态路径标明已选文字、当前槽和形码；中间字符只保留在当前
  组合内，不写文档、不记为独立选择。
  每个可选字都把公开精确池解析出的完整两键身份与文字一起带过过滤、分页和选择；
  完整槽必须精确匹配该身份，尾声母槽必须匹配身份首键，缺失、错位或不一致时
  失败关闭而不提交、不学习。选完最后一字后一次提交完整词，并把这次已验证组装
  作为可立即 Backspace 撤销的个人整词证据；奇数原码（例如 `jdj`）继续作为个人
  召回键，选字所得规范完整码（例如 `jdjm`）只作验证证据。空形码时 Backspace
  逐字退回上一段，Esc 返回原始码串；标点不会误提交
  半成品。五字以上、中间简拼分段和自动组词仍不在当前范围；
  完成的整词进入与普通个人候选相同的待确认、立即 Backspace 撤销、加密持久化、
  `Ctrl+Delete` 忘记及 Backspace 恢复闭环；再次召回时使用相同的个人记忆蓝点，
  不为 Tab 路径建立另一套词库或生命周期；
- 当前安装仍指向上一份不可变 DLL；新候选窗口必须在 Alpha 保持禁用时完成
  注销、重新注册，再由用户显式启用进行下一轮记事本测试。

### 4. 直接反馈与个人候选

自有输入法可以直接记录“按键、展示、选择、提交和取消”的结构化事件，不再
从 UI Automation 猜测候选行为。许愿和可选的持续研究都沿用当前用户 DPAPI
加密、无网络、显式授权和可停止边界。安全输入、密码框以及不允许文本服务的
输入范围一律不记录；不保存宿主周围正文。

先离线评测精确的“有效按键串 → 实际提交文字”，再决定是否创建持久个人
模型。记录过程不实时改变正在使用的模型。

第一步的宿主无关事件核心和显式前台控制已经完成，但仍只属于开发 Alpha：

- 正常激活的 TSF Alpha 默认维护不落盘的有界许愿滚动现场；持续研究落盘授权
  默认关闭，不会因激活文本服务、显示候选或输入文字而自行开启；
- 启动内存会话必须在调用点构造 `explicit_memory_only` 授权；默认构造、激活
  文本服务或显示候选都不会顺带开启；
- 内存会话具有明确的 `Disabled`、`Recording` 和 `Stopped` 状态。重复开始不会
  清掉正在记录或已经停止但尚未处理的事件；必须先停止，才能显式清空并开始
  下一轮。文本服务停用会结束正在记录的会话，但保留其内存内容直至服务对象
  释放；
- 前台文本服务提供 TSF 原生输入模式语言栏项目，但它只是可选控制面，不注册
  新的全局快捷键，也不与持续记录器的 `Ctrl+Shift+F10/F11/F12` 冲突。项目平时显示
  “中”或“英”；现代任务栏使用随系统文字颜色变化的 16×16“自”或“A”
  单色图标，仅内存反馈正在记录时显示一个圆点；
- Windows 11 现代输入指示器不保证为纯 `BTN_MENU` 项目调用 `InitMenu`。输入
  模式项目因此同时声明 `BTN_BUTTON` 和 `BTN_MENU`：现代路径在左键或右键
  `OnClick` 中创建短生命周期的原生 Win32 菜单，经典语言栏仍使用 `InitMenu`。
  两条路径消费同一份脱敏菜单模型；打开或取消菜单不会开始反馈，只有明确选择
  有效动作才会改变内存会话；
- 前台宿主启动后立即维护一个有界滚动内存现场；达到上限时分批淘汰最旧事件。
  输入法内许愿优先按最近完成的输入片段截取重点与少量前文，近 30 秒仅作兜底；
  语言栏的开始、停止和清除动作保留为开发生命周期检查，不再是日用前置步骤；
- 语言栏项目在文本服务激活时添加、停用时移除。Windows 11 现代输入指示器可能
  不展示它；`wish-ime.cmd mark` 仍可通过当前用户 TSF 全局 compartment 发送无正文
  整数命令。按需打开的单实例 `wishpad` 不再捕获或驻留托盘，而是列出、查看并
  整理已经保存的本地许愿；
- 组合码精确为 `xuy` 时，普通 Tab 用最近完成的输入片段确定重点，同时附带此前
  最多两分钟的有界前情，保存一次许愿并显示短暂回执；近 30 秒兜底仍可从语言栏
  或管理命令触发。没有滚动现场的开发测试
  宿主会先显示明确的开始确认，不会声称已经保存。
  `xuy + 空格` 和所有非 `xuy` 的 Tab 路径不变，因此该助记入口不占用普通候选
  或后续搜狗式笔画/部件找字协议；
- 事件默认只存在于调用进程内存；用户明确许愿时，才按输入片段或 30 秒兜底复制
  历史，并使用当前用户 DPAPI 写入稳定的本地许愿目录。用户还可通过独立设置
  开启[持续研究收件箱](research-feedback.md)，让普通输入域里的同类事件组成
  不重叠加密批次；它写入独立目录，不混入许愿列表。结构化包区分参考上下文、
  重点片段与 `xuy` 触发入口；控制通道不携带输入码、候选、路径或快照，也不
  连接网络；
- 只接收输入法自身已经展示的候选页，以及文档编辑成功后的选择、提交和取消；
  不读取密码、宿主周围正文或其他应用内容；
- 空格确认首选、Enter 原码提交、标点确认首选、数字选择、普通候选、换序候选、
  候选绝对名次、退格取消和 Esc 取消分别保留结构化身份；
- 单页最多保留 7 个候选，单次会话默认最多 4096 条事件和 1 MiB 私人文字。
  达到上限时停止接收并标记为不完整，不会丢弃旧事件后继续声称记录完整；
- 私人事件和解密后的许愿快照不实现调试输出；对外状态只包含条数、类型计数、
  是否完整，以及不含码串和原文的半音节间隔直方图。许愿使用单独的严格有界
  二进制格式，只有显式管理命令才可解密。

半音节计时只在反馈明确处于 `Recording` 时调用宿主单调时钟，并且只观察已经
成功显示的普通候选首页。奇数长度码串与紧随其后的偶数长度前缀扩展形成一个
样本；九个桶为 `<8`、`8–15`、`16–23`、`24–31`、`32–47`、
`48–63`、`64–95`、`96–159`、`≥160 ms`。单次绝对时间不会进入公开摘要；只在
反馈内存会话里与事件并列保留，许愿冻结时立即换算成相对点击时刻的年龄。
提交、取消、翻页、换序、Tab 找字、重复帧、码串跳变、上下文拒绝和时钟倒退
都会切断配对；停止与清除也会移除尚未配对的基线。该值是在候选呈现成功后
测得，会包含解码与宿主调度，不能当成原始按键间隔。

候选换序使用另一条更靠近输入事件、且不写文件的临时门。刚完成的一个完整双拼
音节按送达间隔进入三档：不超过 48 ms 时，高置信恢复候选可进入首位；49–63 ms
时，中置信恢复候选只从第二位开始插入；64–95 ms 时只在内存缓存里影子确认是否
存在恢复证据，候选文字与顺序都不改变；96 ms 起不再运行自动恢复检查。

三档共同服从同一语言证据门：原码已有显式别名、项目完整词、核心/补充完整词或
完整无错句子时保持原结果。无时序的离线决策仍在多个位置都能成词时拒绝；实时
TSF 请求则只检查送达间隔明确指向的刚完成音节，不让较早位置碰巧能成词掩盖
当前位置的因果证据。该位置反序后产生完整词时才算恢复可用；显示出来的候选继续以
`TranspositionRecovery` 来源记录。当前组合缓存保留首次决定，保证随后空格、
标点和翻页看到相同顺序。Shift+Tab 只作为验证自动路径召回差异的开发入口保留，
不要求日用用户发现错误后再进入另一个模式。

四键双字可以额外保留相邻两组各自的送达间隔。系统仍先尝试只恢复刚完成的一组；
若没有完整整词，才检查两组同时反序。组合恢复要求两组间隔都低于 96 ms、任一组
单独反序都没有完整整词、两组一起反序才得到完整整词，并以较慢一组决定首位、
第二位或影子档。首版只覆盖这一个四键相邻形态，不扫描更长组合或任意排列。非字母、
退格、提交、焦点变化和不连续码串会清除暂存间隔。

48、64 和 96 ms 对齐现有反馈直方图的边界，只是当前个人 Alpha 的可回退分档，
不是通用人体参数，也没有从私人输入拟合。候选帧现在会在内存中附带一次结构化
换序凭据：实际二键送达间隔、起始音节、连续音节数、请求档位、原码证据阻断/
无唯一恢复/恢复可用结果、恢复文字及其展示名次。双音节凭据记录两组中的较慢间隔。
随后已有的上屏事件给出最终选择，因此同一输入
片段可以判断可见恢复候选是否被采用；影子命中也不再丢失。用户明确许愿时，这些
私人凭据随重点快照写入；持续研究已独立开启时，它们也可进入日常加密批次。两条
路径都使用当前用户 DPAPI，不自动写模型，也不实时改变持久模型。当前进程内另有
一个有界分层校准器：只有可见恢复候选随后被同一码
明确采用或明确放弃时才产生标签，未知结果不充当反证；全局同桶 24 个或同一二键
同桶 8 个明确标签以前完全保留冷启动档位，跨过门槛后也最多移动一个相邻档位。
冷启动档位与实际采用档位都进入同一 V6 凭据；双音节组合凭据暂不进入这个单音节
校准器。该校准器不写文件，宿主或反馈会话
结束即归零。普通候选批次会复用已经完成的“原码完整词/完整句”阻断证据，恢复探测
只查询各音节交换后的完整词索引，不会为影子档再重复一次原句解码。实现只在当前
组合内保留上一个字母的单调时刻和一次结构化结果。以后若
研究个人相对节奏，必须使用明确授权、因果分离且可撤销的反馈，不能从一次退格
直接推断错误真值。

聚合的固定公开 release 基准可显式运行
`cargo test --release --lib pinned_public_transposition_probe_reuses_the_primary_gate -- --ignored --nocapture`；
它不读取私人会话，也不打印候选文字。当前本机 9 个可探测码、180 个样本中，
重复原句安全门平均约 2788.479 µs，复用普通候选证据后的增量探测约 0.820 µs。
这只证明本次结构调整移除了毫秒级重复解码，不是跨设备性能结论。

许愿 V6 保留每条事件相对点击时刻的毫秒数，不把宿主单调时钟绝对值写入包，
并标记参考前文、重点片段、触发入口、截取方式、候选来源、实际加载候选数、
当前页后已有候选/仍可继续加载/已到底、单字或逐字 Tab 位置/统一形码前缀和可选自动换序凭据；
V1/V2/V3/V4/V5 继续兼容读取。
未带时间的兼容调用不会被猜进 30 秒窗口；超过 1024 条时保留最近部分并明确
记录省略数量。冻结只复制事件，不停止、清空或改变记录生命周期。包写入失败只
留下脱敏失败状态，输入法继续工作。留言可通过独立 `wishctl annotate` 或
`wishpad` 管理器明确提供，和快照分别加密但绑定同一不可变 ID。管理器按时间
列出记录，只在选择后解密并显示重点现场；类别和说明可以原子替换，原始现场
保持不可修改。可选尾迹仍是后续工作，见
[“向猫猫许愿”：本地反馈与现场快照](wish-feedback.md)。
持续日常证据的授权、批次和停止语义见[持续研究收件箱](research-feedback.md)。

每条事件还必须通过独立的上下文资格门。前台 TSF 路径会先读取键盘禁用和空
上下文 compartment，再读取当前组合范围的 `GUID_PROP_INPUTSCOPE`：

- 只有明确报告普通文本、聊天、搜索、中文文本或 native-script 的范围进入
  允许状态；
- 密码、数字密码、PIN 和 `IS_PRIVATE` 分别归入敏感状态并拒绝；
- 属性缺失、读取失败、未来未知值以及 URL、邮箱、姓名、地址等其他专用范围
  都不会按普通文本猜测，而是拒绝；
- 翻页和换序这类没有编辑 cookie 的 UI 操作只复用同一组合最近一次成功检查，
  码串不一致或没有检查结果时拒绝；
- 拒绝只增加脱敏计数，不保存被拒绝事件；合成测试覆盖允许、密码、私人、
  键盘禁用、空上下文、受限和未知状态。

同一资格结果也约束个人排序落盘：明确非首选仍可在当前宿主的有界内存中立即
生效，但只有 `Eligible` 会建立持久层待确认事务，并在明确边界后进入加密批次。
这样不会把未知或敏感字段中的文字变成跨应用偏好，同时不影响当前组合的候选
交互。输入范围分类独立于可选的许愿记录生命周期；停止反馈只停止事件收集，
不会让普通候选或 Tab 组词悄悄失去个人学习。

首轮真实 Windows 11 验收确认：只有文字而返回空 `HICON` 的项目不会出现在
现代任务栏；Typora 已加载目标 DLL，因此该结果不是旧进程缓存造成。源码现已
补齐主题感知单色图标。Codex 仍可能继续持有换代前 DLL，必须用新启动的宿主
验收，不能强制从正在运行的进程卸载。当前用户 DPAPI 在线个人排序现已落地；
旧会话离线训练和上下文模型仍是另一阶段。

上述读取顺序与 Microsoft 的
[ITfInputScope](https://learn.microsoft.com/en-us/windows/win32/api/inputscope/nn-inputscope-itfinputscope)
示例一致：通过 `ITfContext::GetAppProperty(GUID_PROP_INPUTSCOPE)` 和当前范围
取得接口。官方
[InputScope](https://learn.microsoft.com/en-us/windows/win32/api/inputscope/ne-inputscope-inputscope)
说明还明确指出 `IS_PASSWORD` 本身不提供安全性，密码字段应禁用文本服务；
因此实现不会把“看见密码 scope”当成唯一防线。

语言栏生命周期遵循 Microsoft 的
[Language Bar (Text Services)](https://learn.microsoft.com/en-us/windows/win32/tsf/language-bar)
约定：文本服务在 `Activate` 添加项目，在 `Deactivate` 移除，并用
`ITfLangBarItemSink` 通知状态变化。Windows 8 以后的
[TF_LANGBARITEMINFO](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/ns-ctfutb-tf_langbariteminfo)
要求输入模式项目使用 `GUID_LBI_INPUTMODE`；因此这里复用同一个“中/英”入口，
没有伪造第二个可能被系统忽略的反馈按钮。微软公开
[SampleIME `LanguageBar.cpp`](https://github.com/microsoft/Windows-classic-samples/blob/77f217b3f89d4dac7864a62cc91ff7b569f26a50/Samples/IME/cpp/SampleIME/LanguageBar.cpp)
为 `TF_LBI_STYLE_SHOWNINTRAY` 项目返回真实的 16×16 图标；现代任务栏不会可靠
绘制只有文字而返回空图标的项目，因此 Alpha 同样从 `GetIcon` 返回透明背景
单色图标，并用 `TF_LBI_STYLE_TEXTCOLORICON` 交给系统适配明暗主题。
本地固定版本对照还显示，Mozc 的 Windows 8+ 输入模式项按普通按钮接收点击，
Weasel 则同时声明按钮与菜单并在点击路径主动弹出菜单；Alpha 只借鉴这一交互
边界，不复制其实现代码。原生弹出菜单以当前前台窗口为 owner，在用户点击期间
同步存在，关闭后立即销毁，不建立后台窗口或常驻线程。

## 安装、升级与回退边界

日常本地开发换代使用仓库根目录的 `update-ime.cmd`。它按自身位置寻找底层
`scripts/replace-tsf-alpha.ps1`，因此可以从任意当前目录运行，也可以由资源
管理器双击；不接受额外参数，不自行编译或下载内容。PowerShell 执行策略参数
和重新启用开关由包装入口固定传入。底层脚本先验证 release DLL 相邻的公开
候选槽，把它复制到 DLL SHA-256 对应的不可变构建目录并再次只读检查，然后
禁用当前用户配置、在单独管理员阶段完成注销和注册，最后重新启用。候选槽
缺失时脚本拒绝继续，不会安装后静默使用 50 词开发包。

`tsf-devctl inspect` 还会汇总可见进程中已经加载的 Alpha DLL：只区分与本次
检查 DLL 相同或不同的不可变版本并报告数量，不输出进程名、窗口标题、模块
路径或输入内容。这个只读提示用于区分“安装没有更新”和“既有宿主仍缓存旧
DLL”；无法枚举的受保护进程不冒充已检查。

入口会先核对 release DLL 摘要、严格安装凭据、候选槽状态和实际注册布局。
如果它们已经对应同一版本，只验证并确保当前用户启用，不再复制、注销、注册
或请求管理员权限。确有新 DLL 时仍执行完整事务；注册工具本身已经同步回读
注册结果并轮询注销传播，因此包装脚本不再额外固定等待两秒。相同 DLL 摘要下
若候选槽状态不同，入口拒绝改写不可变安装目录，要求先产生新的 DLL 构建。
控制器分别使用系统安装枚举和当前用户启用状态查询确认语言配置；刚注册但尚未
启用的配置不会因未出现在当前用户配置枚举中而被误判为缺失。当前用户切换会
先调用旧 `EnableLanguageProfile` 作为兼容通知，但不会再把它返回的 `S_OK`
当作持久成功证据；随后总是调用 Vista 起推荐的
`ITfInputProcessorProfileMgr::ActivateProfile` 请求状态。部分 Windows 版本会
拒绝与 `TF_IPPMF_DONTCARECURRENTINPUTLANGUAGE` 组合的调用并返回
`E_INVALIDARG`；控制器只对这个错误去掉可选标志重试。若现代调用仍失败，只有
系统枚举已经显示请求状态、且后续独立复查再次通过，事务才可继续。调用不包含
设为默认、进程范围或桌面会话范围的标志，也不会单凭旧接口成功就放行。

现代接口可能在执行命令的短生命周期辅助线程内暂时把配置标成活动，因此同一
进程内的启用事务只验证注册完整且启用位已经出现。换代脚本会在改动前读取一条
不含内容的当前用户状态，并在辅助进程退出后观察一个稳定窗口：换代前未活动时
必须验证“已启用、未活动”；换代前已经由真实宿主使用时，只验证持久启用并允许
这些既有宿主继续活动。活动状态不能从失败后的现场倒推，因此更新本身不会偷偷
激活原本未使用的输入法。摘要只报告已经通过的持久状态，不把请求冒充结果。
成功路径只显示结果、DLL 摘要、当前用户启用状态、可见宿主的新旧版本数量、
分阶段耗时和默认输入法边界；若仍有宿主缓存旧 DLL，会明确说明不必关闭应用、
下次打开时自然载入新版。底层检查的详细输出仅在失败时展开。宿主摘要来自独立的
`host-cache-state` 机器可读报告，不解析面向用户的检查文字，也不输出进程身份。
所有会改动候选构建目录、当前用户状态或本机注册的普通换代由一个独占文件锁串行
化；`status` 在锁之前返回，仍然不创建文件。启动管理员阶段之前会先清除并验证
旧的管理员报告，因此取消 UAC 不会回放上一次失败；清理报告失败发生在禁用之前。
若本机注册已经成功而候选、凭据或重新启用的后置验证失败，脚本会再次尝试恢复
原先请求的当前用户启用状态并保持默认输入法不变，然后仍以失败退出供诊断。
Windows PowerShell 5.1 对原生程序
stderr 的 `NativeCommandError` 包装由脚本先完整捕获，再按真实进程退出码处理，
不会在诊断行处抢先终止换代事务。脚本固定使用系统自带的 5.1，而不是仅因版本号
更高就切换到可选 `pwsh`；当前机器实测 `pwsh 7.6.4` 的无配置冷启动反而更慢，
而换代的主要等待来自 TSF 注册传播和一秒持久启用稳定窗口。成功路径只执行一轮
稳定窗口；宿主扫描同时校验待安装 DLL，因此不再重复运行等价的完整检查。

在任意 PowerShell 当前目录中均可运行：

```powershell
.\refresh-ime.cmd
.\refresh-ime.cmd status
.\refresh-ime.cmd space
.\refresh-ime.cmd cleanup
.\refresh-ime.cmd rollback
.\prepare-ime.cmd
.\update-ime.cmd
.\update-ime.cmd status
```

`refresh-ime.cmd` 不进入安装路径。它在独立 Cargo target 中离线构建八个用户态
管理、分析与桌面启动 EXE，以清单 SHA-256 建立不可变 `current / previous` 槽，
并让别名、
研究和许愿入口解析 current。失败时原指针不变，回退先验证两个包；已运行程序
继续使用旧映像，退出后重新打开即可自然切换。它不构建 `--lib`，不访问私人数据
根，也不操作 COM、TSF 配置或默认输入法。核心候选快照仍由已加载类工厂冻结；
装入本轮能力后的宿主可在组合之间安全刷新公开补充层，但这项能力本身和按键、
UI、新采集字段仍必须先安全换代 DLL。详细矩阵见
[用户态工具独立刷新](user-tool-refresh.md)。

经验证的桌面启动器另有固定副本，桌面快捷方式只向它传入 `wish`、`alias` 或
`update`。许愿和自定义短语直接打开 current GUI 而不经过批处理窗口；换代仍打开
可见控制台，以保留诊断与授权过程。固定启动器不接收任意可执行路径，也不绕过
工具槽摘要检查。

`prepare-ime.cmd` 把构建和安装拆成两个明确授权：它使用 `Cargo.lock` 与 Cargo
`--offline` 构建 release DLL、安装控制器以及日用别名、个人学习、持续研究和许愿
工具，随后只调用 `update-ime.cmd status`。这个阶段不请求管理员权限，不操作 TSF
注册或当前用户配置，也不会触碰系统已安装的内容寻址 DLL；因此可以在现有 Codex
宿主继续使用旧版时先完成。若本地依赖缓存不完整，离线构建直接失败，不回退联网。

`status` 是同一入口的只读分支：它验证 release 候选数据、安装凭据、当前用户状态
和可见宿主缓存，然后分别显示 release/installed 摘要与是否待换代。它不禁用、
注销、注册、启用或打开 `wishpad`，也不请求管理员权限；因此可在多个 Codex 任务
仍运行时随时区分“新版尚未安装”和“新版已经安装、现有宿主仍缓存旧 DLL”。
只读摘要同时分别报告 release 校验、已安装状态和宿主扫描耗时，避免把正常的一秒
状态检查误认为卡死，也能在不执行换代的前提下定位异常等待属于哪一段。

- 不直接写注册表设置默认键盘；注册使用 TSF 正式接口；
- 安装、注销、升级和回退必须是不同的显式操作；
- 更新前先切换到其他输入法，并等待旧 DLL 不再被新宿主加载；
- current / candidate / previous 的版本槽位不复用正在加载的文件；
- 显式别名使用独立加密三槽和稳定用户数据根；词语更新不要求重装 DLL，但只在
  新组合边界生效。旧版宿主第一次获得该能力仍需自然退出并加载新版 DLL；
- 个人排序使用稳定用户数据根中的当前用户加密不可变批次，不随 DLL 复制或覆盖；
  逐条忘记与恢复使用独立的同级加密动作日志。`personalctl status` 只显示计数，
  私人身份由 `forget` / `restore` 启动后从标准输入读取，显式清空只移动正向证据到
  同级可恢复归档；
- 注册失败或候选版本启动失败时，微软拼音和 previous 必须保持可用；
- 不申请网络能力，不把解码或私人数据发送给其他进程；
- 在 Windows PE/Authenticode 签名与兼容要求没有验证前，不称为可分发安装包。
- Vista 以后优先使用 `ITfInputProcessorProfileMgr` 管理语言配置；键盘 TIP 类别
  通过 `ITfCategoryMgr` 明确注册。标准 COM 激活信息、TSF 配置和类别必须各自
  有可验证的反向清理；
- DLL 同目录没有 `candidate-data` 时，默认类工厂只有 50 词开发候选源。它足以
  验证对象创建、解码和上屏，不足以日用；只读检查通过也不等于适合安装。
- 独立 `candidatectl` 能确定性生成公开包并原子管理
  current/candidate/previous。新类工厂会从 DLL 相邻的固定槽根读取 current；
  已有类工厂继续持有旧快照，活动组合不会热换。配置目录存在却无效时拒绝
  建立类工厂，不静默使用演示包。
- `candidatectl preflight` 会用包内确定性探针创建真实系统 Thread Manager 与
  合成 Context，经过同一个类工厂、预编辑和首选上屏。`adopt` / `stage` 只有在
  独立可信包摘要、来源、许可、解码兼容性和该预检全部通过后才写材料绑定
  凭据；提升和回退会复核凭据与当前包内容。
- `candidatectl verify-signature` 可以用独立渠道取得的公钥只读验证候选包
  Ed25519 脱离签名，并给出供 `--expected-sha256` 使用的发布摘要；
  `adopt-signed` / `stage-signed` 也可在任何槽位写入前完成相同验签，并把同一
  份已验证材料交给安装与预检。所有命令都要求显式公钥，不发现或保存信任根；
  当前也没有真实发布公钥、签名命令或密钥轮换与吊销策略。
- `tsf-devctl register-machine` 先把 DLL 固定到
  `.local/tsf-alpha/builds/<sha256>`，再依次注册本机 64 位 COM、TSF
  文本服务身份、默认关闭的 zh-CN 配置和键盘类别。任何失败都会逆序撤回；
  注销也会先复核严格安装记录与系统状态，再执行反向事务。注册、启用、激活
  和设为默认仍不合并。

## Alpha 接受条件

- 记事本和 Codex 都能重复完成输入、取消、翻页、选择与切换输入法；
- 宿主关闭、输入法停用、焦点切换和解码失败均不使宿主崩溃；
- 候选结果与终端宿主使用相同核心，在固定输入下保持确定；
- 禁用/卸载后无残留后台采集，微软拼音始终可选；
- 性能报告区分解码、TSF 编辑会话和候选 UI，不用一次总耗时掩盖问题；
- 私人反馈只有经过再次明确授权的本地实验才会读取。

达成这些条件后，Alpha 才进入自然日用；此前仍是可构建、可测试、可卸载的
开发版本。
