# Tab 音形辅助：显式的第二阶段筛选

## 它解决什么

普通双拼已经给出正确读音，但目标单字因为生僻、同音字多或词库排序靠后，
需要翻很多页。这里不把日常输入改造成音形码，而是在用户明确按下 Tab
以后，使用少量形状信息过滤**已经生成的候选池**：

```text
普通双拼按键
  → 冻结普通候选及其原顺序
  → Tab
  → 输入笔画前缀或有序部件首字母
  → 只做稳定过滤，不改分、不自动上屏
```

搜狗官方帮助给出的两个入口是：

- [笔画筛选](https://pinyin.sogou.com/help.php?list=3&q=9)：Tab 后以
  `h/s/p/n/z` 表示横、竖、撇、捺、折；例子是 `zhen + Tab + hh`
  缩小到“珍”；
- [拆字辅助码](https://pinyin.sogou.com/help.php?list=3&q=12)：Tab 后输入
  有序部件的拼音首字母；例子是 `xian + Tab + nx`，用“女、闲”定位
  “娴”。

搜狗另有[U 模式笔画输入](https://pinyin.sogou.com/help.php?list=3&q=8)，
用于不知道读音的字；双拼下因 `u` 已被占用而使用 `Shift+U`。它与本轮
“已知读音后的精细筛选”分开研究。

## 当前冻结的最小协议

`TabShapeQuery` 只接受：

```text
非空小写双拼键 + 一个字面 Tab + 可为空的小写形码前缀
```

刚按 Tab、尚未输入形码时，候选池完全不变。输入前缀以后：

1. 在指定的候选字符位置查找形状记录；
2. 若完整五类笔画码以该前缀开头，则保留；
3. 若任一有序部件首字母码以该前缀开头，也保留；
4. 同时命中两者时只保留一次候选，但把两条证据都报告出来；
5. 保留原候选顺序和原分数，不让形码悄悄变成新的语言模型。

`h/s/p/n/z` 也可能是部件拼音的首字母。搜狗帮助页没有给出二者冲突时
的优先级规则，因此原型采用可审计的并集匹配，而不是臆造隐藏优先级。
如果真实操作数据表明并集缩小得不够，再讨论显式切换或稳定的判别规则。

目标位置是显式参数。`0` 表示筛选候选的第一个字，也可以在以后候选分段
协议明确后筛选词中某一字。模块本身不猜当前光标属于哪个音节。

## 数据边界

第一份真实笔画快照现已导入：固定提交、许可、来源 URL、SHA-256、转换
规则和确定性账目见
[公开数据审计与许可隔离](shape-data-audit.md)。它覆盖 28,165 个字符，
并保留上游给出的替代笔顺；`CharacterShape` 因此支持一个字符有多个完整
笔画码，任一替代码匹配前缀都会留下可审查证据。

在固定 Rime 公开词典中，解码器实际接受词条所含的 16,469 个不同汉字
全部能在这份笔画表中找到。这个结果只排除了当前公开候选集合里的“无数据”
问题，不证明笔顺真值或筛选收益。

上游资料由人工整理，并明确提醒可能有错；其字形多循康熙字典，笔顺也
刻意宽松。它是候选筛选证据，不是权威的大陆规范笔顺真值。真实部件数据
仍未导入：现有部件接口和测试依旧只是人工合成，不能用来宣称拆字覆盖。

Unicode Unihan 的部首、总笔画等属性也不是完整五类笔顺库。不得抓取或
复制搜狗私有字形表来填缺口，也不得因为某个上层代码库采用宽松许可，
便忽略其附带数据文件自己的许可。

## 评测不只看 Top-1

Tab 是用户主动求助后的筛选器，关键指标应是：

- **目标保留率**：正确字不能被错误形码数据筛掉；
- **最短定位长度**：输入几枚形码后能缩到可见范围；
- **候选缩减率**：原池到新池缩小多少；
- **Top-10 可见率**：目标是否进入一屏，而不只看第一名；
- **无数据率**与**无命中率**：分开统计缺字和形码不匹配；
- **歧义并集率**：同一前缀同时按笔画、部件命中的比例；
- **额外动作数**：Tab、形码和最终选择的总成本。

只有在固定公开数据和宝宝的私有回放都显示目标保留可靠、动作数实际下降
以后，才值得进入真正的交互层。当前模块不注册热键、不监听 UIA、不读取
私有会话，也不把项目扩成 TSF 输入法。

## 第一轮公开单字课程结果

现在可以运行：

```powershell
cargo run --release -- public-shape-audit
```

课程只使用仓库内固定的 Rime 与 Conway 快照，不读取私人记录。它先把文字
恰为一个 Unicode 字符的词条按**完整双拼码**分池；池内以词典权重降序作
确定性排序代理，同权重再按文字和拼音排序。这里只练原排名第 11 名以后、
确实需要翻页的目标。形码筛选始终保持原顺序，因此“进入 Top-10”看的是
筛选后的稳定名次，而不是简单假设候选总数小于十。

固定快照结果：

| 最多输入笔画 | 替代笔顺试次进入 Top-10 | 目标任一笔顺可见 | 目标全部笔顺可见 | 平均候选池 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 15,410 / 29,906（51.53%） | 7,461 / 13,285 | 7,029 / 13,285 | 91.94 → 24.41 |
| 2 | 24,796 / 29,906（82.91%） | 11,492 / 13,285 | 11,019 / 13,285 | 91.94 → 10.71 |
| 3 | 28,292 / 29,906（94.60%） | 12,770 / 13,285 | 12,589 / 13,285 | 91.94 → 5.47 |

13,285 个困难目标全部有笔画数据，其中 6,868 个有两个或更多替代笔顺；
所有 29,906 个笔顺试次都保留目标。“任一”是用户恰好采用最有区分力笔顺
的乐观边界，“全部”是无论采用哪条上游认可笔顺都能看见目标的稳健边界。
二者同时报告，避免替代笔顺多的字被静默按试次数加权，也避免只挑最好看
的一条笔顺。

这轮已经证明路线具有明显的**结构性筛选能力**，但还不能宣称真实净省
操作：Rime 权重不是宝宝当前微软输入法的候选顺序，课程也没有观测翻页、
视觉搜索、最终选词和输错笔画。每条路径还固定增加一次 Tab 与一至三枚
笔画键。下一道门仍然是显式获准后在本地私人回放里只抽取“首屏外找字”
情形，对比原本翻页/组词/删改和 Tab 筛选的完整动作账。

## 私人回放动作账入口

在用户明确授权本地私人实验后，可以对逐个点名的加密持续会话运行：

```powershell
cargo run --release --bin capsule-replay -- `
  --session <SESSION_ID> `
  --shape-audit
```

该入口不输出字、拼音、按键串、路径或逐例详情，也不写文件。它把普通
单字与“2～4 字短语后五秒内纯删除、只留一个原字”的候选分开；后者保持
为意图未知的行为形状，不能自动解释成找生僻字。自定义短码或内部改键会
计入 `noncanonical_observations`，不会硬塞进规范完整双拼的单字动作对比。
详细事件条件、动作下界和跨胶囊限制见
[私人事件胶囊与离线回放](event-capsules.md)。真实聚合属于私人行为元数据，
只在获准实验中查看，不提交到仓库。

## 公开会话式实验台

结构课程回答总体上“能否筛回来”，`shape-lab` 则把同一口径缩到一个可
检查的公开单字：

```powershell
# Windows 交互终端：直接按 Tab、笔画键和数字；每键立即生效
cargo run --release -- shape-lab shi --expect 事

# 一次性复现某个前缀
cargo run --release -- shape-lab da --expect 龘 --prefix n --limit 10

# 只有排查实现时才看原排名、动作投影和完整公开笔画码
cargo run --release -- shape-lab da --expect 龘 --prefix n --details
```

实验台按规范自然码把一个无声调拼音编码成完整双拼码，冻结固定 Rime
单字池，并与公开课程共用同一份“权重降序、文字与拼音打破平局”的排序
索引。空前缀就是普通池；非空前缀只能含 `h/s/p/n/z`，只匹配 Conway
笔画码开头并保持原相对顺序。

默认会话刻意不报告“找到了”、是否省键、候选池大小、原排名或完整笔画
码。选择候选后，选中的字就是全部结果；宝宝是否觉得省力不能由程序代替
判断。交互屏只保留目标、双拼、当前前缀、候选和按键提示，`--details`
才恢复供开发者排错的完整审计输出。

Windows 交互终端使用控制台事件逐键读取：直接按 `Tab` 进入，`h/s/p/n/z`
过滤，退格撤回，`Esc` 返回，数字选择，全程不需要 Enter。读取层不注册
全局热键，也不改动控制台模式；状态转换另有平台无关的顺序测试。重定向、
管道或不支持控制台事件的平台自动使用行命令回退，此时以 `t` 代替 Tab、
以 `-` 代替退格，并在每个命令后按 Enter。

这里刻意不接私人胶囊、不学习输入、不写文件，也不注册系统级 Tab 热键。
详细模式中的动作数只是“完整双拼字母 + 可选 Tab + 笔画键 + 一次选择”的统一投影；
终端历史仍会留下参数与输出，因此 `--expect` 只用于公开或合成目标。它的
价值是让协议错误、错误笔画和排序代理的局限立即可见，而不是提前宣称已
获得真实输入法手感。
