# 项目地图：我们现在到底在做什么

## 一句话目标

宝宝按下自然码按键，程序给出真正想写的中文；即使没有手动分词、偶尔
按错一键，也不能悄悄吞字或假装很确定。

这不是在发明一套抽象协议。项目首先要忠实理解宝宝已经在用的键盘，
然后才研究怎样少按键、怎样连打、怎样排序候选。

## 从按键到中文的五层

```text
宝宝实际按键
  ↓
1. 键盘翻译：每个拼音在自然码里究竟是哪两键
  ↓
2. 可写内容：词典里有哪些中文、拼音和候选
  ↓
3. 找路：在哪里分词，哪里漏按、多按、按到邻键或颠倒
  ↓
4. 排序：许多合法中文里，哪一句更像宝宝想写的
  ↓
5. 交互：候选怎样显示、选择、学习和撤销
```

第一层一旦错了，后面的评测数字就会失去意义。这次发现的错误就在
第一层：规范零声母应为 `an → an`，不是 `an → aj`。宝宝举出的其他
映射是对的：

| 拼音部分或音节 | 宝宝实际自然码 |
|---|---|
| `sh` | `u` |
| `ch` | `i` |
| `uang` / `iang` | `d` |
| 有声母时的韵母 `an` | `j` |
| `shuang` | `ud` |
| `chan` | `ij` |
| 零声母 `an` | `an` |

Rime 可以派生 `aj` 一类兼容输入，但兼容别名不是宝宝键盘的规范输出。

## 已经做了什么

| 部分 | 当前状态 | 它回答的问题 |
|---|---|---|
| 键盘翻译 | 已纠正，并有聚焦测试 | 程序是否看懂宝宝按的键 |
| 词典与紧凑索引 | 可运行 | 哪些中文在候选范围内 |
| 词界与一次按键错误 | 可运行、可解释 | 不加空格和小误触时能否找到候选 |
| 搜索性能 | 已从秒级降到毫秒级实验负载 | 算法是否快到可以继续研究 |
| 公开评测 | 已有固定 Rime/UD 数据 | 改动究竟变好还是只对几个例子好看 |
| 中文上下文排序 | 目前很弱 | 合法候选很多时能否选对 |
| 自由混合简拼 | 只保留作压力测试 | 搜索器能表示，不等于适合作为输入方式 |
| 真正输入法界面与个性化 | 尚未开始 | 日常打字是否舒服 |

最近大量性能工作解决的是“候选搜索会不会慢得无法实验”。它很有用，
但不等于打字正确率已经提高。现在性能暂时够用了，近期不应继续为了
跑分无限优化；更重要的是先确认键盘事实和候选质量。

## 双拼能不能融合简拼

答案不是简单的“能”或“不能”：

- 任意一个音节都可随时从两键缩成一键，并且整句没有标记：程序能搜索，
  但按键本身不能唯一确定原句。`aa` 既可看成完整音节 `a`，也可看成
  两个 `a` 开头音节的简写。
- 这不等于简拼没有价值。常用词快捷写法、整词全简拼、完整开头加尾部
  简写、候选栏补全，都可能实用。
- 理论推演负责排除“不可能无歧义”的强说法；公开实验负责比较“虽然
  有歧义，但候选是否仍然好用”。两者缺一不可。

所以前面的十几个小时不是证明“简拼不可行”，而是证明“不该把自由混合
当成已经成立的基础”。接下来要比较更贴近日常输入的几种简写方式。

## 接下来怎么走

### 现在：把地基校正

1. 固定宝宝实际使用的自然码表，特别测试零声母、`zh/ch/sh` 和复合韵母。
2. 用纠正后的 codec 重跑全部公开评测，旧数字一律作废。
3. 每份结果明确写清：确定事实、实现兼容写法、研究假设分别是什么。

### 下一段：先让正常双拼能用

1. 把完整双拼、无词界短句作为可靠主线。
2. 测量正确候选是否进前 1、前 5、前 10，而不只测运行速度。
3. 先改善候选召回与中文排序；短句没有稳定以前，不用长句成绩自我安慰。
4. 未知词或拿不准的输入必须诚实保留，不静默变成另一句中文。

### 再下一段：大胆比较简写

并行比较几种真实操作，不先把其中一种宣布为最终答案：

- 一个词要么完整双拼，要么整词全简拼；
- 至少一个完整音节后，后面连续使用简拼；
- 常用词和短语的快捷写法；
- 输入几键后由候选栏补全。

比较的不只是准确率，还包括少按了多少键、正确项排第几、选择候选又花了
多少操作。若一种简写省下的键都被选词和改错抵消，就停止那条分支；
若它在常用短语上明显省力，就继续扩展到更长输入。

### 最后：做成宝宝能长期使用的东西

只有主线正确率和简写方式稳定后，才进入真实界面、个人词库、学习候选、
撤销和隐私存储。长句模型属于这一阶段的重要能力，但不必拿它来掩盖
基础双拼还不能正常连打的问题。

## 什么时候可以停

这个项目没有一个“研究完所有输入法问题”的终点，可以按里程碑停：

1. **研究基线完成**：映射正确，公开数据可复现，完整双拼和一次误触都
   有稳定 Top-K 结果。
2. **简写结论完成**：至少比较三种受限简写，知道哪种真能净省操作，
   哪些应放弃。
3. **可试用版本完成**：宝宝能在一个真实输入框里连续输入，错误可撤销，
   未知内容不会丢失。
4. **长期优化**：只有宝宝实际使用后暴露的问题，才继续投入性能、长句
   上下文和个性化。

眼下最合理的停止点不是“性能再快一点”，而是完成第一里程碑，然后让
宝宝亲手试一小批短句。那时我们会第一次拥有“程序指标”和“真实手感”
两种证据，再决定往简写、长句还是界面方向大胆扩展。
