# 项目地图：我们现在到底在做什么

## 一句话目标

宝宝按下自然码按键，程序给出真正想写的中文；即使没有手动分词、偶尔
按错一键，也不能悄悄吞字或假装很确定。

这不是在发明一套抽象协议。项目首先要忠实理解宝宝已经在用的键盘，
然后才研究怎样少按键、怎样连打、怎样排序候选。

## 从按键到中文的五层

```text
宝宝实际按键
  ↓
1. 键盘翻译：每个拼音在自然码里究竟是哪两键
  ↓
2. 可写内容：词典里有哪些中文、拼音和候选
  ↓
3. 找路：在哪里分词，哪里漏按、多按、按到邻键或颠倒
  ↓
4. 排序：许多合法中文里，哪一句更像宝宝想写的
  ↓
5. 交互：候选怎样显示、选择、学习和撤销
```

第一层一旦错了，后面的评测数字就会失去意义。这次发现的错误就在
第一层：规范零声母应为 `an → an`，不是 `an → aj`。宝宝举出的其他
映射是对的：

| 拼音部分或音节 | 宝宝实际自然码 |
|---|---|
| `sh` | `u` |
| `ch` | `i` |
| `uang` / `iang` | `d` |
| 有声母时的韵母 `an` | `j` |
| `shuang` | `ud` |
| `chan` | `ij` |
| 零声母 `an` | `an` |

Rime 可以派生 `aj` 一类兼容输入，但兼容别名不是宝宝键盘的规范输出。

| 真正输入法界面与个性化 | 已抽出宿主无关组合核心；正式类工厂可在合成 Context 内完成解码、上屏、焦点清理与编辑事务；公开包可确定性生成，经独立摘要或 Ed25519 签名验证并通过真实 TSF 合成 Context 预检后进入三槽提升或回退；新类工厂已能读取外部 current，仍未注册或安装 | 日常打字是否舒服 |

最近大量性能工作解决的是“候选搜索会不会慢得无法实验”。它很有用，
但不等于打字正确率已经提高。现在性能暂时够用了，近期不应继续为了
跑分无限优化；更重要的是先确认键盘事实和候选质量。

## 双拼能不能融合简拼

答案不是简单的“能”或“不能”：

- 任意一个音节都可随时从两键缩成一键，并且整句没有标记：程序能搜索，
  但按键本身不能唯一确定原句。`aa` 既可看成完整音节 `a`，也可看成
  两个 `a` 开头音节的简写。
- 这不等于简拼没有价值。常用词快捷写法、整词全简拼、完整开头加尾部
  简写、候选栏补全，都可能实用。
- 理论推演负责排除“不可能无歧义”的强说法；公开实验负责比较“虽然
  有歧义，但候选是否仍然好用”。两者缺一不可。

所以前面的十几个小时不是证明“简拼不可行”，而是证明“不该把自由混合
当成已经成立的基础”。接下来要比较更贴近日常输入的几种简写方式。
第一轮受限协议对照已经完成，方法和账目见
[受限简写协议审计](protocol-audit.md)：显式全简即使有模式键仍丢失
太多信息，停止作为通用默认；公开短语白名单不能向新短语泛化；补词界
只救回 1/24，fit-only word bigram 也让完整码和尾简同时退化。保守尾简
与锚定尾简都保留，交由真实选择成本决定。

## 接下来怎么走

### 现在：把地基校正

1. 固定宝宝实际使用的自然码表，特别测试零声母、`zh/ch/sh` 和复合韵母。
2. 用纠正后的 codec 重跑全部公开评测，旧数字一律作废。
3. 每份结果明确写清：确定事实、实现兼容写法、研究假设分别是什么。

### 下一段：先让正常双拼能用

1. 把完整双拼和“完整首音节 + 尾部简写”的无词界短句作为可靠主线。
2. 测量正确候选是否进前 1、前 5、前 10，而不只测运行速度。
3. 先改善候选召回与中文排序；短句没有稳定以前，不用长句成绩自我安慰。
4. 未知词或拿不准的输入必须诚实保留，不静默变成另一句中文。
5. 把 [Tab 音形辅助](tab-shape-refinement.md) 保持为用户显式开启的第二
   阶段筛选；公开课程已证明三画可把 12,589 / 13,285 个首屏外目标在全部
   替代笔顺下筛回 Top-10，下一步只在明确授权的私人回放中测净动作数。
6. 用[候选实验台](candidate-lab.md)分开简洁中文、详细研究证据和稳定
   JSON；锚定尾简颠倒恢复只有显式请求才出现。在真实界面出现前只显示
   统一的字母/选择/切栏投影，不伪造翻页和视觉成本。用 `--expect`
   冻结课程目标，只报告当前可见栏的精确名次，并区分未命中与未检查。

### 再下一段：大胆比较简写

并行比较几种真实操作，不先把其中一种宣布为最终答案：

- 一个词要么完整双拼，要么整词全简拼；
- 至少一个完整音节后，后面连续使用简拼；
- 常用词和短语的快捷写法；
- 输入几键后由候选栏补全。

比较的不只是准确率，还包括少按了多少键、正确项排第几、选择候选又花了
多少操作。若一种简写省下的键都被选词和改错抵消，就停止那条分支；
若它在常用短语上明显省力，就继续扩展到更长输入。

### 最后：做成宝宝能长期使用的东西

只有主线正确率和简写方式稳定后，才进入真实界面、个人词库、学习候选、
撤销和隐私存储。长句模型属于这一阶段的重要能力，但不必拿它来掩盖
基础双拼还不能正常连打的问题。

在开发输入追踪器以前，先按[真实输入兼容性体检](real-input-compatibility.md)
检查三个常用输入环境。若输入框不能可靠报告输入法最终提交，不继续堆
全局钩子和全文快照；按体检中的停止条件改走单应用适配或自有输入法壳。

Codex 的 ProseMirror 输入框已经完成第一轮体检：能收到完整拼音组合和
最终文本变化，但没有 `CompositionFinalized`，因此判为 B。当前只允许
按[Codex 单应用输入追踪探针](tracker-probe.md)做局部差分实验；其单框
人工清单已经完成。原子事件之上的
[纠错候选归并](correction-candidates.md)已能区分先删后补与一条提交内的
直接替换，并已在探针中用显式时间边界完成两种形态的人工短句验证；
只有聚合可显式保存，并可由
[只读脱敏摘要汇总器](summary-report.md)逐个点名合并；仍没有原子事件、
候选明细或训练管线；
另外两个常用环境未通过以前，不把它扩成通用或常驻采集器。

经过隐私审查的[私人事件胶囊](event-capsules.md)安全骨架已经建立，Codex
的这个 ProseMirror 输入框是首个白名单来源。它必须显式给出新路径、
按键捕获和“私人明文未加密”确认，且只在 READY 后保留有界差分；没有
自动保存或目录扫描。脱敏回放会严格分开整段锚定与由规范全码目标路径
提供词界的逐词重新锚定；显式时间边界还能把连续追加的逐词提交合成一个
非滑动窗口，直接模拟去掉词间选词键。逐词词尾策略另有“单音节词保留
完整码”的保守对照；`--compact` 会把窗口质量、操作数与相对完整码的
配对名次变化压成少量核心行，无可缩短窗口也保留在相同分母中。人工
非敏感端到端验证已通过，随后只完成一次短自然试航；先解释配对结果，再
决定是否增加极少量样本。两个互斥的显式公开上下文对照只从锁定的 UD
train 构造 word bigram 或 character bigram，只重排冻结的 unigram
Top-50，不用私人目标训练，并把上下文相对退化与基线不可比窗口分开
报告。另有显式 `--ranking-report` 在一次私人输入流式遍历中，对相同窗口
并列统计现行频率、公开词 bigram 和公开字符 bigram；它只报告 Top-K、
Top-1 得失、名次变化与 Top-10 掉出/救回，不把研究路线写进程序输出。
字符模型按候选平均转移分数排序、不依赖候选词界。两条公开重排现在只
保留作可复现诊断，不进入产品排序主线；后续回到个人、本地且可撤销的
学习设计，不再扩建公开模型。
第一条 `--personal-cache` 因果骨架已经只在内存中运行：每个窗口严格
先评分、后学习，只从规范全码的精确公开词界提取词次，并在由可见
Top-10 加最大三位提升推导出的冻结 Top-13 内重排。第 14 名及以后不可能
进入可见前十，因此不再为个人缓存生成无效的 Top-50 深池。它没有导出或
隐式保存；修订的反向扣除依赖当前
胶囊的内存跨度账本：确定位置的整段或局部重叠编辑会撤销受影响
提交的全部词次，前方编辑会移动后续跨度；跨胶囊只保留计数、不沿用旧
输入框位置。歧义或未关联修订继续脱敏计数。当前仍只用于判断“过去输入
是否在未来窗口提供受限帮助”，不能进入实时或持久化主线。
里程碑结论是保留这套最大三位、可撤销的词频缓存作为安全底座，但停止把
单词频次继续调权成简写方案。后续只有有序个人词对/短语模型值得另开
对照，而且必须相对个人完整码基线计算，不能重复归因。
独立 `--personal-pair-cache` 已在同一可撤销账本上加入窗口内及跨连续
提交的相邻词对；它包含相同词频底座，但合计提升仍封顶三位。词对序列
使用自己的文档跨度，局部重叠会撤销整条序列贡献。
`--personal-pair-comparison` 现已把词频与词对放进同一评测：公共、
冻结历史词频、冻结历史词频加词对和因果在线词对共享每窗一份 Top-13
候选池，并专门报告词对相对词频的 Top-1 得失、名次变化和 Top-10 进出。
只有顺序证据新增救回或减少相对退化，才继续短语模型。
当前单次自然试航的保留词对 token 与 type 相等，没有重复词对证据，
因此词对与词频模式的脱敏名次完全相同，三元组路线停止。回放器现改用
显式 `--history-input` 只训练过去会话、`--input` 只评测未来会话，
并冻结报告历史 token/type/repeated 证据量。新增
`--personal-word-comparison` 可在一次流式评测中并列统计公共排序、冻结
历史词频和因果在线词频：冻结与因果路线从相同历史起步、共享每条码的一次
Top-13 候选搜索，只有因果路线在窗口预测后学习。该命令仍只读私人输入、
只输出脱敏聚合，不写个人模型；是否继续某条路线留给报告之外的研究判断。
独立 `--personal-code-comparison` 又在同一候选搜索上加入精确
`实际窗口码 + 窗口文字` 的冻结/因果完整码路线，用于单独测量按码隔离。
它还比较冻结历史词频与因果精确身份的混合路线；两类证据相加后共同封顶
三位。所有路线继续使用可撤销窗口跨度，明确保持无衰减、不评估简写。

为避免“想起来才开短探针”让样本永远停在十几个词，Codex 白名单来源
现在另有[持续记录器](continuous-recorder.md)：不再绑定旧 PID，能在
Codex 重启或 UIA 元素重建后等待并重新绑定唯一精确目标；新事件按数量
或时间切成 Windows 当前用户 DPAPI 加密的 `.zcs`。它保留暂停、停止和
脱敏状态，既不读取其他应用，也没有自动安装系统启动项。`daily`、
`course`、`theme` 先作为加密会话类别骨架；课程步骤和主题提示以后叠加
在同一事件流上，不另造采集协议。当前先完成一次可见的手动长会话与
重连复测，再单独征得授权决定是否安装可卸载的登录启动入口。

候选版、当前版、上一良好版、排空、提升和回滚不借用双实例服务器模型；
本地单实例现由 `recorderctl` 的固定槽位和原子状态指针管理，职责边界见
[持续记录器的本地换代协议](recorder-lifecycle.md)。

加密段现同时冻结 `producer_version` 和 `capture_profile`，停止时直接
给出整会话的脱敏反馈命令。回放器的 `--session` 只展开该会话连续的
可预测段名，不扫描私有目录；`--history-session` 与后续 `--session`
把旧历史学习和新会话评测分开。后续修改遵循
[反馈驱动升级闭环](feedback-upgrade-loop.md)：促成改动的会话自动成为
开发证据，必须等待下一份独立自然会话才能宣称升级；完整码不退化、
简写相对退化减少且真实操作数不恶化，才进入下一轮。

## 什么时候可以停

这个项目没有一个“研究完所有输入法问题”的终点，可以按里程碑停：

1. **研究基线完成**：映射正确，公开数据可复现，完整双拼和一次误触都
   有稳定 Top-K 结果。
2. **简写结论完成**：至少比较三种受限简写，知道哪种真能净省操作，
   哪些应放弃。
3. **可试用版本完成**：宝宝能在一个真实输入框里连续输入，错误可撤销，
   未知内容不会丢失。
4. **长期优化**：只有宝宝实际使用后暴露的问题，才继续投入性能、长句
   上下文和个性化。

眼下最合理的停止点不是“性能再快一点”，而是完成第一里程碑，然后让
宝宝亲手试一小批短句。那时我们会第一次拥有“程序指标”和“真实手感”
两种证据，再决定往简写、长句还是界面方向大胆扩展。
