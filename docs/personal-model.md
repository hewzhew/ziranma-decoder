# 加密个人模型：持久化边界与生命周期

## 状态

个人化现已分成两条相互独立的路径：

- **在线个人排序 V1 已启用。** TSF 把数字选择或翻页后确认这类明确非首选
  视为 `code + text` 证据；已经由个人记忆召回且可逐字公开验证的二至四字
  完整个人词，再次空格确认时也增加同一完整码支持。当前宿主立即使用；普通文本等明确允许的输入范围先
  建立待确认事务。紧接数字或空格确认的空组合 Backspace 可撤回事务，其他按键、
  焦点离开或停用才确认并通过 Windows 当前用户 DPAPI 写入不可变小批次，使它
  跨应用、跨 DLL 换代继续生效。密码、PIN、私人、受限和无法确认的输入范围不
  写入。
- **旧会话离线模型尚未启用。** `--personal-cache` 与
  `--personal-pair-cache` 仍只用于内存实验；持续记录器不会自动训练，回放器也
  不会保存词频或词对。只有“旧会话学习、独立后续会话评测”证明新增价值后，
  才实现下文的版本模型。

逐条显式忘记使用独立抑制层：它只遮住精确 `code + text` 个人证据，可恢复且不改
公共词典。每次忘记或恢复都作为当前用户 DPAPI 加密的不可变动作追加到同级
`personal-suppression` 目录；它使用独立 schema、魔数和扩展名，不改写正向证据，
旧 DLL 也不会误读。TSF 同时对长期排序与当前会话置顶应用该快照；恢复后既有正向
证据可以重新生效。

个人排序同时提供一条有界的“完整码 → 规范尾简”继承。来源必须是公开快照或项目
公开词层能够验证的完整整词；目标码必须保留至少第一个完整双拼音节，并把一个
非空尾部的每个音节缩成首键。目标文字还必须已经存在于该短码的普通候选池中，
因此 `jdjd → 讲讲` 可以影响 `jdj`，但不会影响 `jd`、首音节简写、任意前缀、
显式私人别名或自由分句。短码自己的未抑制精确证据优先于继承证据；来源完整码
和目标短码任一侧被显式抑制时都不继承。在短码下忘记只追加短码的抑制动作，
恢复后重新使用仍保留的完整码证据。

逐字 Tab 组成的个人整词另有更窄的短码发现门。完整码必须累计至少两次确认，
文字长度必须与二至四个完整双拼音节一致，每个 `两键码 → 单字` 还必须分别属于
公开精确候选；这避免把任意句子、无法验证的别名或一次试探直接注入简拼。满足后
只允许进入上述规范尾简关系，并保留固定前缀与第一个普通候选，把个人词放在其后
的发现位。用户再明确选择一次发现项，才按普通流程建立短码自己的精确证据。短码
suppression 只关闭发现视图，完整码支持继续存在；自动换序请求不运行这条发现门。

在线层也会连接两个相邻的明确单字选择。两个组成项都必须是公开候选源能够验证的
两键完整双拼码和单个汉字；组合码与文字分别直接连接。第一次组合就进入当前宿主
的可撤销候选，第二个字之后紧接 Backspace 会撤销组合；若存活到下一按键、焦点
离开或停用边界，则同一次使用便作为独立 `code + text` 证据进入现有 DPAPI 批次。
短语证据和两个单字证据彼此独立，忘记短语不删除单字偏好。第一页空格首选、标点、
简拼、纠错、Tab、换序、原码和不合格输入范围不参与。首版按连续键盘提交断链，
尚未用文档范围锚点覆盖同一 TSF Context 中的鼠标光标移动。

普通候选组合保持活动时，`Ctrl+Delete` 会进入候选窗内的两阶段忘记模式；此时
数字键精确选择当前页候选，`-` / `+` 与 PageUp / PageDown 仍可翻页，Esc 或
Backspace 取消。进入模式本身不写文件，空格、字母和标点也不会误提交候选。固定
别名或保护前缀会显示“固定词”，只有公共词典、没有长期或本轮个人证据的候选会
显示“没有个人排序”，两者都不产生动作。成功忘记后当前组合立即按新快照重排，
候选窗短暂显示“已忘记 · 退格撤销”；在组合仍活动时紧接 Backspace 会追加恢复
动作，并恢复刚才移除的本轮置顶。焦点离开、输入法停用或继续普通输入都会关闭
这次临时撤销窗口。

## 分级负反馈设计（最窄上下文层已启用）

现有 `Ctrl+Delete` 表达的是最窄的“精确 `code + text` 不再使用个人证据”，不应
同时冒充降权、临时隐藏、上下文偏好或全局禁词。后续交互先采用带语义刻度的分级
控制，而不是把一个连续滑块的任意小数直接写进排序模型：

1. **撤销刚才学习**：只撤回尚未确认的本次选择，现有 Backspace 事务继续承担；
2. **本轮靠后**：只在当前文本服务会话中降低该候选，不写磁盘；
3. **个人降权**：为精确 `code + text` 追加有界负证据，使用饱和曲线限制影响，
   不得越过显式别名或项目保护前缀；
4. **此处避开**：负证据还绑定经过明确授权的左侧上下文身份，只影响相同上下文；
5. **精确屏蔽**：沿用当前可恢复 suppression，只屏蔽这一组 `code + text`。

“无论什么编码都禁用这段文字”属于更宽的全局动作，首版不提供。若以后加入，必须
使用独立确认，列明影响范围，并与精确屏蔽使用不同 schema；不能因一次误选连带隐藏
同字、同音、尾简或其他编码下的正常候选。

候选上的直接操作可在不抢焦点的弹层中显示一条具有上述五个固定停靠点的轨道。
拖动时只在内存副本上预览新名次，松手后仍需一次“应用”；Esc、点击外部或关闭组合
全部放弃预览。预览应让受影响候选与相邻项做一次 90～140 ms 的位置过渡，减少名次
突跳，但不循环闪烁、不修改整体透明度；Windows“减少动画”、高对比度或屏幕阅读器
环境直接切成瞬时更新。动效只解释已经算出的顺序，绝不延迟按键处理或决定模型权重。

上下文排序和遗忘保持两条证据通道。以同码“把 / 吧”为例，固定公开候选池可使用
已确认的左侧词或短语 bigram/trigram，在有界分数帽内重排；上下文负证据只表示“在
这个左侧环境避开某项”，不能推广成全局语言事实。真正的右侧未来文字在候选出现时
尚不存在，因此不能声称实时“前瞻”；后续文字到来后可以作为下一次预测的训练证据，
但不会倒推刚才选择时不存在的信息。读取宿主光标右侧既有文字属于更宽的私人上下文
权限，首版不做。

当前 TSF 首版已经实现其中最窄的正反内存层：只把输入法自身刚提交的上一候选作为
左侧身份，只从跨过撤销边界的明确选择学习，并按精确当前码重排既有 Top-12 池中的
至多一项。选择更后候选时，只对被越过的首个未保护候选记一次反证；每次反证只抵消
一格同身份正证，正反两边共用待确认与立即 Backspace 撤销事务。它不读取宿主文档
前后文；标点、原码、宿主按键、焦点或模式变化都会清空左侧锚点。证据表固定为
2048 项，正证与反证各封顶四次，停用即清空。精确 suppression 和保护前缀仍优先；
这一内存层没有持久 schema，也不能冒充已经验证的语言模型。只有仍有正支持、
未被 suppression 遮住且保有精确个人证据的上下文项，才把当前候选搜索从首屏扩到
Top-12；已经失效的记忆不会继续增加普通按键更新的解码深度。

所有持久负证据仍使用当前 Windows 用户 DPAPI、不可变动作和显式恢复。实现顺序为：
内存左侧正证据、温和反证与确定性排序代数已经完成；下一步先独立评测，再研究显式
“本轮靠后”和持久个人降权。上下文层只有在独立后续会话证明优于无上下文基线后才
落盘。鼠标右键或触控长按只是入口，键盘的 `Ctrl+Delete` 路径必须始终可完成同一
精确操作。

在线 V1 位于 `.local/tsf-alpha/user-data/personal-ranking`。默认累计 8 次明确
选择后刷新，每个批次最多 32 条；文件创建后不改写，多个宿主各自追加，加载时
按批次时间和进程序列合并。同码候选先比较封顶为四次的确认支持，支持相同才由
最近确认打破平局；因此一个已有重复支持的候选不会被一次偶然选择替换，而新偏好
最多重复四次便能与任意旧累计量竞争。最多接受 4096 个批次文件，内存快照最多
保留 8192 个 `code + text` 身份。固定别名和项目保护前缀不会被个人排序越过。

宿主会保留已经验证的不可变包身份。再次激活而目录没有变化时只核对文件名集合，
有新增包时只解密并应用严格晚于现有顺序的部分；发现包被移走或倒序补入时完整
重建，新增包异常时保留最后已知可用快照。这既让 `clear` 后的活动宿主丢弃旧缓存，
也避免每次切换输入法都重复解密全部历史。

冷启动使用另一层不可变加密检查点。没有检查点且批次达到 64 时，新宿主在完成
严格全量加载后写一个覆盖集合明确的检查点；此后覆盖批次翻倍才再写一个。文件名
只暴露覆盖数量和密文批次名集合的摘要，快照、`code + text`、计数、完整覆盖集合
和排序代数都在 DPAPI 密文中。加载器选择覆盖最多且仍是当前批次子集的检查点，
再重放尾部；若发现尾部顺序早于检查点则放弃检查点并走完整规范排序。检查点不
删除原始批次，因此旧 DLL 和同时写入的宿主仍然安全；日志回收仍是尚未实现的
独立维护事务。

固定本机 release 合成探针在 64 个批次、512 个不同身份下，一次完整加载约
`39.560 ms`，检查点冷启动约 `2.538 ms`，无变化刷新约 `0.333 ms`，新增一个
批次约 `1.114 ms`。这些数字只用于验证增长阶数，不是跨设备性能承诺。

管理工具的 `status` 只显示批次、选择、排序条目、忘记动作与当前忘记条目数，不
显示文字。`forget` 与 `restore` 启动后才逐行读取编码和候选文字，不接受私人
命令行参数，因此不会把正文放进 shell 历史。`clear` 只归档正向排序目录，要求
单独确认，并把目录移到同级可恢复归档而非直接删除：

```powershell
cargo run --release --bin personalctl -- status `
  --root .local/tsf-alpha/user-data/personal-ranking

cargo run --release --bin personalctl -- forget `
  --root .local/tsf-alpha/user-data/personal-ranking

cargo run --release --bin personalctl -- restore `
  --root .local/tsf-alpha/user-data/personal-ranking

cargo run --release --bin personalctl -- clear `
  --root .local/tsf-alpha/user-data/personal-ranking `
  --confirm-clear-personal-ranking
```

候选窗发出的忘记或恢复动作在当前宿主立即生效；`personalctl` 从外部追加的动作
会在输入法下次激活时由活动宿主刷新。清空前应先停用输入法或关闭相关宿主；否则
仍持有未刷新选择的旧宿主可能稍后重新建立正向目录。归档恢复目前是手工运维动作，
不冒充自动回退。

公开项目、论文证据以及提交确认、遗忘和运行架构的分层方案见
[候选排序与个人学习研究备忘](adaptive-personalization-research.md)。

## 后续离线模型的目标与非目标

个人模型用于保存已经通过因果回放提取的个人词频或有序词对，使后续解码
可以复用历史证据，而不必每次重放全部原始会话。

后续离线模型第一版只做：

- 当前 Windows 用户本地使用；
- DPAPI 当前用户加密；
- 由操作者点名的、已经正常结束的会话显式训练；
- 固定候选池内的有界重排；
- 可查看脱敏状态、可回退、可清空。

后续离线模型第一版不做：

- 保存原始聊天、按键、组合串、文档差分或候选列表；
- 云同步、联网提交或跨设备迁移；
- 记录过程中实时修改模型；
- 根据当前正在评测的答案边预测边持久化；
- 自动寻找“最新会话”、扫描私人目录或接受任意输出路径；
- 把 `daily/course/theme` 混成无法区分来源的准确率结论。

## 进入离线版本模型之前的证据门槛

会话 A 可以作为历史，会话 B 只能作为后续评测。若实现是根据 B 的结果
设计的，则至少等待会话 C 才能验证该实现。任何会话不得同时出现在历史组
和评测组。

候选方案必须在独立后续会话中满足：

1. 规范完整码 Top-1、Top-5 与 Top-10 不下降；
2. 简写相对同一套完整码基线的退化减少，或确实救回 Top-10 候选；
3. 词对方案相对相同词频底座提供新增收益，而不是重复归因；
4. 没有扩大候选池、提升上限或使用未来答案掩盖退化；
5. 采集完整性和评测分母足以解释结果。

若只有词频通过，只保存词频；若词对提供独立收益，再保存词对。两者都未
通过时不创建持久模型。

## 明文载荷

拟议的 `ziranma-personal-model-v1` 明文载荷只包含：

- 格式版本与模型种类（词频或词频加有序词对）；
- 解码兼容指纹：自然码映射版本、公开词典快照、候选池深度和提升策略；
- 已消费的完整会话号，用于拒绝重复训练；
- 词语及其非零计数；
- 可选的有序词对及其非零计数；
- 创建、更新和成功训练的聚合计数。

词语、词对、来源会话号都属于私人数据，必须位于 DPAPI 密文内部。外层只
暴露固定格式标识、保护方式和密文长度。文件名使用不含正文的模型别名。

不会写入模型：

- 原始事件与逐键时序；
- 组合拼音和实际按键串；
- 文档位置、删除文字和修改轨迹；
- 训练时的候选名次或整句文本；
- 当前会话的活动文档跨度。

训练完整会话时，活动跨度只在内存中用于撤销被后续编辑覆盖的贡献；会话
结束后只保留最终聚合计数，跨度不会跨会话持久化。

## 文件与更新方式

模型仅允许位于 Git 已忽略的固定目录：

```text
models/private/personal/<模型别名>/slots.v1
models/private/personal/<模型别名>/model-<代号>.zpm
```

模型别名只能包含有界的 ASCII 字母、数字和连字符。命令不接受绝对路径、
父目录或符号链接。

每个 `.zpm` 都是创建后不再改写的 DPAPI 密文版本。`slots.v1` 只保存
`current/candidate/previous` 三个安全文件名，不含词语、来源会话或模型
计数；它沿用记录器控制器已经验证的同目录临时文件、刷新和原子替换方式。

每次训练或更新遵循：

1. 从槽位状态解析并严格校验 current；
2. 在内存副本上完整训练点名会话；
3. 序列化后立即 DPAPI 加密；
4. 以新代号创建不可变密文文件并刷新；
5. 原子更新槽位状态，只把新版本登记为 candidate；
6. 独立评测通过后，显式 promote 才把旧 current 放入 previous；
7. 任一步失败都保留原 current，未登记的完整密文至多成为可安全忽略的
   孤立候选，不会被隐式加载。

磁盘上不出现明文临时文件。解析和序列化缓冲区处理后尽力覆零，但不宣称
普通进程内存具有安全隔离或可验证的完整清除。

## 显式命令生命周期

命令名称是设计草案，实施时仍需逐项测试：

```text
personal-lab model create    # 从点名的已结束历史会话创建候选模型
personal-lab model evaluate  # 只读评测；绝不更新模型
personal-lab model update    # 显式吸收已经完成评测的会话
personal-lab model status    # 只显示版本、种类、计数和兼容状态
personal-lab model promote   # 评测通过后 candidate → current
personal-lab model rollback  # current 与 previous 原子互换
personal-lab model delete    # 单独确认后删除一个固定别名
```

`create` 和 `update` 必须带独立的私人学习确认开关，并拒绝尚未正常结束的
会话。`evaluate` 永远只读，评测会话不会因命令成功而自动加入模型。状态和
错误输出不显示词语、词对、会话号列表或本地路径。

删除是唯一不可由模型槽位自行回退的操作；实现时必须先解析并回显固定模型
别名，再要求单独确认。第一版不提供“清理所有模型”或目录级删除。

## 与持续记录器的关系

持续记录器继续只负责产生加密事件段，不加载、写入或锁定个人模型。这样
记录失败不会损坏模型，模型升级也不会干扰采集高可用性。

持久模型通过独立离线命令更新。只有离线方案在多个独立会话中稳定后，才
讨论由控制器在会话正常停止后提示可训练更新；即使进入该阶段，也不默认
执行，更不在输入过程中实时学习。

## 接受、回退与停止

一个模型版本必须保留：兼容指纹、脱敏计数、来源去重证据和上一版本槽位。
新版本先成为 candidate，并在独立会话上相对 current 只读评测；通过后才
promote。发现完整码退化、格式不兼容或计数异常时不提升 candidate，已经
提升后发现运行问题则回退 previous。

以下情况停止扩展模型：

- 词对相对词频没有新增收益；
- 历史重复证据不足；
- 改善只发生在参与设计的会话；
- 需要更大提升幅度或更深候选池才能制造收益；
- 需要保存原始聊天才能解释模型状态。

在下一次独立评测完成前，不决定第一版究竟保存“仅词频”还是“词频加
词对”，也不实现自动更新。
