# 当前解码设计

## 问题定义

输入是一串非空的小写英文字母，表示程序实际收到的自然码按键。词典中
的每个条目保存：

```text
中文文本、空格分隔的无声调拼音、合成相对权重
```

codec 把每个拼音音节变成标准两键自然码，同时保留音节边界。解码器
输出至多 Top-K 个候选；每个候选必须带有：

- 完整标准编码；
- 本次匹配采用的可变长编码；
- 哪些音节只使用了一键简拼；
- 输入与候选编码之间的纠错操作；
- 候选来自词典还是显式未解析输入；
- 词频分、简拼代价、纠错代价、未解析代价和总分。

本项目的规范 codec 以实际自然码输入为准：`sh → u`、`ch → i`、
`uang → d`、韵母 `an → j`，所以 `shuang → ud`、`chan → ij`；
零声母两字母音节保留原拼音，所以 `an → an`，不是 `aj`。Rime 可
派生的兼容别名不作为规范输出。

目标不是模拟真实输入法准确率，而是建立确定、可测试、可解释的联合
解码基线。

## 宿主无关的组合状态

终端 `typing-lab` 已不再独占组合协议。`CompositionSession` 保存当前
双拼串、候选页、换序状态和 Tab 笔画状态，通过 `CompositionInput`
接收语义按键，通过 `CompositionEffect` 请求候选确认、翻页或单字查询。

已提交文字不属于该状态：终端宿主只为显示累积它，未来 TSF 宿主则
把它交给当前编辑框。候选解码、Windows 编辑会话、候选窗口和私人存储
也继续位于状态机外。它是[自有 Windows TSF Alpha](tsf-alpha.md)的第一阶段，
不代表仓库已安装输入法。

## 拼写隐变量

对于一个含 `n` 个音节的词，每个音节可以采用：

- 两键标准自然码；
- 标准码的第一键，作为一键简拼。

因此一个词有至多 `2^n` 个拼写解释，长度在 `n` 到 `2n` 之间。Decoder
不会构建这些字符串。它只把标准两键音节序列写入 trie 一次；`2^n`
种解释由查询时的一键/两键转移隐式表示。解析器仍限制单个词条最多 12
个音节，因为合成评测器需要穷举拼写作为测试样例和参照实现，而不是
因为生产索引需要展开它们。

这段描述的是当前搜索器能够表示的**自由混合压力测试**，不是已经验证
可用的输入协议。[形式化审计](abbreviation-feasibility.md)证明它不唯一
可解码：公开码本的 410/410 个完整码都能同时切成两个一键简拼，重复
`a` 的边界解释按斐波那契数增长。动态规划只压缩计算，不能补回丢失的
信息。后续产品假设必须改用歧义受控的快捷码或锚定简拼规则。

## 连续组合候选栏

当前交互主线不要求逐词按空格。一个多音节词可以先输入完整首音节，
再用各后续音节的首键；多个词的按键直接相连，由同一个句子 lattice
推断词界。固定公开词典中的 `mafmkm` 已能自动切为：

```text
maf | mkm → 麻烦 | 猫猫
```

普通句子排序仍保留零错误路径优先，避免高频纠错候选破坏干净输入。
同时，k-best 状态、词条终点和句子转移会分别保留普通候选与“完整首
音节 + 连续尾部简写”内部的一次相邻颠倒。
因此 `mafkmm` 可以在恢复栏显示“麻烦猫猫”，而主候选的稳定顺序不变。
这是一种候选多样性策略，不是新的输入模式或硬编码词界。

## 拼写 trie 与联合错误状态

trie 的每条边标记一个标准两键音节，终止节点只保存词条编号。查询一个
标准编码假设时，一条音节边允许两种转移：

- 输入接下来的两键等于完整音节码：消费两键；
- 输入接下来的一键等于音节码首键：消费一键，并记录当前音节为简拼。

到达终止节点后，遍历路径才组装出完整的 `Spelling` 解释。完整转移总是
先于简拼转移，词典边保持稳定插入顺序，最终再按统一候选规则排序。

每条拼写路径同时携带一组很小的按键对齐状态：

- 已消费到的实际输入位置；
- 是否已经使用全局一次错误预算；
- 是否暂存了颠倒中的第一枚预期键。

消费一枚预期键时，状态可以原样前进，也可以在预算未使用时执行邻键
替换、跳过一枚预期键（漏键）或先跳过一枚实际键（多按）。颠倒会暂存
当前预期键，并由下一枚预期键完成，因此可以自然跨越音节边界。相同状态
会立即去重。一次错误的状态空间至多是精确位置、三种编辑距离偏移和一个
待完成颠倒，共 5 个状态；实现用固定容量值类型承载状态和终点长度，避免
每条 trie 边的堆分配。超过上限会显式失败，而不是静默丢状态。同一扫描
内，排序规范化后的状态集只在首次出现时用哈希表分配整数 ID；逐键转移
随后通过 `状态 ID × 26` 的稠密表复用。缓存不跨输入或错误模式共享。

到达词条终点时，只有完整消费实际输入的状态能够产出候选；尚未使用错误
预算的状态还可以接受末尾一次多按。最终再用确定性对齐规则规范化纠错
位置，保证重复键情况下仍输出与旧实现相同的说明。

生产查询不再生成整串错误假设。测试中仍保留上一版假设生成器和逐词
穷举器作为两套独立参照；超过 1,000 个唯一的干净、混合简拼、邻键、
颠倒、漏键及多按输入会逐候选比较解释和排序。

当前 50 词演示词典的结构统计为：

```text
节点                 96
音节边               95
词条终点             50
隐式全码/简拼拼写   212
```

结构测试要求每个词条只出现为一个终点，并检查节点数小于隐式拼写数；
`index-stats` 命令让这项约束也能在命令行审查。

## 错误通道

对实际输入 `x` 和某个可变长候选编码 `c`，只接受以下关系：

1. `x == c`；
2. 长度相同且只有一个位置不同，两个键在手工 QWERTY 邻接表中相邻；
3. 长度相同且只有两个相邻位置不同，交换后恰好相同；
4. `x` 比 `c` 少一个键，插回该键后恰好相同；
5. `x` 比 `c` 多一个键，删除该键后恰好相同。

简拼选择和一次错误可以同时出现。暂不接受两次错误、任意替换或概率化
键距。

## 评分

```text
词频分 = ln(合成相对权重)
简拼代价 = 简拼音节数 × 0.85
总分 = 词频分 - 简拼代价 - 纠错代价 - 未解析代价
```

默认纠错代价：

```text
原样匹配        0.00
相邻按键颠倒    2.25
QWERTY 邻键替换 2.75
漏键            3.00
多按            3.00
逐键未解析      8.00
```

这些数字只是明确、可修改的研究假设，不是从用户数据或公开语料估计的
概率。总分相同时依次偏好更少简拼、更低类别序号的纠错操作和稳定的
文本、编码顺序。未解析候选没有词频证据，其词频分和语言分记为零，再
单独扣除未解析代价，不能伪装成低频词。

每个词条可能有多个能够解释输入的拼写路径。解码器只保留其中得分最高
且稳定排序的路径，再与其他词条竞争 Top-K。

## 假阳性策略

程序只返回候选，不自动上屏。完整原样解释和容错解释都保留分数拆解。
高权重纠错候选可能超过低权重原样候选，这正是评测需要观察的现象，
不能据此静默修改输入。

当前合成评测会报告干净输入首选是否仍然无需纠错。未来使用更大公开
词典后，还需要校准“最佳纠错候选与最佳原样候选的分差”，再讨论任何
主动提升策略。

句子层采用更严格的保守约束，依次比较未解析键数、是否使用纠错预算，
最后才比较语言和局部代价。因此任何完全由词典覆盖的路径（包括使用
一次明确纠错的路径）都排在含未解析键的路径之前；在同为完整覆盖时，
零纠错路径又排在纠错路径之前。

## 多词无界搜索

`decode_sentence` 在整个输入串上使用动态规划。状态由输入键位置和全局
错误预算组成；每条转移消费一个词的某个全码、简拼混合解释。未使用
错误的状态可以选择原样转移或消耗唯一一次错误，已使用错误的状态只能
继续原样匹配。除此之外，每个活跃位置都有一条消费一键的未解析边；
它输出 `〔x〕`，不声称拼音或中文，也不消耗纠错预算。

每个存在活跃路径的输入位置只启动一次 trie 前缀扫描。扫描从该词界沿
剩余输入前进，遇到词条终点便输出一条带终止位置的候选边，因此一次
遍历能够发现所有可能词长。若未使用错误的路径存在，这次扫描同时产出
零错误和一次错误边；已使用错误的路径复用其中的零错误边。只有该位置
不存在未用错误路径时，才执行更窄的纯精确扫描。

同一词条、同一终点的零错误边和纠错边会先按错误层分开保存。未使用
错误的路径仍按原有候选规则选择两者中的最佳解释，已使用错误的路径则
一定能取到零错误边；这避免了高简拼代价下较高分的纠错解释把合法精确
边遮掉。

逐键未解析边始终存在，而不只在 trie 完全没有出边时补上。这样即使
当前位置有一条词边但它会在后面走入死路，整句仍能继续。候选排序先
最小化未解析键数，所以这些边不会压过任何完整词典覆盖。当前使用逐键
标记是为了让分段唯一、解释简单；相邻标记的显示合并留给后续界面层。

为了让不同词数的路径可以比较，句子层把每个词的合成权重归一化为一元
词概率。若前面存在一个词且加载了 bigram 模型，则使用：

```text
unigram = ln(词权重 / 词典总权重)
bigram  = ln P(当前词 | 前词)
语言分  = 0.35 × unigram + 0.65 × bigram
词的句子分 = 语言分 - 简拼代价 - 纠错代价
```

首词或未加载 bigram 时只使用 unigram。bigram 采用 add-0.5 平滑，
语料、共现次数、前词总次数和插值结果都可以审查。未解析边的语言分
为零，只扣除每键 8.00 的显式代价；它还会清空 bigram 前词状态，避免
跨过未知输入捏造一个并不存在的相邻词关系。

归一化 unigram 避免直接相加正的 `ln(词权重)` 所造成的“拆成越多词
得分越高”。转移从流式 trie 前缀扫描产生，不遍历全部词条，也不再按
每个可能片段长度重复查询。

未加载 bigram 时，边的文本不会进入下一状态。解码器因此在每个位置
先为每条终点拼写路径保存一份消费长度、`Spelling` 和 `Correction`；
节点词条只以 `(路径编号, 词条编号, 身份编号, 分数)` 的标量索引展开，
不重复克隆解释。索引记录复现结构去重与错误层折叠，再分别对可达错误层
按完整子状态保留至多 K 个唯一前缀。组内所有边拥有完全相同的后缀集合，
所以第 K 名以下的边不可能进入最终 Top-K；只有保留项才物化包含中文、
拼音和完整分数的候选对象。这是把后面的同未来状态上界提前应用，不是
beam。词条结构身份仍严格等价于 `(文本, 标准码)`，即使调用方绕过
解析器直接传入跨路径重复词条也不改变行为。
加载 bigram 时当前词文本会成为下一状态，代码明确跳过这层提前缩减。

无 bigram 的 Top-K 扫描还使用节点子树上界。每个节点在索引建成后记录
子树最高词频及到终点的最短/最长音节数，子树乐观分为：

```text
ln(子树最高词频) - 当前已经使用的简拼数 × 简拼代价
```

未来简拼与纠错代价均非负，所以任何后代都不可能超过这个分数。一次
纯精确预扫先完整记录 `(规范词条身份, 终点)` 的最佳精确解释；这使代码
能够证明某条已发现纠错解释会不会在后面被精确解释跨错误层替换。阈值
分成三组独立维护：未用错误前缀产生的精确边、同一前缀产生的纠错边，
以及已用错误前缀还能使用的精确边。子树上界必须严格低于所有可能终点
和所有相关组的第 K 个稳定文本才会剪枝；等分保留。预扫和剪枝只属于
unigram sentence Top-K，word 查询、不限 K 的测试参照和 bigram 模式
仍走完整遍历。

每个终点节点的词条按频率非增顺序保存。同一拼写路径上的简拼与纠错
代价相同，因此后续词条的总分也不会回升。精确与纠错解释会按规范词条
身份跨错误层竞争，所以停止条件不能只检查候选当前所在的组：词条分数
必须严格低于未用错误前缀的精确、纠错两个阈值；精确词条若还服务于
已用错误前缀，也必须低于第三个精确阈值。只有全部成立才整段停止，
等分继续展开。这个终点上界与子树上界共享同一证明边界和禁用条件。

缩减后的 lattice 使用记忆化 k-best 动态规划。状态为：

```text
(输入位置, 是否已用错误, 前一个词)
```

在当前一阶语言模型下，同一状态的所有前缀拥有完全相同的未来选择和
未来增量分。解码器为每个状态合并全部出边与子状态 Top-K，按句子规则
（未解析键数、错误层、总分）排序、按最终文本去重后只保留 K 条，再
缓存结果。未解析键数和分数都沿路径相加，不会改变未来状态，因此无需
扩张缓存键。根状态的结果因此是
当前固定 lattice 上的 Top-K 唯一文本，不需要跨前词状态的经验 beam。
未加载 bigram 时前词不会进入缓存键，从而共享更多后缀结果。

## 数据和隐私

`tests/fixtures/public/` 只能包含公开、人工构造或合成内容。演示频率
不是语料统计。`data/public/rime-pinyin-simp/` 是固定到明确提交的
Apache-2.0 上游快照；许可证、作者、来源、SHA-256 和运行时转换统计
必须与数据一起保留。`.gitattributes` 禁止跨平台换行转换，以便快照
哈希可复核。

真实输入、按键时间戳、个人词典和衍生模型不进入 Git。当前版本只有
一个必须手动 `--arm` 的 Codex 单应用兼容性探针：默认不捕获按键、不
显示文字、没有磁盘输出或网络；它不属于解码器生产路径。只有显式脱敏
摘要或通过独立知情开关的私人胶囊能在 STOP 时一次性写入。每次提交同时
保留“最终拼音预编辑 → 上屏文字”和“组合前文档 → 提交后文档”两份单段
差分，使直接选中替换不丢失被替换原文。探针原子事件之上的纠错候选
归并同样只在内存工作，要求同位置、非歧义和调用者给出的时间边界，
且不把删补或替换行为宣称为用户意图。探针只有同时收到
`--preview-candidates` 和显式正数 `--candidate-gap-ms` 才运行这一层；
默认输出继续隐藏文字、拼音和具体按键值，READY 会重置单调计时与候选
状态。停止时只输出事件数、证据完整性、候选分类和删补间隔的流式聚合；
不保留文字清单，不把候选数命名为错误率。可选 `--save-summary` 只把
这份聚合以固定 v1 JSON 原子新建到 Git 已忽略的
`data/private/session-summaries/`；路径必须显式、目标必须不存在，
候选明细始终不落盘。另有一个更高权限的私人事件胶囊实验：只有显式
`--save-capsule`、`--capture-keys`、新 `.zic` 路径和
`--allow-private-plaintext` 同时出现时，才在 STOP 后一次性保存 READY
之后的有界原子事件。格式明确标记 `contains_private_text=true` 与
`encryption=none`，不保存完整输入框快照，也不进行流式磁盘日志。离线
回放只能逐个点名胶囊，以公开锁定词典分别统计真实按键、规范全码和三种
整段受限简写；若规范全码的目标路径提供精确、非简拼的公开词典分段，
再另外统计逐词末音节简写、保留单音节词的保守词尾简写与逐词首音节
锚定。显式给出连续窗口间隔时，
还可以合并同一位置连续追加、无修订的相邻提交，模拟移除每词选词键后的
整段输入；不做滑动窗口或跨修订猜测。窗口简写必须和同一个规范完整码
窗口配对，分别报告名次改善、持平、下降、Top-10 掉出/恢复与相同分母的
按键节省；无可缩短音节按原码持平处理。终端结果不显示文字，显式
`--compact` 只缩减显示字段，不改变回放内容。
另有两个互斥的显式公开上下文对照：`--public-context` 只从固定 UD
train 训练现有 word bigram，`--public-character-context` 从同一批公开
句子训练 character bigram，并用候选的平均字符转移分数排序。两者都只
重排每条码冻结的 unigram Top-50 候选池，不运行更宽的联合搜索，也不能
制造新路径。私人目标仅在重排后评分；只有两套完整码基线均可见时才比较
简写相对退化，避免把上下文基线丢失误报为改善。字符路线是最后一个公开
基线。两条冻结池公开重排均只保留为可复现诊断，不进入产品排序主线；
公开上下文路线到此封口，不继续堆更复杂的公开模型。

公开路线封口后，`--personal-cache` 提供第一个纯本地因果学习基线。它只
在内存中统计由规范全码精确目标路径证明的词语，连续窗口必须先预测再
学习；跨胶囊顺序完全由操作者逐个给出的 `--input` 决定。重排仍限制在
冻结 unigram Top-50 内，每个候选的历史提升键封顶三位，没有历史时保持
原顺序。缓存无文字访问器、序列化或自动保存。词次只积累正证据，但文档
位置不会跨会话沿用：当前胶囊另有内存文档跨度账本，确定位置的
删除、替换和局部重叠会保守撤销整个受影响提交的词次，前方编辑会平移
后续跨度；新胶囊清空跨度但保留历史计数。歧义位置与未关联修订单列，不
猜测性扣除。它仍不是可保存的个人模型。
当前将其定位为有界、可撤销的个人词频安全底座，而不是长句简写解法；
三位提升上限保持冻结，也不进入持久化。下一条个人上下文实验若启动，
必须使用有序词对或短语证据，并相对同一套个人完整码基线单独证明收益。
`--personal-pair-cache` 实现了第一个有序对照：它保留相同词频证据，额外
统计此前连续窗口或单次多词提交中的相邻词对。窗口仍先预测再整体学习；
词对序列有独立跨度，局部重叠编辑会撤销整条序列的词对。词频与词对合计
提升键仍封顶三位。报告使用独立模式标签，必须和词频模式对照，不能把
共同底座的改善重复归因给词对。
为了避免同一会话的稀疏证据被重复解释，个人模式另有显式
`--history-input` / `--input` 分组。历史组按给定顺序只训练内存状态，
其命中与窗口不进入最终报告；评测组随后才计分。评测开始点冻结脱敏的
历史 token/type/repeated 证据量，其中 repeated 等于 token 减 type。
没有历史重复词对时停止增加更长 n-gram，等待真实后续会话。

任何持久化个人模型都必须晚于上述独立历史/评测门槛。拟议格式只保存
DPAPI 加密的最终词频、可选有序词对、兼容指纹与来源去重证据，不保存
原始事件、按键或聊天正文；记录器与模型写入继续分离。完整生命周期、
原子轮换和回退边界见[加密个人模型设计](personal-model.md)。

## 大词典规模探针

Rime `pinyin-simp` 固定快照包含 65,125 行。导入器不改写源文件，而是
报告每一个兼容决定：

```text
导入词条             65,116
零权重升至 1          1,714
不支持拼音                8
超长词条                  0
重复词条                  1
trie 节点             46,596
trie 音节边           46,595
词条终点             65,116
非空终点节点         39,027
单节点最大词条          312
隐式拼写            335,428
```

导入统计由完整快照测试锁定。公开快照只驱动显式 `public-*` 命令，不
替换 50 词的穷举回归基线；否则全路径参照测试会失去可运行性。

release benchmark 使用 codec 生成的固定全码/简拼/错误查询，一次预热
后重复采样，分别报告单词、短句和长句延迟分布，并通过结果校验和避免
整段工作被优化掉。当前本机三轮结果约为：

```text
单词 median       0.9 ms
短句 median       8.5 ms
长句 median      20.4 ms
```

绝对数字不是跨机器基准；更长和更开放的输入分布仍需单独测量。

排名器现会把转移按完整子状态分组。同一子状态拥有完全相同的后缀集合；
按最终句子规则去掉重复前缀文本后，组内第 K 名以下的边不可能进入
Top-K，因为前 K 个更好前缀都能与同一个后缀组合。这是精确上界而不是
beam，并继续由不裁剪的全路径 oracle 逐候选验证。

首先，转移去重和错误层折叠以哈希索引替代随候选数增长的线性扫描；
短句/长句中位数从约 `1.21 s / 2.56 s` 降到
`128.9 / 251.1 ms`。随后，提前精确缩减、轻量 trie 终点、固定容量
状态、逐键转移复用、共享终点解释、子树最高词频上界和终点词频上界
逐层减少正式工作；结果校验和不变，不裁剪全路径 oracle 继续逐候选
核对。

当前分型恢复前沿在普通 Top-K 之外，还分别保留锚定颠倒所需的终点、
转移和 k-best 路径。固定工作负载中，短句/长句总路径访问为
10,760 / 11,622；536 / 594 条精确预扫路径核对 6,009 / 7,187 个
词条，并剪掉 19,154 / 18,827 个子树。对齐工作为
`5,623 实查 + 859,991 复用` / `5,641 + 798,787`。终点拼写路径为
7,555 / 8,538，正式展开 2,319 / 2,459 个词条并跳过
70,455 / 68,633 个词条。逻辑、物化、最终 lattice 边分别为
`2,198 → 575 → 564` / `2,378 → 604 → 594`；排名转移为
751 / 806，路径组合为 7,751 / 10,367。

分型保留使工作量高于只保留普通前沿的旧记录，但避免为寻找少数恢复
证据而统一扩大所有候选类型。跨 64 个独立句的公开颠倒短语恢复栏当前
为 40/64 Top-10。固定工作负载仍满足当前预算；下一阶段不再为追逐
本机毫秒数牺牲研究可见性，重点转向同长度排序和真实选择成本。

## 已知限制

- 50 词演示词典只用于可穷举回归；6.5 万词快照的 train-only 词级
  bigram 很稀疏，尚不足以改善公开双路径诊断；
- train-only 字级 bigram 受输出字数偏置明显影响，等长文本上的区分
  仍不足；
- codec 还没有完整合法普通话音节表；
- demo bigram 只来自很小的人工合成语料；公开 train-only 词级 bigram
  虽来自自然语料，覆盖仍不足；
- QWERTY 邻接表是手工离散表，不含键距、时间或个人手型；
- 分数没有校准为概率；
- 词典外回退只逐键原样保留，不推断未知词的拼音、词界或中文；
- 单词级 `decode` 仍是封闭词典查询，未解析回退只属于句子解码；
- 一次多按纠错若能完整覆盖输入，会按保守规则排在未解析回退之前；
- 词外探针有 3/12 被其他词典路径完整覆盖，当前拒识排序过于绝对；
- 固定大词典工作负载已进入十毫秒级，但尚不能代表任意长输入或设备。

## 下一项算法跃迁

大词典、词外探针、长句用例和重复采样 benchmark 已把下一个问题定位
清楚。底层性能目标已经达到；下一项算法跃迁应重新建模“完整词典覆盖”
和“诚实未解析”的置信关系，使陌生词不会仅因能被若干简拼词拼接就
永远压过回退。先扩充与词典独立、许可明确的公开句子和词外评测，报告
正常句召回、首选拒识率与按键保留率，再校准词典路径和回退的分差。

只读校准层计算最佳完整路径相对全部逐键原样回退的每键分差，并扫描
0～8 的假想门槛，不参与真实候选排序。18/12 条人工小集曾让 `5.0`
看似能完全分开两类；固定 UD Chinese GSDSimp test 与 6.5 万词 Rime
的独立校准已经推翻这个结论。自然句完整码只有 4/64 Top-1 相符，相符
分差 `5.639～5.876`，60 个不符结果却覆盖 `4.601～6.231`；未收整词
完整码也只有 5/128 相符，而且其分差低至 `3.145`。两条全简拼轨道均
为 0 个相符 Top-1。固定阈值无法分开这些重叠分布。

固定 UD train 已建立第一个隔离的词级 bigram 基线，只在 test 上做
双路径诊断：自然句完整码的 60 个错误首选只有 1 个被公开答案路径
翻转，未收整词完整码仅 7/123，全简拼两轨均为 0。因此当前不把它接入
完整大词表搜索。公开答案路径由 Rime 分词直接构造，结构上必定可达；
但现行 Top-10 只召回自然句完整码 12/64、未收整词完整码 24/128，
全简拼两轨均为 0。字级 bigram 的累加分受文本长度主导：自然句完整码
35 个等长错误样本只以 18:17 偏好答案，未收整词完整码为 42:51；全
简拼按字符平均后虽出现信号，却不是可直接用于搜索的加和分数。

当前 test 已用于架构诊断，后续只把它当作持续 benchmark，不再作为
未见最终集。下一里程碑先不增加语言模型：比较显式快捷码白名单、
“完整音节锚定 + 连续尾部简拼”和显式简拼模式的状态规模、冲突规则与
净按键成本，先选出歧义至多多项式增长或有硬上限的协议。自由混合保留
为最坏情况回归，不进入近期产品路线。

第一轮对照现已落在[受限简写协议审计](protocol-audit.md)：显式全简在
held-out dev 只有 25/128 进入 Top-10，停止作为通用主线；fit-only
公开快捷短语对所选 dev 的精确覆盖为 0/128，说明白名单应服务于真实
重复表达而不是泛化预测。锚定尾简为 104/128。其 24 条失败中补词界
只救回 1 条；fit-only word bigram 又让完整码/尾简 Top-10 分别
`122→120` / `104→102`，两条分支均停止。116 条长词压力层中，“每词
最多省一键”和锚定尾简的 Top-10 同为 113；后者多省 149 键、少 4 个
首选。两条保留到真实操作成本对照，不由公开语料替用户决定。

协议冻结后，才在不触碰 held-out dev 的前提下继续用 fit 部分估计字符
上下文与输出字数先验；最终用尚未参与决策的官方 dev 或另一公开
holdout 确认。

未知模型无论怎样扩展都必须保留原始按键和来源说明，不能伪造确定中文。
当前紧凑 trie、联合对齐状态、流式 lattice、全路径枚举参照和解释结构
可以继续作为行为基线。
