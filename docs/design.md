# 第一阶段设计

## 问题定义

输入是一串非空的小写英文字母，表示程序实际收到的自然码双拼按键。
词典中的每个条目显式保存：

```text
中文文本、全拼、标准自然码按键、合成相对权重
```

程序输出至多 Top-K 个候选。每个候选必须带有标准编码、采用的纠错操作
和完整分数拆解。

第一阶段的目标不是模拟真实输入法准确率，而是建立一个确定、可测试、
可解释的基线。

## 支持的错误通道

对输入串 `x` 和某个词典编码 `c`，只接受以下三类关系：

1. `x == c`；
2. 长度相同且只有一个位置不同，两个键在本项目定义的 QWERTY 邻接表
   中相邻；
3. 长度相同且只有两个相邻位置不同，交换这两个输入键后恰好得到 `c`。

第三类允许跨越两个双拼音节的边界。例如“你好”的标准编码是 `nihk`，
`nhik` 会被解释为中间的 `i`、`h` 到达顺序颠倒。第一阶段没有通过
偶数位置强行限制交换边界。

暂不接受漏键、多键、非邻键替换、两次错误或简拼。

## 候选生成

演示词典很小，因此第一阶段对所有词条做穷举比较。这样实现容易审查，
也给将来的 trie、有限状态图或 beam search 提供行为基线。

一个词条只有在与输入满足上述关系之一时才生成候选。候选分数为：

```text
词频分 = ln(合成相对权重)
总分   = 词频分 - 纠错代价
```

默认代价：

```text
原样匹配        0.00
相邻按键颠倒    2.25
QWERTY 邻键替换 2.75
```

这些数字只是明确、可修改的基线假设，不是从用户数据或公开语料估计的
概率。总分相同时以中文文本和标准编码保证稳定排序。

## 交互和假阳性

程序只返回候选，不自动上屏。原样候选和纠错候选都保留完整解释。第一
阶段允许高权重的纠错候选在排序中超过低权重的原样候选，但不能据此
静默修改输入。

扩大公开评测集以后，需要单独测量：

- 干净输入的候选和首选变化；
- 各类合成错误的 Recall@1、Recall@5 和 Recall@10；
- 原样候选与最佳纠错候选的分数差；
- 词典规模扩大后的确定性延迟。

在这些数据出现以前，不设自动纠错阈值。

## 数据和隐私

`tests/fixtures/public/` 只能包含公开、人工构造或合成内容。演示频率不
代表真实语料统计。

真实输入、按键时间戳、个人词典和衍生模型不进入 Git。第一阶段不会
创建采集器，也不会写入输入日志。

## 已知限制

- 演示词典极小，无法说明真实准确率；
- 词典直接保存标准编码，尚无完整拼音转自然码 codec；
- 没有同音词上下文、词语切分或语言模型；
- QWERTY 邻接表是手工、离散的，不含键距和个人手型；
- 分数不是校准概率；
- 穷举搜索不面向生产规模。

## 后续顺序

1. 建立更大的公开合成评测集和指标报告；
2. 实现并验证完整自然码 codec；
3. 评估漏键和多键；
4. 再研究全码、简拼混输及无词界切分；
5. 算法稳定后接入 Rime；
6. 最后才评估 Windows TSF。
