# 当前解码设计

## 问题定义

输入是一串非空的小写英文字母，表示程序实际收到的自然码按键。词典中
的每个条目保存：

```text
中文文本、空格分隔的无声调拼音、合成相对权重
```

codec 把每个拼音音节变成标准两键自然码，同时保留音节边界。解码器
输出至多 Top-K 个候选；每个候选必须带有：

- 完整标准编码；
- 本次匹配采用的可变长编码；
- 哪些音节只使用了一键简拼；
- 输入与候选编码之间的纠错操作；
- 词频分、简拼代价、纠错代价和总分。

目标不是模拟真实输入法准确率，而是建立确定、可测试、可解释的联合
解码基线。

## 拼写隐变量

对于一个含 `n` 个音节的词，每个音节可以采用：

- 两键标准自然码；
- 标准码的第一键，作为一键简拼。

因此一个词有至多 `2^n` 个拼写解释，长度在 `n` 到 `2n` 之间。Decoder
不会构建这些字符串。它只把标准两键音节序列写入 trie 一次；`2^n`
种解释由查询时的一键/两键转移隐式表示。解析器仍限制单个词条最多 12
个音节，因为合成评测器需要穷举拼写作为测试样例和参照实现，而不是
因为生产索引需要展开它们。

## 拼写 trie 与联合错误状态

trie 的每条边标记一个标准两键音节，终止节点只保存词条编号。查询一个
标准编码假设时，一条音节边允许两种转移：

- 输入接下来的两键等于完整音节码：消费两键；
- 输入接下来的一键等于音节码首键：消费一键，并记录当前音节为简拼。

到达终止节点后，遍历路径才组装出完整的 `Spelling` 解释。完整转移总是
先于简拼转移，词典边保持稳定插入顺序，最终再按统一候选规则排序。

每条拼写路径同时携带一组很小的按键对齐状态：

- 已消费到的实际输入位置；
- 是否已经使用全局一次错误预算；
- 是否暂存了颠倒中的第一枚预期键。

消费一枚预期键时，状态可以原样前进，也可以在预算未使用时执行邻键
替换、跳过一枚预期键（漏键）或先跳过一枚实际键（多按）。颠倒会暂存
当前预期键，并由下一枚预期键完成，因此可以自然跨越音节边界。相同状态
会立即去重。

到达词条终点时，只有完整消费实际输入的状态能够产出候选；尚未使用错误
预算的状态还可以接受末尾一次多按。最终再用确定性对齐规则规范化纠错
位置，保证重复键情况下仍输出与旧实现相同的说明。

生产查询不再生成整串错误假设。测试中仍保留上一版假设生成器和逐词
穷举器作为两套独立参照；超过 1,000 个唯一的干净、混合简拼、邻键、
颠倒、漏键及多按输入会逐候选比较解释和排序。

当前 50 词演示词典的结构统计为：

```text
节点                 96
音节边               95
词条终点             50
隐式全码/简拼拼写   212
```

结构测试要求每个词条只出现为一个终点，并检查节点数小于隐式拼写数；
`index-stats` 命令让这项约束也能在命令行审查。

## 错误通道

对实际输入 `x` 和某个可变长候选编码 `c`，只接受以下关系：

1. `x == c`；
2. 长度相同且只有一个位置不同，两个键在手工 QWERTY 邻接表中相邻；
3. 长度相同且只有两个相邻位置不同，交换后恰好相同；
4. `x` 比 `c` 少一个键，插回该键后恰好相同；
5. `x` 比 `c` 多一个键，删除该键后恰好相同。

简拼选择和一次错误可以同时出现。暂不接受两次错误、任意替换或概率化
键距。

## 评分

```text
词频分 = ln(合成相对权重)
简拼代价 = 简拼音节数 × 0.85
总分 = 词频分 - 简拼代价 - 纠错代价
```

默认纠错代价：

```text
原样匹配        0.00
相邻按键颠倒    2.25
QWERTY 邻键替换 2.75
漏键            3.00
多按            3.00
```

这些数字只是明确、可修改的研究假设，不是从用户数据或公开语料估计的
概率。总分相同时依次偏好更少简拼、更低类别序号的纠错操作和稳定的
文本、编码顺序。

每个词条可能有多个能够解释输入的拼写路径。解码器只保留其中得分最高
且稳定排序的路径，再与其他词条竞争 Top-K。

## 假阳性策略

程序只返回候选，不自动上屏。完整原样解释和容错解释都保留分数拆解。
高权重纠错候选可能超过低权重原样候选，这正是评测需要观察的现象，
不能据此静默修改输入。

当前合成评测会报告干净输入首选是否仍然无需纠错。未来使用更大公开
词典后，还需要校准“最佳纠错候选与最佳原样候选的分差”，再讨论任何
主动提升策略。

句子层采用更严格的保守约束：只要存在完整覆盖输入的零纠错分词路径，
所有使用纠错预算的路径都排在它后面。语言概率只在相同纠错层级内排序。

## 多词无界搜索

`decode_sentence` 在整个输入串上使用动态规划。状态由输入键位置和全局
错误预算组成；每条转移消费一个词的某个全码、简拼混合解释。未使用
错误的状态可以选择原样转移或消耗唯一一次错误，已使用错误的状态只能
继续原样匹配。

每个存在活跃路径的输入位置只启动一次 trie 前缀扫描。扫描从该词界沿
剩余输入前进，遇到词条终点便输出一条带终止位置的候选边，因此一次
遍历能够发现所有可能词长。若未使用错误的路径存在，这次扫描同时产出
零错误和一次错误边；已使用错误的路径复用其中的零错误边。只有该位置
不存在未用错误路径时，才执行更窄的纯精确扫描。

同一词条、同一终点的零错误边和纠错边会先按错误层分开保存。未使用
错误的路径仍按原有候选规则选择两者中的最佳解释，已使用错误的路径则
一定能取到零错误边；这避免了高简拼代价下较高分的纠错解释把合法精确
边遮掉。

为了让不同词数的路径可以比较，句子层把每个词的合成权重归一化为一元
词概率。若前面存在一个词且加载了 bigram 模型，则使用：

```text
unigram = ln(词权重 / 词典总权重)
bigram  = ln P(当前词 | 前词)
语言分  = 0.35 × unigram + 0.65 × bigram
词的句子分 = 语言分 - 简拼代价 - 纠错代价
```

首词或未加载 bigram 时只使用 unigram。bigram 采用 add-0.5 平滑，
语料、共现次数、前词总次数和插值结果都可以审查。

归一化 unigram 避免直接相加正的 `ln(词权重)` 所造成的“拆成越多词
得分越高”。每个位置、错误状态和前词状态只保留确定性排序后的有界
beam。转移从流式 trie 前缀扫描产生，不遍历全部词条，也不再按每个
可能片段长度重复查询。

## 数据和隐私

`tests/fixtures/public/` 只能包含公开、人工构造或合成内容。演示频率
不是语料统计。

真实输入、按键时间戳、个人词典和衍生模型不进入 Git。当前版本没有
采集器，不写输入日志，也不联网。

## 已知限制

- 演示词典仅有 50 个词，无法说明真实准确率；
- codec 还没有完整合法普通话音节表；
- bigram 只来自很小的人工合成语料，不能代表真实中文；
- QWERTY 邻接表是手工离散表，不含键距、时间或个人手型；
- 分数没有校准为概率；
- 句子 beam 是有界近似，长而高度歧义的输入不保证精确全局 Top-K；
- 没有词典外回退，完整输入无法被词典覆盖时就不会产生句子候选。

## 下一项算法跃迁

单词层已经联合简拼和错误通道，句子层也由流式前缀扫描构建 lattice。
下一步应把候选选择升级为可测量的 k-shortest 路径搜索：

```text
状态：
    输入键位置
    已用错误预算
    前一个词的语言模型状态
    lattice 入边
    k-shortest 路径排名

转移：
    使用已有可解释词边
    可选的高代价词典外回退边
    加入 unigram/bigram 或后续公开语言模型分
```

这会把 beam 近似造成的搜索误差与语言模型误差分开测量。随后换入有
明确许可证的更大公开词典和独立语料，增加词典外输入、长句、内存及
延迟基准和真实性更高的错误评测。当前紧凑 trie、联合对齐状态、流式
lattice、解释结构和旧参照测试可以继续作为行为基线。
