# 当前解码设计

## 问题定义

输入是一串非空的小写英文字母，表示程序实际收到的自然码按键。词典中
的每个条目保存：

```text
中文文本、空格分隔的无声调拼音、合成相对权重
```

codec 把每个拼音音节变成标准两键自然码，同时保留音节边界。解码器
输出至多 Top-K 个候选；每个候选必须带有：

- 完整标准编码；
- 本次匹配采用的可变长编码；
- 哪些音节只使用了一键简拼；
- 输入与候选编码之间的纠错操作；
- 词频分、简拼代价、纠错代价和总分。

目标不是模拟真实输入法准确率，而是建立确定、可测试、可解释的联合
解码基线。

## 拼写隐变量

对于一个含 `n` 个音节的词，每个音节可以采用：

- 两键标准自然码；
- 标准码的第一键，作为一键简拼。

因此一个词有至多 `2^n` 个拼写解释，长度在 `n` 到 `2n` 之间。当前
小词典基线会穷举这些解释，并限制单个词条最多 12 个音节，避免无界
展开。

穷举并不是最终架构。它的价值是给未来的 trie、Viterbi 或 beam search
提供行为正确、容易检查的参照。

## 错误通道

对实际输入 `x` 和某个可变长候选编码 `c`，只接受以下关系：

1. `x == c`；
2. 长度相同且只有一个位置不同，两个键在手工 QWERTY 邻接表中相邻；
3. 长度相同且只有两个相邻位置不同，交换后恰好相同；
4. `x` 比 `c` 少一个键，插回该键后恰好相同；
5. `x` 比 `c` 多一个键，删除该键后恰好相同。

简拼选择和一次错误可以同时出现。暂不接受两次错误、任意替换或概率化
键距。

## 评分

```text
词频分 = ln(合成相对权重)
简拼代价 = 简拼音节数 × 0.85
总分 = 词频分 - 简拼代价 - 纠错代价
```

默认纠错代价：

```text
原样匹配        0.00
相邻按键颠倒    2.25
QWERTY 邻键替换 2.75
漏键            3.00
多按            3.00
```

这些数字只是明确、可修改的研究假设，不是从用户数据或公开语料估计的
概率。总分相同时依次偏好更少简拼、更低类别序号的纠错操作和稳定的
文本、编码顺序。

每个词条可能有多个能够解释输入的拼写路径。解码器只保留其中得分最高
且稳定排序的路径，再与其他词条竞争 Top-K。

## 假阳性策略

程序只返回候选，不自动上屏。完整原样解释和容错解释都保留分数拆解。
高权重纠错候选可能超过低权重原样候选，这正是评测需要观察的现象，
不能据此静默修改输入。

当前合成评测会报告干净输入首选是否仍然无需纠错。未来使用更大公开
词典后，还需要校准“最佳纠错候选与最佳原样候选的分差”，再讨论任何
主动提升策略。

## 多词无界搜索

`decode_sentence` 在整个输入串上使用动态规划。状态由输入键位置和全局
错误预算组成；每条转移消费一个词的某个全码、简拼混合解释。未使用
错误的状态可以选择原样转移或消耗唯一一次错误，已使用错误的状态只能
继续原样匹配。

为了让不同词数的路径可以比较，句子层把每个词的合成权重归一化为一元
词概率：

```text
词的句子分 =
    ln(词权重 / 词典总权重)
  - 简拼代价
  - 纠错代价
```

这避免了直接相加正的 `ln(词权重)` 所造成的“拆成越多词得分越高”。
每个位置和错误状态只保留确定性排序后的有界 beam。当前实现仍会枚举
所有词条和 `2^n` 种词内拼写；动态规划解决了词界组合，但尚未解决词典
规模和词内组合的效率。

## 数据和隐私

`tests/fixtures/public/` 只能包含公开、人工构造或合成内容。演示频率
不是语料统计。

真实输入、按键时间戳、个人词典和衍生模型不进入 Git。当前版本没有
采集器，不写输入日志，也不联网。

## 已知限制

- 演示词典仅有 50 个词，无法说明真实准确率；
- codec 还没有完整合法普通话音节表；
- 没有同音词上下文或语言模型；
- QWERTY 邻接表是手工离散表，不含键距、时间或个人手型；
- 分数没有校准为概率；
- 穷举 `2^n` 个简拼组合不面向长句或生产规模。

## 下一项算法跃迁

下一步不应继续给枚举器堆规则，而应把现有动态规划的转移生成器替换为
词典 trie，并加入最小的词 bigram：

```text
状态：
    输入键位置
    trie 前缀
    已用错误预算
    前一个词的语言模型状态
    Top-K 路径

转移：
    消耗两键：完整双拼音节
    消耗一键：一键简拼音节
    结束一个词：加入 unigram/bigram 分并回到 trie 根
    使用一次局部错误：替换、颠倒、漏键或多按
```

trie 会让共享编码前缀只遍历一次；bigram 则能区分仅靠词频无法判断的
词序。两者都可以继续沿用当前解释结构和合成回归评测。
