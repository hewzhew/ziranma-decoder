# 纠错候选归并

## 目的

输入探针已经能输出有顺序的原子事实。分开删除再补入时是：

```text
Commit → Revision（删除）→ Commit（补入）
```

选中旧文字后直接开始新的输入法组合时，删除与补入则合在一条提交的
`document_change` 中。`CorrectionCandidateDetector` 在内存中把这两种
证据足够的行为归成一个 **纠错候选**。这个名称是边界：删补或直接替换
很像纠错，但也可能是用户主动改写，程序不能把行为模式冒充成意图标签。

模块没有文件、网络、数据库或后台任务。仓库测试只使用人工字符串。
`tracker-probe` 可以通过 `--preview-candidates --candidate-gap-ms <MS>`
显式接入它；候选仍只打印到终端并随进程退出消失。

## 保守归并条件

删除后出现补入时，必须同时满足：

1. 两个事件的字符位置相同；
2. 两边位置证据都不是 `Ambiguous`；
3. 间隔不超过调用者明确给出的 `max_gap_ms`；
4. 补入内容非空；
5. 事件时间单调不倒退。

`max_gap_ms` 是实验配置，不是关于人类纠错速度的测量结论。超时、异位或
歧义事件直接不归并，不用语言猜测补救。

一条提交若要形成直接替换候选，`document_change` 必须同时包含非空的
删除与插入，而且位置证据不能是 `Ambiguous`。这条净差分比较的是组合前
文档与提交后文档，不会把中间拉丁拼音误当成被用户删掉的原文。

如果删除紧跟在一条提交后，且删除范围完全落在该提交刚插入的范围内，
候选会保留 `source_commit_sequence`。这只是来源关系，也不证明原提交
“错误”。

## 输出证据

每个候选保留：

- 删除、补入和来源提交的事件序号；
- 两端会话内毫秒时间与间隔；
- 字符位置、删除文字和补入文字；
- 删除按键、补入按键与合并后的 `keys_complete`；
- 两端的位置证据；
- 若补入来自输入法提交，保留组合拼音；
- `RestoredSameText` 或 `ReplacedWithDifferentText` 内容分类；
- `DeleteThenInsert` 或 `DirectReplacement` 事件形态。

`logical_key_actions` 统计记录中的主按键动作数；`Shift(Left)` 是一个带
修饰语义的逻辑动作，不宣称等于操作系统层面的所有 key-down/key-up 数。
直接替换只有一条原子记录，无法诚实地把其中的按键拆成“删除键”和
“补入键”，因此整组限域按键放在 `replacement_keys`，删除侧留空。

## 当前明确不做

- 不把候选自动写入私人日志或训练集；
- 不给候选贴“手滑”“错别字”等意图标签；
- 不归并多轮、跨位置或超时改写；
- 不从 `Ambiguous` 位置推断纠错；
- 不把“替换后全文与原文完全相同”的零净变化冒充成可定位的直接替换；
- 不从单段净差分反推含共同前后缀的完整选择范围；
- 不把这一启发式的命中率当作真实准确率。

当前只允许手动开始/结束的短会话候选预览：命令行必须明确给出时间边界，
计时使用会话内单调时钟；READY 会重置候选序号、时间和遗留状态。候选
明细仍不能保存；终端预览不能悄悄升级成原始事件日志或训练数据。

探针停止时会从同一内存状态打印脱敏 `SESSION_SUMMARY`。它统计事件数、
证据完整性、形态分类和先删后补的间隔聚合，不保留候选文字列表。直接
替换的结构性零间隔不混入删补间隔；候选数也不命名为“错误数”或
“准确率”。

操作者可以另行显式给出 `--save-summary`，仅把上述聚合保存为
`ziranma-session-summary-v1`。目标被限制在 Git 已忽略的固定私有目录，
必须是新 `.json` 文件，并用原子、拒绝覆盖的方式创建。保存内容不含
候选明细，但仍按私人行为元数据管理。多份摘要只能由
[`summary-report`](summary-report.md)逐个显式点名后做只读合并；它不会
把候选数重新解释为错误数。

## 提交后裁掉尾字

另一种行为不是“删除后补入”，而是先提交一个较长候选，再连续删掉它的尾部。
例如完整码 `xmuufu` 提交“线束缚”，随后删除末尾“缚”而留下“线束”。
`CommitTailTrimDetector` 为这种情况保留单独的**尾部裁剪观察**：

- 删除事件必须直接跟在来源提交或它的上一条尾部裁剪之后；
- 删除位置必须有 `Caret` 或 `UniqueText` 证据；
- 删除范围必须精确等于刚提交文字的当前后缀；
- 中间插入、异位删除、位置歧义或其他事件立即断开；
- 连续删除多个尾字时，每一步都继续绑定最初的来源提交，并保留当前剩余文字。

这条归并**没有速度阈值**。毫秒间隔只作为事实保存在观察中，不参与“是不是想
造词”的判定，因此 100 ms 和十几分钟都不会被算法擅自赋予不同意图。若来源按键
完整、只含小写字母及最终选择键，而且每个上屏汉字严格对应两键完整双拼，观察器
才会额外给出一个待审阅的码词提案；`xmuufu → 线束缚 → 线束` 可得到
`xmuu → 线束`。按键不完整、简拼、纠错或长度不齐时仍可保留编辑事实，但不会猜码。

观察器不写文件、不修改个人词典，也不把提案自动当成用户意图；包含的组合和文字
不会进入 `Debug`。它是未来打字练习实验室和显式标注流程的基础结构。
