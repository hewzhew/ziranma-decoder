# Tab 音形辅助：公开数据审计与许可隔离

## 结论

第一版真实笔画包采用
[Conway Stroke Data](https://github.com/stroke-input/stroke-input-data) 的
`sequence-characters.txt`，固定到提交
`4449c63198292fd36d68d8068d39641bb6bbf86d`。它的 CC BY 4.0 允许复制、
修改和商业使用；项目必须保留来源与署名、标明转换，并且不能附加阻止许可
权利的限制。完整来源、许可、校验和与导入账目保存在
`data/public/conway-stroke-data/`。

这不是法律意见。工程上的取舍是：核心仓库只接纳许可边界清楚、可以逐文件
追溯的数据；不同许可的数据不混成一份无法拆开的数据库。

## 候选资料比较

| 资料 | 能提供什么 | 许可与风险 | 本轮决定 |
| --- | --- | --- | --- |
| [Conway Stroke Data](https://github.com/stroke-input/stroke-input-data) | 28,165 字、五类有序笔画、替代笔顺 | 表数据 CC BY 4.0；需署名和变更说明；人工整理，可能有错，字形多循康熙且宽松 | **采用为独立笔画包** |
| [Make Me a Hanzi](https://github.com/skishore/makemeahanzi) `dictionary.txt` | 约九千常用字的 IDS 分解与部件信息 | 字典为 LGPL v3+；需进一步确认数据链接、修改与再分发义务 | 不进入核心，保留作隔离实验候选 |
| Make Me a Hanzi `graphics.txt` / Hanzi Writer 字形数据 | SVG 路径与有序笔画 | Arphic Public License；修改字形数据有较强的开放与通知义务 | 不进入核心 |
| [CHISE IDS](https://github.com/chise/ids) | 大范围 IDS、抽象字形和异体关系 | GPL v2 or later | 不进入核心 |
| [CJKVI IDS](https://github.com/cjkvi/cjkvi-ids) | 带地区标签的 IDS 集合 | 大部分沿用 CHISE/GPL v2 边界，混合文件还需逐项判断 | 不进入核心 |
| Unicode Unihan / IDS 标准 | 部首、总笔画、IDS 语法等元数据 | 许可清楚，但不是覆盖目标字集的完整五类笔顺或部件读音表 | 只作校验元数据，不冒充笔顺库 |

“代码仓库使用 MIT”或“上层库使用 MIT”不表示其附带汉字数据也自动变成
MIT；本审计始终按具体数据文件判断。

2026-07-28 再次按上游一手说明复核后，Conway 仍明确把
`sequence-characters.txt` 标为 CC BY 4.0；Make Me a Hanzi 的
`COPYING` 仍把 `dictionary.txt` 定为 LGPL v3+、`graphics.txt` 定为
Arphic Public License；CJKVI 的 README 仍说明 `ids.txt` 跟随 CHISE
条款、其他大部分数据为 GPLv2。Unicode License v3 虽然边界清楚，Unihan
提供的部首—笔画等属性也仍不是有序部件及其普通话首字母表。因此本轮没有
新增真实部件包，避免用“许可看似可用”替代“数据语义确实适配”。

## 采用数据的事实边界

固定快照的严格导入结果为：

- 60,227 个不同笔画序列；
- 63,005 个字符—序列分配；
- 28,165 个不同字符；
- 14,176 个字符有替代序列；
- 单字最多 90 个替代序列，最长序列 52 画。

把它与固定的 `rime-pinyin-simp` 快照按**解码器实际接受的词条**交叉后：

- 16,469 个不同汉字全部有笔画记录，缺失 0；
- 133,827 次词条内汉字出现全部有笔画记录；
- 17,038 个单汉字词条全部有笔画记录。

这是两个固定公共快照之间的结构覆盖率，不是笔顺正确率、候选保留率或真实
使用覆盖率。词典权重也没有被当作现实频率；审计只做不加权计数。

替代数很多不是解析器错误。上游的手工源文件使用正则表达式记录宽松字形
和宽松笔顺，生成文件已经把组合展开。本项目直接导入展开后的
`sequence-characters.txt`，不自行重写上游正则展开器。

数字类别确定映射为：

```text
1 → h（横）  2 → s（竖）  3 → p（撇）  4 → n（捺/点）  5 → z（折）
```

解析器接受注释与空行；其余行必须恰好是
`数字序列<Tab>一个或多个字符`。它拒绝未知类别、重复序列、同一行重复
字符、控制字符和越界输入。每个字符的替代码都会保留，因而不会把上游
“允许两种笔顺”静默压成一种。

## 许可隔离

```text
核心 Rust 逻辑
  ├─ CC BY 4.0 Conway 笔画包（独立目录、独立通知、可替换）
  ├─ 未来部件包（尚未选择，不得偷渡）
  └─ 私人反馈数据（data/private，绝不并入公开字形包）
```

部件首字母功能仍保持接口与人工合成测试，但没有真实部件表。若以后确实
需要 LGPL、APL 或 GPL 数据，应作为显式可选、可拆卸的数据包重新审计，
不能让它悄悄改变核心代码或其他公开数据的许可口径。

## 已完成的公开验证门

`public-shape-audit` 已对固定公开同码单字池完成前三项：

1. 对固定公开同音候选池的目标保留率、无数据率和缩减率；
2. 前 1、前 2、前 3 枚笔画的最短定位长度；
3. 多替代序列造成的宽松匹配率；

原排名第 11 名以后的 13,285 个目标均有数据；三画时，12,589 个目标在
全部替代笔顺下进入 Top-10，平均候选池由 91.94 缩到 5.47。方法、完整
分母与限制见 [Tab 音形辅助](tab-shape-refinement.md)。固定数字由公开回归
测试保护。

## 下一道验证门

现在剩下的是现实动作账：宝宝的私有回放中 Tab + 笔画 + 选择是否真的
少于翻页、组词找字或改错。公开课程没有现实候选顺序、视觉搜索成本，也
没有输错笔画的行为分布，因此不能越过这道门直接进入实时交互。

这一步需要读取私人记录，而且必须由宝宝明确发起一次隐私审阅后的
本地实验；本轮没有读取 `data/private/`。
