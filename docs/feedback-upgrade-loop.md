# 从持续记录到受控升级

## 目的

持续记录的目的不是把私人数据囤得越多越好，而是让下一次改动能够回答：

1. 采集证据是否完整、可信；
2. 完整双拼、简写和纠错分别在哪里失败；
3. 改动是在独立的后续输入上变好，还是只记住了旧答案；
4. 省下的按键是否被选词、回删和重打抵消。

闭环因此是：

```text
自然会话
  → 当前用户加密段
  → 脱敏质量与候选报告
  → 只选择一个可解释改动
  → 冻结实现
  → 下一次独立自然会话验证
  → 接受、回退或停止
```

记录器不会自动修改源代码、下载更新、上传数据或把刚出现的文字立即写进
持久模型。升级仍由宝宝和猫猫明确审阅、实现和验证。

## 版本与采集口径

每个 `.zcs` 的加密载荷包含：

- `producer_version`：产生该段的记录器版本，例如
  `0.1.0+continuous.3`；
- `capture_profile`：原子事件的采集语义；当前为 `codex-uia-v1`；
- 会话号、段序号、起止时间、`daily/course/theme` 类别和事件胶囊。

这些字段和文字一起受到 DPAPI 保护。文件名只含会话号和段序号。

普通实现修复或报告变化应更新 `producer_version` 的本地修订后缀；若
按键限域、组合归并、目标选择或差分含义变化，则必须创建新的
`capture_profile`，不能把口径不同的数据静默合并。当前回放器只接受它
明确支持的 profile，遇到未知 profile 会拒绝而不是猜测兼容。

## 一次会话怎样形成反馈

正常停止后，记录器会打印：

```text
CODEX_RECORDER_FEEDBACK session=<ID> segments=<N> events=<N> ...
FEEDBACK_COMMAND cargo run ... --session <ID> ... --compact
```

`--session` 不是目录扫描。它只在固定私有目录中按
`segment-<ID>-00000000.zcs`、`00000001`……依次寻找，遇到第一个缺号就
停止；第 0 段不存在、文件是符号链接或不是普通文件时拒绝。仍在内存中
尚未轮换的当前段不会进入这份快照。

也可以手动运行：

```powershell
cargo run --release --bin capsule-replay -- `
  --session <ID> `
  --window-gap-ms 15000 `
  --compact
```

输出只含质量计数、窗口数、真实动作数、各简写策略的省键和 Top-K 名次。
宝宝可以把这份脱敏报告交给猫猫；不需要粘贴 `.zcs` 内容。

若只想在记录过程中看采集是否健康，可运行：

```powershell
cargo run --release --bin capsule-replay -- `
  --session <ID> `
  --health-only
```

这个模式不构建词典或枚举候选，只报告事件形状，因此适合频繁中途检查。

第一份会话只能用于描述问题、建立历史或提出假设，不能同时证明针对它的
修改有效。

## 旧会话学习，下一会话考试

个人缓存或顺序证据必须明确分开：

```powershell
cargo run --release --bin capsule-replay -- `
  --history-session <旧会话ID> `
  --session <新会话ID> `
  --window-gap-ms 15000 `
  --personal-pair-cache `
  --compact
```

处理顺序严格按命令行给出的 selector 顺序。`--history-session` 中的段
只更新内存历史；最终命中、名次和窗口成绩只统计 `--session` 指定的后续
会话。历史和评测 selector 展开后仍统一拒绝重复文件；加密元数据还会
拒绝同一会话跨组、段序/时间倒退，以及能够明确证明“评测早于历史”的
组合。个人模式还拒绝按新→旧顺序给出的多个受保护评测会话，避免评测中
先学到的未来证据帮助较早样本。不同独立会话允许使用不同记录器版本，
旧版历史和新版评测无需伪装成同一采集程序。

同一份会话不能同时作为 history 和 evaluation。代码层的重复路径检查会
拒绝这种情况，但实验解释也必须坚持这条边界。若新版本是依据会话 B 的
报告修改的，那么 B 已经成为开发数据；至少等待会话 C 才能验证升级。

## 升级门槛

每次只改变一类东西，并相对改动前冻结的基线比较。

### 采集层

关注 `incomplete_keys`、`key_failures`、缺少字母码、歧义位置和连接状态。
若证据不完整，先修记录器；不能拿缺首键或错配事件去调解码器。采集语义
改变后提升 `capture_profile`，旧、新 profile 分开报告。

`noncanonical_code_observations` 只表示实际字母码和由拼音反推的标准自然码
不同，明确不等同于错误。自定义短语、用户别名、选词和找字流程都可能
产生这种观察；只有重复出现、目标稳定且后续没有高置信纠正时，才可考虑
把它作为个人别名证据。

### 解码层

完整规范码是安全基线。候选排序或个人缓存只有同时满足下面条件才进入
下一轮：

- 后续独立会话的完整码 Top-1/Top-5/Top-10 不下降；
- 简写相对同一版本完整码的退化减少，或有候选从 Top-10 外被救回；
- 没有用更大的私人提升幅度、未来答案或扩大候选池掩盖退化；
- 报告显示真实窗口分母和配对结果，不能用一两个成功例子代替整体。

若只有历史会话改善、后续会话没有改善，视为过拟合并回退。

### 交互层

省键不能只看反事实输入长度。还要一起看：

- `recorded_actions` 与反事实 `projected_actions_one_selection`；
- 修订、组合内 Backspace/Delete 和候选选择动作；
- 掉出 Top-10 后可能产生的额外补救成本。

修订也不能一律叫“打错”。组合内部编辑较接近按键纠错；提交后的短时
删除再重输可作为纠正候选；多字删除/插入、导航后编辑和“先组词再删掉
陪衬字”的找字流程应单独保留为改写或辅助取字候选。证据不足时保持未知，
不得用它训练错误模型。

一种策略即使少按字母，但需要更多选词或纠错，也不能称为效率提升。

## 日常、课程与主题

- `daily`：不指定内容的自然使用，最适合做最终外部有效性检查。
- `course`：宝宝和猫猫事先冻结的一组练习目标，例如完整双拼、连续简写、
  候选数字键、句中替换或误键恢复。它适合定位能力缺口，但练习结果不能
  反过来冒充自然准确率。
- `theme`：某个稳定语域，如课程笔记、代码讨论或日常聊天。用于判断
  个性化是否只在一个语域有效。

类别目前只标记整次加密会话，不动态保存课程标题或主题文字。未来加入
步骤时，仍应使用同一事件流和同一版本字段；课程设计在开始前冻结，不能
看完答案再改题目。

## 何时升级，何时停

可以升级：

- 同一问题跨多个独立会话重复出现；
- 有明确、局部、可回退的实现假设；
- 改动在未参与设计的后续会话上改善；
- 完整码安全基线和未知输入保留没有受损。

应该停止或等待：

- 样本质量不足或只有一个窗口；
- 改善只来自同一批开发数据；
- 简写省键被选择和补救动作抵消；
- 更复杂模型没有带来新增救回；
- 新路线需要扩大到其他应用、联网或自动读取更多私人内容。

“暂时没有足够证据”是有效结论。持续记录器的价值正是允许我们等下一轮
自然证据，而不是为了让模型继续长大而制造数据。
