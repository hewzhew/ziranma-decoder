# 私人事件胶囊与离线回放

事件胶囊是从“只知道数量”走向“能用真实输入证据比较解码方案”的最小
私人数据层。它只服务于人工武装的 Codex 白名单输入框，不是常驻键盘
记录器，也不进入解码器生产路径。

需要日常增量收集时，不再反复扩大这个明文 `.zic` 模式；使用
[Codex 专用持续记录器](continuous-recorder.md)生成当前 Windows 用户
DPAPI 保护的 `.zcs` 小段。两者解密后的原子事件语义相同，但授权方式、
生命周期和磁盘保护不同。

## 明确的私人内容边界

胶囊会保存 READY 之后产生的有界 `COMMIT/REVISION`：

- 会话内单调经过时间；
- 限域按键及 `keys_complete`；
- 提交时的拼音组合；
- 预编辑差分与组合前后文档净差分。

这些字段包含真实文字和真实按键。`.zic` 中的 UTF-8 字符串使用小写
十六进制，只为避免转义歧义，**不是加密**。文件头明确写入：

```text
contains_private_text=true
encryption=none
```

胶囊不保存墙上时间、PID、目标名称或完整输入框快照，但差分仍可能包含
被替换的旧文字，所以必须按私人聊天数据管理。当前没有自动过期或安全
擦除；不再需要时，由操作者删除精确文件。

## 显式保存

只有同时给出以下四项才会启用一次性保存：

```powershell
cargo run --bin tracker-probe -- --pid <PID> --arm --capture-keys `
  --save-capsule data/private/event-capsules/manual-001.zic `
  --allow-private-plaintext
```

启动后仍须聚焦精确目标框、按 `Ctrl+Shift+F11` 并看到
`KEY_CAPTURE_READY`。READY 会清除先前状态并把胶囊计时归零；只有之后的
原子记录进入胶囊。`Ctrl+Shift+F12` 停止后才一次性写入，不进行流式
磁盘日志。

目标只能是：

```text
data/private/event-capsules/<非隐藏新文件>.zic
```

程序拒绝子目录、其他扩展名、符号链接目录和已存在目标。写入使用同目录
临时文件、刷新、同步及拒绝覆盖的最终硬链接。胶囊最多 4096 个事件；
每事件最多 128 个按键；单一私人文本字段最多 64 KiB；所有私人文本字段
合计最多 4 MiB。任何超限都会使整个胶囊拒绝保存，不生成悄悄截断的
“完整”样本。

`--save-capsule` 必须和 `--capture-keys` 及单独的
`--allow-private-plaintext` 一起出现。后一个参数是对“本地明文、未加密”
的明确确认，不能由预览、摘要或候选参数隐式开启。

## 显式只读回放

每个胶囊仍必须逐个点名：

```powershell
cargo run --release --bin capsule-replay -- `
  --input data/private/event-capsules/manual-001.zic `
  --window-gap-ms 5000 `
  --personal-cache `
  --compact
```

回放器不会扫描私人目录、不会寻找最新文件、不会写报告，也不会打印
胶囊文字。它拒绝符号链接、重复路径、坏格式及大于 16 MiB 的文件。
当前固定使用仓库已锁定的公开 Rime 词典，输出一行
`CAPSULE_REPLAY_REPORT contains_text=false ...`。

持续会话中途可使用 `--session <ID> --health-only`。这个模式仍只展开显式
会话的连续、可预测段名，但不载入词典或枚举候选，只输出事件数量、按键
完整性、组合内编辑键、修订形状和位置歧义等脱敏健康计数。

`--window-gap-ms` 没有默认值；省略时只做逐提交回放。显式给出正数后，
回放器还会把同一胶囊内的最大连续提交段视作一个离线窗口。相邻提交只有
同时满足以下条件才连接：

- 都是按键完整、拼音可编码且有精确全码目标词界的提交；
- 文档净差分只是非空追加，没有删除，位置证据不为 `Ambiguous`；
- 后一提交恰好从前一提交的字符终点继续；
- 两次提交的会话内间隔不超过显式毫秒边界；
- 中间没有 `REVISION` 或其他不合格提交。

窗口不做滑动切片，因此一个最大连续段只贡献一次样本。随后分别报告
`window_raw_joined`、`window_canonical_full`、
`window_word_tail_one_short`、`window_word_tail_keep_singletons` 与
`window_word_head_anchored`。前两条把各次提交的选词键移除后直接连接
字母；后三条进一步模拟逐词简写。超过 64 个字母的窗口单独计数并跳过，
不截断。

回放先按顺序解释真实按键：组合内 Backspace/Delete 与光标移动会作用于
正在构造的字母串；组合开始前的文档导航不会误算为拼音。之后分别报告：

- `raw_existing`：宝宝实际完成这次提交的有效字母串；
- `canonical_full`：从可编码拼音重新生成的规范完整自然码；
- `tail_one_short`：仅把最后一个音节缩成一键；
- `head_anchored`：第一个音节完整，后续音节一键；
- `all_short`：每个音节都用一键。
- `word_tail_one_short`：在每个词内分别缩短最后一个音节；
- `word_tail_keep_singletons`：多音节词仍缩短词尾，单音节词保留完整
  双拼，作为少省一键的保守对照；
- `word_head_anchored`：每个词都重新以完整首音节起步，其余音节一键。

后六条是**反事实策略**，不冒充宝宝实际输入过。逐词边界也不能为了得到
好结果任意制造：只有规范全码 Top-10 中已经存在目标文字，而且该路径的
每段都是精确、非简拼、无未解析键的公开词典候选时，才复用它的可审计
词边界。`word_boundaries_available_commits` 与
`word_boundaries_unavailable_commits` 分别报告是否满足这一前提。

每条策略累计尝试数、输入字母总数、目标文字是否进入 Top-1/5/10，以及
Top-10 内的脱敏名次直方图。直方图采用 `名次:次数`，例如 `1:3,2:1`；
目标不在 Top-10 时不进入直方图，因此直方图计数之和恒等于
`hits_at_10`，不会打印候选文字。

为了把“少几个字母”和“少几次实际操作”分开，报告还包含：

- `recorded_logical_key_actions`：胶囊全部提交与修订实际关联到的限域逻辑
  按键，包括选词键、组合内修改键和导航键；
- `continuous_window_recorded_logical_key_actions`：只累计进入连续窗口的
  提交实际按键，供同一窗口反事实比较；
- 每条策略的 `projected_actions_one_selection`：`input_keys + attempts`，
  即假设每次反事实输入只需一次最终选词的理论操作数。

最后一项不包含看候选、翻页、组合内改错或错误候选的补救成本；若目标
没有命中相应候选范围，它也不能称为一次成功输入的操作数。不同策略的
尝试数可能不同，不能只比较命中数，也不能把公开词典回放称为真实输入法
准确率。

默认输出保留全部机器可读字段。显式 `--compact` 时改为少量脱敏行：
会话质量、连续窗口、规范完整码基线，以及三条简写相对同一完整码窗口的
配对结果。`improved/same/worsened` 比较目标在 Top-10 内的精确名次；
完整码可见而简写不可见另记 `dropped_from_top_10`，反向变化记
`recovered_into_top_10`，两边都不可见则单列 `both_outside_top_10`。
四种比较状态之和恒等于 `comparisons`。

配对行还在同一分母上报告 `baseline_keys`、`strategy_keys` 与
`saved_keys`。若某个窗口没有可缩短的音节，策略仍以原完整码参加比较，
记入 `unchanged` 和相应名次结果，不再从分母消失。给出
`--window-gap-ms` 时紧凑报告展示这些窗口配对；省略时间边界时仍展示
逐提交泳道。两种格式都不包含胶囊文字，`--compact` 也不会改变回放或
写入任何文件。

## 显式公开上下文对照

`--public-context` 与 `--public-character-context` 都必须和
`--window-gap-ms` 同时给出，而且两者互斥。它们都从仓库锁定的
UD Chinese GSDSimp **train** 快照筛选公开可覆盖词序列；前者使用现有
add-alpha word bigram，后者把同一批公开词序列连接成句后训练 add-alpha
character bigram，并以每个候选的平均字符转移对数概率排序。两者都不读取
test 快照调参，也不把胶囊文字、目标或按键加入训练。

每条码先由原 unigram 解码器生成固定 Top-50 候选池，公开上下文只能重排
该池，不能制造新路径；目标文字只在重排完毕后用于本地名次评分。词模型
保留公开语料的词界，字符模型不依赖候选的词切分；两者是分开的诊断基线，
不会在一份报告中混合。紧凑输出用 `public_word_bigram` 或
`public_character_bigram` 明确标记当前模型。

紧凑报告先分别给出两种解码器的规范完整码基线，再为三条简写输出
`CONTEXT_COMPARE`。只有 unigram 与公开上下文的完整码目标都在 Top-10
时，才比较简写相对各自基线的退化量：

- `relative_reduced/same/increased`：公开上下文使相对退化减小、持平或
  增大；
- `drops_rescued/new_drops`：原先掉出 Top-10 被救回，或上下文新增掉出；
- `unigram_baseline_only/context_baseline_only/neither_baseline`：两套完整
  码基线不同时可见的窗口，单独列出而不伪装成救回。

这只是公开书面语域的安全对照，不代表它适合私人聊天，也不是私人
个性化模型。固定候选池深度是诊断边界，不是生产参数。这两个开关应使用
`cargo run --release`；它们会增加离线运行时间，但仍不联网、不写报告、
不改变胶囊。若词与字符两条公开重排都不能在冻结池内救回简写退化，就到
此停止公开上下文路线，不继续用更复杂的公开模型追逐这份私人小样本。

## 因果个人词缓存

`--personal-cache` 是与两个公开上下文开关互斥的第三种诊断，也必须显式
给出 `--window-gap-ms`。它不训练公开模型，而是在本次进程内维护一个
私人词计数缓存；多个 `--input` 按命令行给出的顺序处理，因此文件顺序
就是跨胶囊的因果顺序。缓存没有文字读取接口、序列化或磁盘导出，
`Debug` 也只显示脱敏词型数与词次。进程结束后不会保存个人模型。

学习词语必须来自规范完整码 Top-10 中目标路径的精确公开词典分段。每个
最大连续窗口先使用当时已有的缓存重排，完成本窗口全部评分后才学习该
窗口中的目标词；所以一个窗口不能用自己的答案抬高自己。未进入连续窗口
但满足同样精确分段证据的单次提交，只能影响它之后的窗口。

重排仍冻结在原 unigram Top-50 候选池内。每个候选按此前出现的词次得到
有界排序键调整：1 次最多前移键值 1 位，2–3 次为 2 位，4 次以上封顶
为 3 位；没有历史证据时严格保留原次序。私人目标只在重排完成后用于
名次评分，不能制造新候选。

这是**内存态实验**，还不是可持久化的个人词库。缓存同时维护当前胶囊的
私有文档跨度账本：确定位置的删除、替换或局部改动只要与已学习提交重叠，
就保守撤销该提交的全部词次；发生在跨度前方的编辑会移动后续跨度。每个
新胶囊开始时清空旧文档跨度，但保留历史词计数，因此新输入框的相同位置
不会误删旧会话历史。

报告分别给出累计学习词次、撤销提交/词次数、最终保留词次、
`personal_cache_revision_events_with_reversal` 与
`personal_cache_revisions_not_reversed`。位置证据为 `Ambiguous` 的编辑
不会猜测性移动或撤销账本，并单列
`personal_cache_ambiguous_edits_not_applied`。无法关联到任何仍活动学习
跨度的修订也不会凭文字相同跨会话扣除。

若缓存在因果回放中不改善简写、或损伤完整码基线，就停止该缓存策略；
若只在重复词上有受限帮助，再研究明确加密、可清空的持久层，而不是直接
扩大提升幅度。

当前里程碑把这条策略保留为“有界、可撤销的个人词频安全底座”，但不把
它算作长句简写方案：排序键调整继续封顶三位，不增加权重、不导出模型。
若继续研究个人上下文，必须另设按顺序学习的词对/短语对照，并继续使用
先预测后学习、冻结候选池和相对完整码指标，不能把词频底座的收益重复
计算成简写收益。

`--personal-pair-cache` 是独立的第四种诊断，和前述三个模式全部互斥。
它包含完全相同的个人词频底座，再额外读取此前学到的有序
`前词 → 后词` 次数；没有词对证据时，排序应与 `--personal-cache`
一致。词频与词对的合计排序键调整仍封顶三位，词对不能借新开关突破安全
上限。

一个连续窗口完成预测后，会把窗口内所有精确词界连接成一个有序序列，
因此能够学习原先分开提交的跨提交词对；不成窗口的多词提交只学习本提交
内部词对。词对序列另有当前文档跨度，任何确定位置的整段或局部编辑只要
与它重叠，就撤销整条序列贡献的词对；跨胶囊清空跨度但保留历史词对计数，
规则与词频账本相同。

紧凑报告分别使用 `personal_word_cache` 与
`personal_word_pair_cache` 标签。词对路线只有在相对各自个人完整码基线
减少简写退化、救回候选，并且不损伤完整码时才算新增价值；仅仅重复出现
词频模式已有的 Top-1 改善不算词对收益。

## 显式历史与未来评测

个人模式还接受一个或多个 `--history-input`，用于严格分开过去和未来：

```powershell
cargo run --release --bin capsule-replay -- `
  --history-input data/private/event-capsules/natural-001.zic `
  --input data/private/event-capsules/natural-002.zic `
  --window-gap-ms 15000 `
  --personal-pair-cache `
  --compact
```

所有历史胶囊先按参数顺序因果回放，只更新同一个内存缓存；它们的候选
命中、简写名次和窗口数不会合入最终成绩。随后才依次评测 `--input`
点名的胶囊，因此输出中的 `capsules/events/commits` 只属于未来评测组。
`--history-input` 只能和两个个人缓存模式之一使用；历史与评测路径合并
后仍统一拒绝重复、符号链接、目录扫描和未点名文件。至少必须有一个
评测 `--input`。

持续记录器生成的整次会话可以用会话号代替逐段路径：

```powershell
cargo run --release --bin capsule-replay -- `
  --history-session <旧会话号> `
  --session <新会话号> `
  --window-gap-ms 15000 `
  --personal-pair-cache `
  --compact
```

`--session` 只按固定名称连续展开该会话的加密段，不扫描目录；历史、评测
展开后仍使用同一重复路径检查。根据旧会话报告做出的修改必须等下一次
独立会话验证，完整规则见[反馈驱动升级闭环](feedback-upgrade-loop.md)。

报告在评测开始点冻结并显示历史胶囊数、历史事件数、历史学习提交数，
以及历史保留词/词对的 token、type 与 `repeated` 数。这里
`repeated = tokens - types`，只表示超过首次出现的额外证据，不包含文字。
最终保留缓存也使用同一口径。没有历史重复词对时，不继续增加三元组或
更长短语；等待真实的后续会话比用同一胶囊切片或复制答案更诚实。

## 当前限制与下一停止点

- 逐提交泳道仍以一次 `COMMIT` 为单位，不把窗口结果混进同一分母；
- 显式窗口回放已经能合并连续追加的相邻提交，但不能推断跨修订、跨位置
  或超过时间边界的句子；
- UIA 若把一次最终上屏拆成异常的提交加修订，当前不会猜测性合并目标；
- 含部分汉字的组合载荷无法重新编码时，仍可进入 `raw_existing`，但不
  进入七条拼音派生策略；
- 不完整按键、无法解释的组合编辑和超过 64 键的提交会单独计数并跳过；
- 纠错候选仍是可观察结构，不是用户意图标签。

首个停止点“人工非敏感短句完成追踪器保存 → 严格读取 → 八泳道脱敏
回放”已经通过；随后只完成了一次手动开始/停止的短自然试航。该试航已
用于同会话因果基线，但不会被复制或切片成伪造的未来集。当前停止点是等
自然产生下一份独立会话，再以第一份作显式历史、第二份作评测；持续
记录器只解决自然积累与加密分段，不放宽过去/未来分离。
