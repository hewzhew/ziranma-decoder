# 合成评测说明

## 目的

当前评测是开发期的回归仪器，用来回答：

- 某类搜索路径是否真的能够找回来源词条；
- 新规则是否挤掉了原本排在前面的正确候选；
- 排序是否确定；
- 算法扩展后，哪些错误类型变好或变差。

它不能回答真实用户准确率，因为样例由同一份被测小词典生成。

## 样例生成

对每个公开词条，评测器生成以下确定性样例：

| 类型 | 生成方式 |
|---|---|
| 干净全码 | 使用 codec 生成的完整标准编码 |
| 混合简拼 | 枚举除完整码以外的全部一键/两键音节组合 |
| 邻键替换 | 每个位置分别替换成手工 QWERTY 表中的每个邻键 |
| 相邻颠倒 | 交换每一对内容不同的相邻键 |
| 漏键 | 分别删除每一个键 |
| 多按 | 在每个间隙插入一个确定性的相邻重复键 |
| 双词无界 | 将词典中相邻两个词的全简拼直接拼接并搜索词界 |

没有随机数，因此相同代码和词典必须得到相同样例与 Recall 计数。

## 语言模型对照

bigram 训练序列位于 `demo_bigram_corpus.tsv`，句子排序用例位于
`demo_sentence_cases.tsv`。两者是分开的人工文件，但部分评测词对会在
训练序列中出现，因此它们不是统计学意义上的独立自然语料。

句例会把每个词变成全简拼并直接拼接，然后分别用纯 unigram 和
unigram/bigram 插值解码。当前 13 条用例结果为：

```text
unigram Top-1  12/13
bigram  Top-1  13/13
两者 Top-5     13/13
```

这只能验证 bigram 确实在预期歧义上改变排序，例如同码 `jp` 在“按键”
之后从“简拼”改选“键盘”；不能用来估计真实语言模型收益。

另有 5 条含 6～7 个词的人工长句，与训练行分开保存。当前小词典下
unigram 和 bigram 都是 5/5 Top-1；它们用于防止路径长度扩展破坏搜索，
仍然不是独立自然语料。

## 词外探针

`oov_lexicon.tsv` 保存 12 个不在演示解码词典中的人工词及无声调拼音，
标准按键仍由共享 codec 生成。评测只观察句子首选是否暴露未解析键，
不要求恢复词外中文，因为当前模型没有这项能力。

当前结果为：

```text
首选含未解析键       9/12
首选完全原样         0/12
被词典完整覆盖       3/12
未解析键/总输入键   17/48（35.4%）
```

“完整覆盖”可能来自同码词或其他合法切分，不能逐例直接叫作错误；但
完全覆盖在当前排序中绝对压过回退，因此 3/12 和 35.4% 清楚暴露了拒识
过弱。今后修改回退排序必须同时报告这组数字和封闭词典 Recall。

## 拒识影子校准

`evaluate` 另行运行只读的拒识影子层。它不返回新候选、不改动当前
“完整覆盖优先”的排序，只对每个输入计算：

```text
全部原样回退分 = -逐键未解析代价 × 输入键数
每键分差 = (最佳完整词典路径分 - 全部原样回退分) / 输入键数
```

当前逐键未解析代价为 8.00。若不存在完整词典路径，该输入在所有门槛下
都计为拒识；否则，只有每键分差不低于门槛才会在假想策略中接受词典
结果。固定扫描 0～8，已知正例合并 13 条短句和 5 条长句，负例使用
12 个独立人工词外探针。“已知句保留”只表示没有被拒识，并不替代同页
单独报告的句子 Top-K 正确率。

当前结果为：

```text
完整覆盖          已知句 18/18，词外 3/12
完整路径每键分差  已知句 5.090～5.910
                  词外   4.657～4.715
门槛 5.0 的影子决策
                  已知句保留 18/18
                  词外拒识   12/12
```

这个干净间隙来自 30 个很小的人工样本，且分数受演示词典、合成频率、
简拼代价和未解析代价共同影响。在加入独立集以前，它最多只能把 `5.0`
提升为待复核假设，不能据此采用生产拒识规则。下一节的独立公开校准
重新报告完整分布、正常句拒识和词外漏拒，并实际推翻了这个数字。

## 独立公开校准

`cargo run --release -- public-calibrate` 使用固定到提交
`4231dfd59866fa5999ad4a6bc1fdecd7985b3b59` 的 UD Chinese GSDSimp
train/test splits。train 含 3,997 句和 98,614 个语法 token，test 含
500 句、12,010 个语法 token 和 1,691 个标点 token；快照、CC BY-SA
4.0 许可证、上游 README、来源、SHA-256 和限定说明均保存在
`data/public/ud-chinese-gsdsimp/`。

筛选不查看解码结果。按上游顺序保留 8～24 个纯汉字的句子；Rime 有
整词时用最高权重读音，否则逐字回退。153 句长度合格，111 句为纯汉字
且全部可表达，固定取前 64。它们使用 678 次整词读音、164 次逐字回退。
另有 699 个唯一的 2～4 字 UD token 不作为完整词存在于 Rime、但可
逐字表达，固定取前 128。两组均同时产生完整码与全简拼，真实候选排序
仍完全不变。

影子标签不再把所有“词外”武断地算作应拒识。它直接比较现行 Top-1
文本是否等于公开来源文本，再分别报告相符结果保留率和不符结果拒识率：

| 轨道 | Top-1 相符 | 相符每键分差 | 不符完整路径每键分差 | 门槛 5.0 |
|---|---:|---:|---:|---:|
| 自然句完整码 | 4/64 | 5.639～5.876 | 4.601～6.231 | 保留 4/4；拒绝 4/60 |
| 自然句全简拼 | 0/64 | 无 | 3.611～5.047 | 拒绝 63/64 |
| 未收整词完整码 | 5/128 | 3.145～4.912 | 3.002～5.869 | 保留 0/5；拒绝 102/123 |
| 未收整词全简拼 | 0/128 | 无 | 0.971～5.478 | 拒绝 119/128 |

这组结果推翻了人工小集上 `5.0` 的完美分界。相符与不符的完整路径分差
明显重叠：自然句把门槛升到 6.0 会拒绝 58/60 个不符结果，也会拒绝
4/4 个相符结果；未收整词的相符结果反而整体偏低。全简拼没有相符
Top-1，说明 6.5 万词规模下 unigram 缺少解决组合歧义的上下文证据。
拒识只能避免输出一部分错误中文，不能把错误首选变成正确首选。

同一命令还运行不改排序的 Top-K 召回诊断：

| 轨道 | Top-1 | Top-5 | Top-10 |
|---|---:|---:|---:|
| 自然句完整码 | 4/64 | 10/64 | 12/64 |
| 自然句全简拼 | 0/64 | 0/64 | 0/64 |
| 未收整词完整码 | 5/128 | 15/128 | 24/128 |
| 未收整词全简拼 | 0/128 | 0/128 | 0/128 |

每个探针的按键都由记录下来的 Rime 答案分词生成，所以答案路径在
lattice 中结构可达。Top-10 缺失表示现行 unigram 把它排在可见窗口
之外；尤其全简拼的组合歧义不能靠只重排前十名解决。

这仍不是实际输入准确率：读音由 Rime 为公开文本确定，而非用户按键；
只取 test split 中满足长度、字符和词典覆盖条件的源序前 64/128 项；
没有输入上下文、候选选择或真实错误分布。但它足以否定直接采用固定
分差阈值。

### Train-only 词级上下文基线

同一命令另把 train 中的非标点纯汉字句映射到 Rime 词表：完整 token
存在时保留整词，否则逐字回退；任一 token 无法表达则整句排除。整个
过程不查看 test 文本的筛选结果、公开答案与解码结果。固定映射统计为：

- 2,346 个纯汉字句，2,339 个可覆盖训练序列；
- 51,712 个词实例，其中整词 42,745 次、逐字回退 8,967 次；
- 64,422 个不同 Rime 文本的词表中，观察到 40,299 种、49,373 次
  二元组。

模型沿用 add-0.5 和 35% unigram / 65% bigram 插值。为避免在证据不足
时先承担完整大词表 bigram 搜索的巨大成本，评测先做只读双路径诊断：
对每个 test 探针，只重新评分“公开答案路径”和“现行 unigram Top-1
路径”。它是上下文信号的乐观诊断，不会把答案塞进生产候选，也不等于
完整搜索准确率。

| 轨道 | 原始相符 | 原始不符中答案路径胜 | 双路径上限 | 答案减原 Top-1 每键分差 |
|---|---:|---:|---:|---:|
| 自然句完整码 | 4/64 | 1/60 | 5/64 | -1.587～0.042 |
| 自然句全简拼 | 0/64 | 0/64 | 0/64 | -5.895～-0.805 |
| 未收整词完整码 | 5/128 | 7/123 | 12/128 | -3.517～1.186 |
| 未收整词全简拼 | 0/128 | 0/128 | 0/128 | -9.623～-2.589 |

自然句完整码只有一个错误首选被词级 bigram 翻转，全简拼没有收益；
未收整词完整码也只有 7 个样本。因而当前不把这个模型接入
完整大词表搜索，也不重新校准产品拒识阈值。下一轮应先检验更密的字级
上下文、候选路径召回和词边界，再以同一 train/test 隔离标准比较。

### Train-only 字级上下文基线

同一批 2,339 个 train 序列拼接词界后含 74,381 个汉字实例、2,995 个
输出符号（含未知与句末）和 43,048 种、76,720 次含边界二元转移。只读
双文本诊断分别报告累加 log 概率、答案与原 Top-1 的字符长度关系，以及
每字符转移平均 log 概率。后者只用于剥离长度偏置，不是生产评分公式。

| 轨道 | 累加分双文本上限 | 答案更长/等长/更短 | 等长样本答案胜/负 | 平均分双文本上限 |
|---|---:|---:|---:|---:|
| 自然句完整码 | 46/64 | 0/35/25 | 18/17 | 32/64 |
| 自然句全简拼 | 0/64 | 64/0/0 | 无 | 47/64 |
| 未收整词完整码 | 77/128 | 0/93/30 | 42/51 | 52/128 |
| 未收整词全简拼 | 11/128 | 78/50/0 | 11/39 | 46/128 |

累加分在答案更短时得到系统性优势，在全简拼答案更长时又得到系统性
劣势；所以 46/64 与 77/128 不能当作真实提升。等长样本显示纯字级
bigram 的语义区分很弱，平均分则说明自然句全简拼仍有可研究信号。
下一步需要在不触碰 test 的 dev 数据上同时估计字符上下文与输出字数/
简拼先验，再决定是否值得进入可加和搜索；当前实现不改变任何候选。

需要额外说明：本节 test 结果已经用于选择后续研究方向，所以从这一
里程碑起它是固定的持续 benchmark，而不是仍可声称“完全未见”的最终
确认集。后续参数选择应在 train 的拟合/调参切分内完成，并把尚未用于
结果选择的官方 dev 或另一份独立公开语料留作确认。

## 连续组合短语评测

`cargo run --release -- public-compose-evaluate` 专门检验“不按词确认”的
短语输入。它扫描固定 UD test 中相邻的两个非标点 token，只保留合计
2～6 个纯汉字、两个整词都存在于固定 Rime 词典、尾部简写确实省键，
并且能在一个多音节词的首音节构造相邻颠倒的样本。每个词都采用同一
规则：首音节保留两键，后续音节只输入第一键，词间不插入空格。

筛选账目是 9,819 个双词窗口、8,891 个长度与字符合格、7,465 个整词
可覆盖、5,919 个可省键、5,796 个可构造颠倒，依源序固定取前 64 个
唯一短语。结果为：

| 轨道 | Top-1 | Top-3 | Top-5 | Top-10 |
|---|---:|---:|---:|---:|
| 完整码主榜 | 49/64 | 60/64 | 60/64 | 62/64 |
| 尾部简写主榜 | 21/64 | 32/64 | 43/64 | 45/64 |
| 主榜 Top-10 内同字数 | 22/64 | 33/64 | 44/64 | 45/64 |
| 颠倒输入主榜 | 0/64 | 0/64 | 0/64 | 0/64 |
| 锚定颠倒恢复栏 | 22/64 | 34/64 | 41/64 | 47/64 |

完整码共 430 键，尾部简写共 343 键，原始输入少 87 键（20.2%）。
尾部简写有 21 条直接首选、24 条位于第 2～10、19 条仍在 Top-10 外；
即使乐观地把每个首屏非首选只算一次选择，也不能把 87 个省键直接
宣称为 87 个净收益。同字数过滤只在已经返回的 Top-10 内重排，几乎
没有改善，说明眼前瓶颈主要是同长度短语竞争。

颠倒输入刻意不进入稳定主榜，避免纠错压过干净的零错误解释；恢复栏
单独保留“完整首音节 + 连续尾部简写”内部的一次相邻颠倒。它在 64 条
自然短语上达到 47/64 Top-10，证明这条规则具有超出“麻烦猫猫”单例的
可行性，但仍不是产品准确率：样本只有双词、读音来自 Rime、错误是
程序构造的，而且固定 test 已经用于方向判断。下一轮参数学习必须移到
train/dev 切分，test 只继续作持续 benchmark。

## 指标

对每个合成样例，来源词条在候选列表中的位置决定：

```text
Recall@1  来源词条是否排在第 1
Recall@5  来源词条是否出现在前 5
Recall@10 来源词条是否出现在前 10
```

此外，干净输入会检查第一候选的解释是否仍为 `Exact`。这可以发现新增
容错路径是否开始压过干净解释。

逐音节 trie、句子 lattice 与拒识影子另有多层非指标回归保护：

- 超过 1,000 个唯一输入同时与旧错误假设实现、逐词穷举实现逐候选比较；
  同一组用例也覆盖规范化状态 ID 和逐键转移复用。
- 结构测试检查 50 个词条只存 50 个终点，而不是 212 个展开拼写。
- 搜索统计测试检查联合遍历确实产生可审查的路径、对齐、终点拼写路径
  和展开/跳过词条计数，并锁定二者合计至少覆盖每条终点路径。
- 超过 150 个双词及错误变体在每个起点对照流式扫描与旧逐片段查询，
  并单测零错误边不会被更高分的纠错解释遮掉。
- 双词短句会枚举未缩减的完整 lattice 路径，再核对生产 unigram/bigram
  k-best 的候选、解释、分数和顺序；另有边界测试锁定 bigram 模式不会
  套用只对 unigram 成立的提前 lattice 缩减。
- 轻量 trie 终点会在多个输入、起点、错误层和 K 下直接对照完整对象
  缩减结果，并用绕过解析器的重复词条锁定结构身份语义。
- 同一矩阵会实际触发子树上界，再逐转移核对未剪枝结果；bigram 边界
  明确锁定零次精确预扫和零次子树剪枝，完整公开词典测试则锁定剪枝
  确实发生。
- 终点词条上界在同一未剪枝矩阵中实际跳过词条；独立等分测试锁定同一
  终点的确定性文本排序，跨路径重复身份继续对照完整物化结果，bigram
  模式锁定零次词条跳过。
- 人工小词典用例检查未知键原样保留、完整词典路径严格优先、未解析边
  不消耗纠错预算、空词典仍有候选，以及未知片段会重置 bigram 上下文。
- 5 条人工长句固定检查 unigram/bigram 的 Top-K 路径没有随长度退化。
- 拒识影子检查报告确定、门槛响应单调、空词典全部拒识，并逐项确认
  运行影子评测前后的真实解码候选完全不变。
- 独立标签 Top-K 召回单测锁定 Top-1 错误但 Top-5 可见的歧义，并确认
  诊断前后的真实候选完全不变。
- 固定 UD test 快照检查 14,510 行、500 句、12,010 个语法 token，
  并锁定 64/128 个校准探针及 64 个连续组合探针的全部筛选计数、
  省键数和源序确定性。
- 固定 UD train 快照检查 118,599 行、3,997 句、98,614 个语法 token，
  并锁定词级/字级训练映射、二元组计数和重复构建的确定性。
- 完整 Rime 快照测试锁定 65,125 个源行的导入、跳过、零权重转换、
  39,027 个非空终点节点和最大 312 个同码词条。

这些测试证明实现保持当前封闭词典行为，并消除了构建期拼写展开和生产
路径的错误假设枚举，但同样不能证明真实输入准确率。
`index-stats`、`search-stats` 和 `sentence-stats` 可分别输出索引结构、
单词搜索工作量，以及句子 lattice/k-best 工作量；`public-index-stats`
审查固定大词典的导入和结构。

`cargo run --release -- benchmark 3` 提供固定大词典、固定工作负载、
一次预热、重复采样和结果校验和，报告 min/median/mean/p95/max。一次
本机记录为单词 median 约 0.9 ms、短句约 8.5 ms、长句约 20.4 ms。
它比 CLI 单次计时可靠，但 CPU、编译器和机器仍会影响结果，
不能跨设备直接比较。哈希结构去重先把短句/长句中位数从约
`1.21 s / 2.56 s` 降到 `128.9 / 251.1 ms`，后续轻量终点、转移复用、
共享终点解释、子树上界和终点词频上界继续降低工作量。

当前含分型恢复前沿的确定性工作账为：短句/长句路径访问
10,760 / 11,622，其中精确预扫 536 / 594 条路径、核对
6,009 / 7,187 个词条，并剪掉 19,154 / 18,827 个子树；对齐为
`5,623 实查 + 859,991 复用` / `5,641 + 798,787`。终点拼写路径
7,555 / 8,538，正式展开 2,319 / 2,459 个词条，跳过
70,455 / 68,633 个词条。逻辑、物化、最终 lattice 边分别为
`2,198 → 575 → 564` / `2,378 → 604 → 594`，排名转移为
751 / 806，路径组合为 7,751 / 10,367。分型恢复有意保留了普通
Top-K 以外的锚定颠倒证据，因此这些计数高于只保留普通前沿的旧记录；
标准评测候选和结果校验仍不变。固定工作负载尚在当前性能预算内，后续
重点转向排序、真实选择成本与词外回退。

## 当前偏差

这套评测天然偏乐观：

- 主 Recall 的来源词一定存在于词典；
- 词外探针只有 12 个手工词，不代表真实词外分布；
- 独立公开校准经过纯汉字、长度和 Rime 可表达性筛选，不代表完整 UD
  分布；读音也来自 Rime 而非真实按键；
- 多词样例主要是双词全简拼，另有 5 条人工长句；
- 错误严格服从程序已经支持的类型；
- 合成相对权重是手填的；
- 小词典 demo bigram 的训练权重和句例都是人工构造的；公开 bigram
  虽来自独立 train split，仍非常稀疏且受 UD/Rime 分词映射影响；
- 多按目前只生成重复键，不覆盖任意误触；
- 没有真实手指时序、应用上下文或候选选择行为。

因此 100% Recall@10 只表示“来源词在封闭测试中没有从前十名丢失”，
不表示现实准确率达到 100%。

## 怎样逐步提高可信度

建议按以下顺序扩展：

1. 先按 `abbreviation-feasibility.md` 比较受限简写协议；不再把每音节
   自由一键/两键混合作为默认目标；
2. 选定歧义有界或由白名单硬限制的协议后，再将 train 固定切成拟合/
   调参部分；
3. 只在调参部分比较字符回退模型、输出字数先验和融合权重，并要求等长
   文本与受限简拼同时改善，而不是利用长度偏置；
4. 冻结选择后才在尚未用于架构决策的官方 dev 或另一公开 holdout
   确认；当前 test 继续作为历史 benchmark；
5. 若调参与新 holdout 都支持，再设计可加和、能进入完整搜索的状态与
   精确 Top-K 参照；不只重排前十名；
6. 扩大独立公开词典外来源，并区分“逐字正确恢复”和“错误完整覆盖”；
7. 用合成器保留一部分解码器尚未显式建模的错误；
8. 最后才在明确同意和严格本地隔离下进行公开文本的受控打字实验。

真实聊天和日常输入不属于这套公开评测的必需条件。
