# 词汇层与个人学习边界

## 范围

本文记录 2026-08-02 对公开输入法实现和公开词汇数据的复核，并把目前的
`conversation overlay` 放回一个可扩展的整体结构中。后续在 2026-08-04 落地了
只消费明确非首选的在线个人排序 V1，以及只连接两个已验证完整码单字选择的窄
个人短语层；它没有读取旧私人会话，没有生成离线词频或词对模型，也没有把第三方
词表复制进项目。

## 为什么不能把所有缺词都堆进一张会话 TSV

`ziranma-conversation-overlay-v1.tsv` 目前承担的是很窄的职责：为已经人工确认
的完整自然码补少量项目自有短语，并在公共快照产生自由简拼噪声前提供整词候选。
它适合修复“呜哇”“一大串”这一类明确缺口，但不适合作为无限增长的用户词典：

- 公开通用词、领域术语、显式手癖别名和自动学习证据有不同来源与许可证；
- 一次上屏不等于稳定偏好，提交后的编辑还可能撤销这次证据；
- 同一文字的规范码与个人别名不能混为一个频次；
- 运行时记忆需要遗忘和清空，发布词典则需要固定版本、摘要和回退。

因此“会话词层”应当是词汇分层中的一个项目自有静态包，而不是所有个性化功能的
总称。

## 公开实现给出的边界

### Rime

Rime 允许多个 translator 生成候选后再合并，并把固态词典与用户词典分开。
用户词典支持 `NewTransaction`、`CommitPendingTransaction` 和
`RevertRecentTransaction`；提交后的紧邻退格可以撤回尚未确认的学习事务。
这支持本项目继续使用“先 pending、遇明确边界再确认、重叠编辑可撤销”的语义。

- [Rime 方案与 translator](https://github.com/rime/home/wiki/RimeWithSchemata)
- [Rime 用户词典说明](https://github.com/rime/home/wiki/UserGuide)
- [Rime Memory 实现](https://github.com/rime/librime/blob/1d0df6e40cdcac17a986adc65e4668ae84ae0ada/src/rime/gear/memory.cc)
- [Rime UserDictionary 接口](https://github.com/rime/librime/blob/1d0df6e40cdcac17a986adc65e4668ae84ae0ada/src/rime/dict/user_dictionary.h)

### Mozc

Mozc 把显式 `UserDictionary` 与 `UserHistoryPredictor` 分开。历史预测器提供
`Finish`、`Revert`、按条清除和全部清除；排序信号包括新近度/LRU、文字长度与
bigram 连接，而低置信度候选可被标记为不得越过默认首选。

这说明显式加词、短期会话偏好和长期历史模型应是三个独立能力；它们可以在候选
合并处相遇，但不能共享一份无界频次。

- [Mozc UserHistoryPredictor](https://github.com/google/mozc/blob/3f235b4eb6fcff7d14ef5f0fb8ee56de7ee4c732/src/prediction/user_history_predictor.h)
- [Mozc UserDictionary](https://github.com/google/mozc/blob/3f235b4eb6fcff7d14ef5f0fb8ee56de7ee4c732/src/dictionary/user_dictionary.cc)

## 建议的词汇层

| 层 | 内容 | 生命周期 | 隐私与来源 | 候选作用 |
| --- | --- | --- | --- | --- |
| 公共核心层 | 固定拼音词典与基础频率 | 固定版本 | 第三方公开数据，锁定提交与摘要 | 通用召回与公共基线 |
| 公共语言层 | 更大词汇表、n-gram 或语言模型 | 独立可替换包 | 单独许可证与来源清单 | 公共排序和长句覆盖 |
| 项目领域层 | 会话、电子、课程等人工审阅包 | 随版本发布 | 项目原创、MPL-2.0 | 完整码精确补词 |
| 显式别名层 | `wua → 呜哇` 一类用户指定映射 | 用户主动增删 | 私人配置，不进入 Git | 精确码最高优先级召回 |
| 会话记忆层 | 当前宿主中数字选择或翻页确认的非首选，以及两个相邻完整码单字选择组成的短语 | 宿主内、有容量 | 只在内存，随时清空 | 固定候选之后的同码重排与池外短语试用；已验证完整整词可影响池内规范尾简 |
| 个人排序层 | 普通输入范围中待确认后成立的明确 `code + text` 选择；相邻单字短语一次存活即作为独立身份 | 紧邻退格可撤回；确认后进入跨宿主不可变小批次；同码排序支持四次封顶 | 当前用户 DPAPI；可看计数、可恢复清空 | 固定候选之后的抗偶然选择重排、受限补回、个人短语召回与池内尾简继承 |
| 私人确认层 | 从旧会话训练的 code-aware unigram/bigram | 尚未启用的加密版本槽 | DPAPI、显式训练/提升/回退 | 未来的有界重排与受限 OOV 覆盖 |
| 抑制层 | 候选窗 `Ctrl+Delete` 后数字选择，或管理工具显式忘记/恢复 | 当前用户 DPAPI 不可变动作；短暂 Backspace 可撤销 | 只记录精确身份，不推断错误原因 | 屏蔽指定实际码视图的个人证据或尾简继承且不改公共词典 |

“课程式”“主题式”不需要新造一种学习算法；它们更适合作为项目领域包的激活标签。
同一包可以有 `general`、`electronics`、`course:<id>` 等作用域，运行时只合并当前
明确启用的包。

## 召回与排序协议

1. 先按实际输入码查询显式别名和完整码项目包；
2. 查询不可变公共快照；
3. 只有达到确认门槛的私人 `code → text` 才能提供公共池外候选；
4. 按 `(文字, 实际码, 来源层)` 保留身份，显示前再按文字稳定去重；
5. 公共候选和已有个人证据使用有上限的概率混合，个人分数不能无界覆盖公共模型；
6. 完整无错、已解析与全局纠错预算等保守层级仍由解码器保证；
7. 调试报告可显示来源层，日常候选窗不显示研究标签。

这把“缺词召回”和“已有候选重排”分开，也避免用逐条加词掩盖自由简拼、词界或
语言模型本身的问题。

## 可评估的公开数据

现有固定 `rime-pinyin-simp` 快照继续作为公共核心层。可进一步评估
[rime/rime-essay](https://github.com/rime/rime-essay)：它是 Rime 默认词汇表与语言
模型，但采用 LGPL-3.0。若采用，应作为带原始许可证、固定提交、SHA-256 和独立
provenance 的数据包加载，不能把内容直接粘进项目的 MPL-2.0 overlay。

任何新公共数据先经过同一闸门：

- 明确许可证、来源 URL、固定提交和校验和；
- 用 `src/codec.rs` 生成自然码，不维护第二份手工双拼映射；
- 统计导入、去重、无效拼音、字符集和词长分布；
- 分开报告 OOV 召回、Top-K、公共候选位移、冷/热延迟与包体积；
- 数据包不自动获得高于项目显式别名或已审阅完整码词条的优先级。

`jieba` 与 `phrase-pinyin-data/pinyin.txt` 按词形精确相交得到 43,544
条；限定为全汉字且字数等于拼音音节数后数目不变，其中 33,508 个词形
不在当前 Rime 核心快照。这个数字只表示潜在召回，不表示 33,508 个都应
进入日用词典。比如 `jieba` 的高权重首先服务分词，直接按其数值排序会把
某些专名或语料偏置带进首选。

两套输入法词库的基础表更能说明分层必要性：雾凇 `base` 有 542,948
个数据行、约 16.6 MB；万象 `jichu` 有 1,422,012 行、约 45.0 MB，均
超过当前候选快照的 131,072 条上限，万象也超过 16 MB 载荷上限。万象
已经收录“什么、声母、韵母、独属于、尤其是、呜哇、省略号、一大串”，
但仍没有“直角矩形”和组合句“不是第一个”。后两类分别更适合项目领域层
和句子组合排序，不能把所有问题都归因于缺词。

下一轮优先做万象基础表的**独立裁剪实验**，不替换当前核心层：规范化
声调后仍交给 `src/codec.rs` 生成自然码；按明确的字符、词长、频率和包
上限规则生成不超过 120,000 条的候选包；保留 CC-BY-4.0、固定提交、
来源 URL、原文件 SHA-256 与逐项导入统计；最后同时比较新增召回、原有
候选位移、OOV 暴露、冷/热延迟和包体。MIT 交叉层作为较小的对照组，
不直接采用 `jieba` 数值排序。

### 万象 Top-100k 独立实验

固定提交 `fdda7afb218e9643f695ada5ec337ec03762751b` 的
`dicts/jichu.dict.yaml` 为 45,011,120 字节，SHA-256 是
`9d14c0c49588d63b16c554df4711bed5da822c63de9d50f4759c53542138ac00`。
源文件只保存在 Git 忽略的 `.local/public-audit/`；仓库不复制这份
CC-BY-4.0 数据。

专用裁剪器逐行规范化 Unicode 声调，随后仍调用中央自然码 codec；只接受
全汉字、字数等于音节数、正权重且不超过显式长度上限的词条。它用有界堆
按“权重降序、同权重源行优先”选取前沿，不在内存中物化 142 万个
`LexiconEntry`。本轮固定参数为 `max_entries=100000`、
`max_text_characters=8`：

- 源数据 1,422,012 行；字段异常 1 行、非正权重 1,001 行、文字范围
  26 行、拼音不支持 82 行；
- 1,420,902 行通过结构闸门，最终保留 100,000 条，无所选身份重复；
- 最低保留权重 963，候选载荷 2,588,167 字节；
- 独立包发布摘要
  `ae268a35f8e0125598a98205a3ce1c057f7567d08bec84e148804b70e7330eb7`；
- 显式 SHA-256 验证与 Windows TSF 合成预检均通过；未 stage、promote
  或安装。

与该轮尚未清理繁体单字残留的 65,116 条核心包做聚合对照：共同词形
32,976，仅核心 31,446，
仅万象切片 67,024；共同的文字/规范码身份 32,937。双方共同覆盖 28,447
个规范码，其中 25,757 个首选文字一致，2,690 个不同。一次进程加载检查
在本机上，现有包约 133～180 ms，万象切片约 242～261 ms；这只是同机
诊断，不是通用性能结论。

共同文字与拼音的 32,901 个权重比值也并非常数：万象/现核心的中位数为
8.25，四分位区间约为 5.20～12.80，5%～95% 区间约为 2.40～26.64。
因此不能把两个来源的原始权重直接放进同一个分数空间，也不应让万象包
直接替换核心包。

下一工程边界改为两个各自带 provenance 的运行时层：核心层保持现有
首选；补充层只用完整整词码提供召回，优先于自由简拼噪声，但不得无证据
越过已有核心完整码首选。这样既保留万象新增词汇，又无需伪造一个“联合
许可证”或假定两套权重同尺度。多源层合并先在纯函数和公开场景中证明
候选位移上限，再考虑接入 TSF。

冷启动实验曾增加一条不比较权重的窄校准：若补充层 Top-1 本身也被核心层
确认为同码完整词，就把这个双方共有候选移到首位。独立 UD test 随后发现它新增
51 个正确首选的同时丢失 57 个原本正确首选，并产生 27 个非目标首选变化，未过
零损失安全门。因此宿主已经恢复保守分层，补充层独有词和双方共有词都不能越过
核心首选；共识重排只保留为离线反事实审计，不随普通 TSF 换代启用。

Top-100k 只是第一轮资源预算，不是词语质量边界。截止线附近的只读审计
显示，权重 927～962 约有 9,288 行，其中包括可独立确认的双字、三字和
四字以上长尾词。裁剪器因此允许显式构造最高 Top-120k 的第二轮实验包；
120,000 仍低于快照的 131,072 条固定上限，且不会自动替换当前 Top-100k
包。运行时只允许其中一个补充层独有的多音节完整词参与组合；其余前后
片段必须由核心层完整码完全覆盖，补充单字、两个补充片段、简拼、纠错和
未解析边均不能进入这条路径。跨层不比较原始频率，每次最多提升一个这样
的组合；已有核心整词首选以及非字面回退的普通核心首选都保留在它前面。
若核心只能原样返回未解析的字母串，该字面回退不会阻挡结构完整的补充组合。

第二轮本地公开实验包保留 120,000 条，最低权重 891，候选载荷
3,132,236 字节，发布 SHA-256 为
`53152a594f3dc3f280d35c99a48cadb9ac21c9e94d98cacfb1f50fff67de8c39`。
显式哈希验证和 TSF 预检均通过；它只留在 Git 忽略的公开审计目录，没有
stage、promote 或安装。固定 28 组公开完整码及音节边界前缀的同机 release
热路径中，核心完整码首选变化仍为 0；这些耗时只用于发现本机回退，不作为
跨设备性能结论。

纯合并器和聚合审计现已接入 TSF 的显式补充层。合并器先固定核心完整码
Top-1，再接纳至多 N 个**不在核心完整词集合中**的补充完整词。实际补进新词
时只恢复核心其余完整词，不用普通候选中的自由简拼句子凑满；没有新词进入
时则原样保留核心普通候选。补充词典的自由简拼、纠错和句子路径不进入这条
通道。因此重复词不会借补充来源改变核心内部次序，补充候选也不能在尾部
绕过 N 的上限。

对上述两个本地公开包、候选前六做只读审计：

| 每码补词上限 | 进入前六的新文字/规范码 | 覆盖到的规范码 | 核心完整码首选变化 | 核心缺词码升为首选 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 / 67,063（0.00%） | 0 | 0 / 28,447 | 0 |
| 1 | 63,197 / 67,063（94.24%） | 63,197 | 0 / 28,447 | 58,476 |
| 2 | 66,403 / 67,063（99.02%） | 63,197 | 0 / 28,447 | 58,476 |

上限从 1 增至 2 只多放入 3,206 个同码次选，没有增加任何规范码覆盖；
因此若进入下一道 TSF 实验门，首个保守配置应为“前六、每码最多补 1 个”。
固定 24 条公开完整码/音节边界前缀、5 次重复的 release 热路径又得到 120 个
预热样本：本机核心/启用补充的 median 为 4.924/5.083 ms，p95 为
10.828/10.131 ms，median 增量约 0.159 ms；24 条中 7 条候选顺序发生变化，
核心完整码首选变化仍为 0。核心和补充索引首次构建约 174/352 ms，故同一宿主
进程缓存不可变候选蓝图，不在每个组合或每次类工厂创建时重建。绝对耗时不是
跨设备结论，用户选择成本仍需实际内测；当前包继续保持未安装。

运行时边界已经接入 TSF，但默认关闭。补充包使用跨 DLL 版本的独立公开槽根和
`supplemental.zcl`，不占用核心包的 candidate/previous。显式开启状态同时绑定
current 包和每码补词上限；缺失即关闭，状态损坏、包指针漂移或预检失败时只
回退核心。提升补充包不会自动获得启用权，需再次确认；关闭保留已验证包。

### 同码深层短词与双来源共识

全局 Top-N 还能漏掉另一类正常词：完整码已经有高频代表，但用户需要的词位于
同码第 2 名以后。固定公开来源中，`ubuu` 的公开整词依次至少包含 4 个不同词面，
`收束` 位于第 4；`ubxd` 下 `首项` 位于第 3。Top-120k 的最低权重约 891，而二者
分别只有 656 与 144，因此扩大 20k 条仍不能解决。这不是句子 beam 深度，也不是
个人记忆失效，而是构建时永久删除了同码身份。

这与成熟输入法的词典边界不同。固定 librime 源码的 `Dictionary::Lookup()` 通过
编译后的 table/prism 查询完整词条，随后才对等长码结果排序、过滤；`Poet` 在词图
上限制句子 beam。固定 libime 源码同样先从 `PinyinTrie` 枚举匹配词进入 lattice，
再由 `Decoder` 的 beam/n-best 控制路径数。两者都把“词典能否被查询”和“这一帧
展示多少候选”分开，而不是用一个全局词频截线同时决定二者。

裁剪器现提供默认关闭的 `--two-character-coverage-depth 1..8`。深度 1 完全保持旧
行为；更深时先保证每个双字完整码的第一个代表，剩余容量再让第 2～N 个身份按
同一来源内部权重竞争。它仍受 120,000 总上限约束，不会改动日用包。固定万象
全量源有 67,988 个双字码；每码最多 4 项共 136,586 个身份。一个只保留双字深度
的 120k 反事实包能显著增加公开 UD 双字覆盖，但会丢掉 Top-120k 的全部三、四字
覆盖；因此不能直接替换现有补充层。严格逐层装填能包含 `首项` 而漏掉 `收束`，
剩余项按权重装填又能包含 `收束` 而漏掉 `首项`，也证明单纯换一种 120k 排序仍在
移动同一个容量矛盾。

下一步用独立公开来源做二值确认，而不混合频率。jieba 固定提交
`67fa2e36e72f69d9134b8a1037b83fbb070b9775` 的 MIT `jieba/dict.txt`，文件
SHA-256 为
`7197c3211ddd98962b036cdf40324d1ea2bfaa12bd028e68faa70111a88e12a8`；它独立收录
`收束`、`首项` 与 `第一个`。`candidatectl short-consensus-audit` 只用 jieba 确认
词面存在，读音、自然码与层内次序仍只来自万象，再排除现有基础包：

```powershell
target\release\candidatectl.exe short-consensus-audit `
  --source .local\public-audit\wanxiang-fdda7afb\jichu.dict.yaml `
  --confirmation .local\research\upstreams\jieba\jieba\dict.txt `
  --base-payload .local\public-audit\wanxiang-fdda7afb\package-top120k-v1\lexicon.tsv `
  --per-code-depth 2 `
  --entry-limit 50000
```

确认表 349,046 行中有 114,134 个唯一双字词面；与万象相交得到 84,277 个唯一
文字/码身份。Top-120k 已有 28,327 个，仍有 55,950 个双来源确认的新增身份，
覆盖 34,894 个规范码；每码 1 项需要 34,894 条，每码 2 项需要 46,832 条。这个
规模已经超过基础包至快照上限之间的 11,072 条余量，所以正确工程边界不是再猜
一个截线，而是经过认证的独立短词精确层和按码惰性查询的紧凑索引。

该边界现已实现，但仍默认关闭。`build-short-consensus-layer` 对万象、jieba 与参与
去重的基础载荷分别验 SHA-256，再生成标准三文件候选包和 v2 provenance；专用
加载器验证清单、来源侧车、双汉字/双音节形状、完整码顺序、同码权重顺序、重复
身份和每码深度，只保存原始 TSV 与 34,894 个码范围。固定 depth-2 包的 46,832
条载荷约 0.90 MB，范围索引约 0.56 MB；本机 release 一次观测的首次认证建索引
约 36.846 ms，固定码热查询约 0.105 µs。数字只用于当前实现回归，不推广到其他设备。

候选合并目前只是纯预览。最初“保留 Top-1 后立即插入”的方案已被公开留出否决：
334 个匹配双字词面（421 次）中，补 1/2 项都会让 36 个目标名次后移、6 个跨页。
仅把插入点移到固定第一页之后仍有 3 个目标跨页，也不通过安全门。这些负结果保留
在 `exact-short-layer-audit` 中，不会被包装成成功。

进一步的分页保护预览固定完整第一页，并在插入前检查同码已有精确短词；会造成
任何既有精确身份跨页或掉出前 50 时，就缩减或跳过该码。固定留出上，每码补 1 项
让 59 个公开目标新进入前两页，补 2 项让 64 个进入；二者均保持第一页零变化、
目标零跨页且零掉出总范围。补 2 项比补 1 项多覆盖 5 个目标，代价是多挤出 22 个
第 50 名附近的旧尾项，没有增加目标跨页或掉出，故暂定为离线胜出配置。TSF 尚不读取该包，
所以当前候选位移仍为零；release 热路径与真实宿主首帧安全门通过前，不会自动安装
或启用。

### 公开组合路径审计

`candidatectl layer-composition-audit` 使用固定 UD Chinese GSDSimp 公共语料，
不读取私人会话。正样本只选相邻两词或三词，并要求恰好一个多字词仅在
Top-120k 补充层存在、其余词都由核心完整码覆盖；整句文字或整串码已经作为
完整词存在的样本会被排除。两词/三词以及补充词在前、中、后的五种结构按轮转
取样，选样过程不查看解码结果。

当前冻结口径使用日用 Rime 核心和万象 Top-120k 补充包；不要用两个万象切片
代替这两个不同职责的载荷。完整复现命令为：

```powershell
cargo run --release --bin candidatectl -- layer-composition-audit `
  --core-payload .local/candidate-rime-pinyin-simp-0c6861ef-v1/lexicon.tsv `
  --supplemental-payload .local/public-audit/wanxiang-fdda7afb/package-top120k-v1/lexicon.tsv `
  --corpus data/public/ud-chinese-gsdsimp/zh_gsdsimp-ud-test.conllu `
  --fit-corpus data/public/ud-chinese-gsdsimp/zh_gsdsimp-ud-train.conllu `
  --frontier-limit 7 `
  --sample-limit 128
```

报告会列出两个候选载荷及拟合/保留语料的内容 SHA-256；缺少这些指纹的历史
数字不能与新结果直接比较。

补充 120,000 条
`849aae039dfe503eb4dadfcb8529ddb74992a05b202e7cf6a69be932c73c8717`，

128 条正样本中，核心基线的目标 Top-7 为 29；窄组合路径提高到 83，新增可见
54 条且没有丢失原可见目标。旧的“组合直接抢首选”会发生 47 次非目标首选
变化；固定非字面回退的普通核心首选后，新增召回没有减少，首选变化降为 0。
仍未进入 Top-7 的 45 条中，补充词边深度造成 0 条、核心边深度造成 6 条，
其余 39 条都是已生成路径之间的竞争。扩大补充边前沿不是当前瓶颈；下一轮应
研究可泛化的词级边界或组合内部排序，而不是继续增加搜索宽度。

负对照从同一语料选择 128 条由两个核心完整词构成的自然短语，并排除整句文字
和整串码碰撞。保留首选、开放一个组合位时，没有原可见目标掉出 Top-7；19 条
目标降位，57 个核心候选被挤出。开放两个组合位虽让正样本再多 14 条进入
Top-7，却让一个负对照目标掉出 Top-7，并挤出 123 个核心候选。因此运行时只
开放一个组合位；第二个位置保持关闭，后续应先改善组合内部排序，而不是扩大
固定名额。上述数字是固定公开快照上的边界证据，不代表跨语料的质量结论。

审计器随后在同一个组合位中冻结比较三个不跨来源比较原始权重的顺序。把
“核心分段更少”移到“补充跨度更长”之前，正样本和负对照的结果完全不变；把
补充层与核心层各自的局部名次移到结构之前，正样本 Top-7 从 83 降到 82，新增
可见从 54 降到 53，负对照挤出的核心候选从 57 增至 58。两种简单字段换序均
没有通过改动运行时的证据门槛，现行结构 V1 保持不变。竞争组合若要继续改善，
需要在隔离的公开拟合/评测切分上研究更有信息量的边界或上下文信号，而不是继续
排列同一组启发式字段。

下一轮把 UD train 的 3,997 句与 UD test 的 500 句固定为拟合和保留评测，工具会
拒绝两边内容相同。字符模型只使用 train 中 2,346 条全汉字、去标点句子；九个
门槛在读取 test 结果前已经固定。它只允许结构候选前八中的一个挑战者在公开字符
转移覆盖和平均对数概率增益同时过门时换到组合首位，不创建新路径，也不改变普通
核心首选。

拟合组上，预先声明的 `d8-g0.25-r0.50` 从结构基线的 Top-7 75/128 提高到
90/128，新增可见从 49 提高到 64，负对照没有目标丢失；但自动选定该档后，保留
评测从基线 83/128 降到 75/128，新增可见从 54 降到 46。这个反向结果否决了把
当前字级模型接入运行时，也说明同一来源内漂亮的拟合提升不足以证明泛化。工具
保留这套固定切分和聚合报告作为后续模型的防过拟合门，生产仍使用结构 V1。

词界对照保留同一批组合路径，但进一步携带每段文字、核心/补充来源、音节数和
层内名次；公开文本报告仍只输出聚合数字。模型从 train 中 2,339 条可映射序列
累计 51,061 个词次，其中 43,306 次使用源词、7,755 次逐字回退；候选按每音节
平均词概率比较，九个搜索深度、增益和覆盖门槛同样在读取 test 前固定。

拟合选择 `词界-d8-g0.10-r0.75` 把 Top-3/Top-5/Top-7 从 74/74/75 提高到
90/90/90，并在 128 条正样本中更换 30 次组合首位；保留评测却仍为
77/82/83，只更换 1 次组合首位且没有改变目标名次。负对照在拟合与保留中分别
更换 3 次和 1 次组合首位，也没有改善目标指标。这不是退化，但没有提供可泛化
收益，因而不接入运行时，也不根据 test 回调本轮门槛。可解释词段证据和固定
评测闸门继续保留，供不同来源或真正有新信息量的词级信号复用。

## 最近的工程顺序

1. 保持现有两个项目 overlay 的窄职责，并为后续领域包设计来源清单；
2. 以默认关闭的独立公开补充根承载“前六、每码最多补 1 个”，先由新宿主做
   小范围实际输入与许愿反馈；不替换核心包；
3. 已实现本地、可列出、可删除、可回退的 DPAPI 显式别名三槽，并移除 TSF
   源码中的个人别名数组；支持该版本的宿主在新组合边界安全热刷新。日常
   `aliaspad` 面板一次固定、移除或撤销，私密正文经标准输入进入独立管理器，
   不出现在子进程命令行；CLI 继续保留先暂存、后提升的审查路径；
4. 独立评估 `rime-essay` 等公共语言包的许可证、体积、召回和延迟；
5. 最后才把评测通过的私人确认层做成 DPAPI `candidate/current/previous` 槽位。

这些步骤延续现有隐私和换代边界，不要求在 TSF 宿主里实时写数据库。
